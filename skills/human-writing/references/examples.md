# 真实改稿对照：从 AI 油腻草稿到质朴人话

这篇文件收集了本站在实际写作与改稿中，经历过的三次最典型的人类退稿与重构实录。

动手写文章或改稿时，随时对照这三组范例，体会真实人话与机器油腻感的区别。

---

## 范例一：告别“大字报加粗金句”，还原为“过程说明与操作代价”

- **出处**：博文《用代码做视频：Remotion 与 Opus 5.5 的体验》结尾总结

### ❌ 典型 AI 草稿（假大空标语连发，像机场成功学）
> 总结这次探索，我有以下四点深刻体会：
> - **静帧便宜，渲染贵。** 在静态图片阶段打磨好，永远比盲目生成整段视频高效。
> - **给它规矩，比给它灵感更管用。** 约束越具体，模型的表现就越惊艳。
> - **改法要换思路，不要只调参数。** 遇到视觉缺陷，重构往往优于微调。
> - **真素材省掉的是编造。** 真实数据是最高级的设计语言。

### ✅ 阮一峰人话改版（交代真实物理耗时与操作代价，平静质朴）
> 做完这四个案例，我有几个比较深的心得。
>
> 第一，做视频的时候我发现，在静态图片阶段修改最划算。因为生成一张静态图只要几秒钟，如果直接渲染整段视频，电脑要跑好几分钟。频繁重新渲染太浪费时间，把画面排版在图片阶段定好，渲染基本就能一次过。
>
> 第二，给模型的约束越具体，生成的画面风格就越协调。比如提前把调色板固定成米白底板配深灰字，把字体限定在黑体。模型有了明确的边界，就不会天马行空地乱配颜色。
>
> 第三，遇到画面不好看，往往不是参数问题，而是排版策略的问题。比如文字被深色背景吞掉，去调亮文字颜色通常不管用，先横向擦出一块浅色底板把背景垫开，字迹立刻就清晰了。

## 范例二：告别“假接地气（堆短视频网梗）”，还原为“客观物理事实”

- **出处**：博文《用 ASD-STE100 规范约束 AI 输出的测试》图示评审段落

### ❌ 典型 AI 草稿（穿西装硬学主播说网梗，尴尬做作）
> D 版画的流程图虽然很全，但有两个致命槽点。第二点尤其实在是太搞笑了：图片拉出来整整有 10060 像素高！滚轮滑冒烟了都滑不完，简直蠢得要命，谁看谁眼瞎。阅卷老师的评价也很扎心：“懂程序的人有用，新人根本看不懂。”

### ✅ 阮一峰人话改版（客观记录尺寸、操作体验与真实评价）
> D 版流程图画得很工整，“先做什么、出错了往哪走”都没错。
>
> 但它有两个致命硬伤。一是程序里有不少“业务规矩”（比如能归进已有手册就别新开一篇），规矩不是流程步骤，图里根本没地方塞，全漏了。
>
> 二是流程图拉出来整整有一万像素高。在屏幕上要滑动很久鼠标，而且每个框里塞满了代码，阅读体验并不好。
>
> 阅卷老师的评价很直接：“懂程序的人对着看有用，新人根本看不懂。”

## 范例三：告别“编造轻浮流水账”，还原为“硬核工程架构机制对比”

- **出处**：博文《从开发者到管理者：Agent 的能力边界与工具供给》核心案例

### ❌ 典型 AI 草稿（为了显得接地气，编造轻飘飘的日记流水账）
> 为什么我们要给 Agent 准备好工具呢？我昨天就遇到了一个很典型的例子。我让 Agent 去帮我克隆一个 GitHub 仓库，结果它第一次超时了，第二次又报错连不上，折腾了我半天。后来我发现原来是本地代理没配好，配好了之后立马就跑通了，真的太神奇了。

### ✅ 阮一峰人话改版（硬核机制演进，交代真实操作困境与人机差异）
> 以前在服务器上做运维，经历了三个极其折腾的阶段。
>
> 最开始是当人肉中继。因为不熟悉复杂的 Linux 命令，我在本地开着模型聊天。模型在窗口里给出一行命令，我手动复制，切到终端粘贴到远程服务器执行。执行报错了，我再截图或者把错误信息复制回本地问模型。来回倒腾几次，大半天全浪费在复制粘贴上了。
>
> 后来为了不当传话筒，我在服务器上也装了一套 Open Code 和模型凭据。这样虽然不用来回复制，但新的麻烦又来了：服务器和本地环境完全割裂，服务器上的 Agent 根本看不到我本地的代码仓库，两边同步起来非常痛苦。
>
> 直到最近我才想通：既然本地 Agent 已经能运行终端命令，为什么不直接给它一把 SSH 密钥，让它从本地直接连上服务器？给它加上一条“高危操作必须向我确认”的提示词之后，它就可以自己在终端里查日志、看服务状态。
>
> 其实早几个月前，模型的推理能力和系统的 SSH 工具就完全成熟了。模型早就做得到，纯粹是因为我这个管理者没有意识到该给它配这条管道。
