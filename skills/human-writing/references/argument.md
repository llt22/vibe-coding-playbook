# 论证与段落连贯：先让文章站得住，再谈文风

清楚的句子救不了空洞的论证。长文动笔前，先确认主张、证据和推理能够连起来。

## 一、主张必须能被反驳

真正的主张会排除其他可能，读者可以同意，也可以不同意。

- 空话：`Agent 正在改变软件开发。`
- 可讨论的主张：`编码 Agent 普及后，开发者最稀缺的能力会从手写代码转向识别模型边界和配置工具环境。`

如果一句话放进任何行业文章都成立，它通常不是本文主张。

## 二、每个核心主张都要完成五步

1. **主张**：明确说你判断什么。
2. **证据**：给出事实、数据、代码、日志、原话或可靠来源。
3. **推理**：解释这份证据为什么支持主张。不要让读者替你补中间一步。
4. **边界**：说明结论在哪些条件下成立，哪些情况没有覆盖。
5. **回应**：若存在明显反例或替代解释，正面处理，不装作不存在。

### 常见断裂

- 有观点，没有证据。
- 有案例，却没有解释案例为何能代表更大的现象。
- 有相关性，直接写成因果关系。
- 用一个人的经历证明行业趋势。
- 把厂商宣传、README 声明或模型自评当成独立证据。
- 只挑支持结论的材料，不交代失败案例和限制。

## 三、证据按强弱排序

同一主张优先使用更靠前的证据。

1. 可复现的实测、代码、日志与原始数据。
2. 官方文档、论文、标准和产品行为。
3. 多个相互独立的真实案例。
4. 有明确上下文的当事人原话。
5. 单次个人体验。
6. 类比、感觉和预测。

弱证据可以帮助解释，不能单独承担强结论。

## 四、事实、判断和预测分开写

- **事实**：来源能核对，或实验能复现。
- **判断**：作者根据事实得出的解释。
- **预测**：尚未发生，必须写明条件和不确定性。

不要把“我认为”“很可能”删掉后，就把判断伪装成事实。也不要每句都加“可能”，把明确结论写得没有立场。

## 五、段落只承担一个推进动作

一个段落通常完成下面一种工作：

- 提出主张。
- 展示证据。
- 解释机制。
- 处理反例。
- 收窄边界。
- 转入下一层问题。

段落开头要让读者知道这一段接着什么。Williams 的实用原则是从旧信息走向新信息：句首先接住上一段已经出现的人、事或概念，句尾再放本句真正的新内容。

### 不连贯

> Agent 需要工具权限。模型上下文窗口有限。我们最近换了一个浏览器。

三句都可能正确，但没有推进关系。

### 连贯

> Agent 拿到工具权限以后，才能直接完成网页任务。但浏览器返回的 DOM 很长，会迅速占满上下文。因此我们换成了只输出语义快照的浏览器。

每句话都接住上一句的结果，再带出下一步。

## 六、删除没有承担功能的段落

删掉一个段落以后，如果主张、证据、推理和阅读路径都没有损失，这个段落就不该存在。

尤其警惕：

- 只负责营造气氛的宏大开场。
- 重复上一节结论的“总结一下”。
- 为了显得全面而加入的常识段落。
- 与全文主张无关的有趣资料。
- 只换同义词复述标题的结尾。

## 七、交稿前的论证检查

逐条回答：

1. 全文最重要的判断能否用一句话说清？
2. 这句话有什么可核对的证据？
3. 文中是否解释了证据与判断之间的关系？
4. 最强反例或替代解释是什么？
5. 哪些内容是事实，哪些是判断，哪些是预测？
6. 每个段落是否都推动了主张？
7. 文章删掉三分之一后，是否反而更清楚？
