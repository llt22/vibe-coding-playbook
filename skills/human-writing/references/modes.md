# 文体模式：共同底线，不同写法

本站的共同底线是清楚、具体、克制、有证据。不同文章不必使用同一种声音。

动笔前先选一个主模式。可以混合，但只能有一个主模式。

## 1. 教程 / 操作说明

目标是让读者照着做成功。

- 先写前置条件、输入和完成标准。
- 步骤使用 STE 规则：编号、祈使句、一个步骤一个主要动作。
- 每个关键步骤写预期输出和失败处理。
- 不加入与操作无关的个人感想。
- 结尾写适用范围、未覆盖情况和回退办法。

核心问题：读者能不能不问作者就做完？

## 2. 实测 / 工具体验

目标是让读者知道工具在什么条件下好用，什么条件下不好用。

- 先交代环境、版本、任务和评价标准。
- 记录成功和失败，不只展示最好的一次。
- 把事实、判断、预测分开。
- 给出成本、耗时、限制和适用边界。
- 结论可以明确，但不要替读者制造兴奋。

核心问题：别人能不能判断这个结果是否适用于自己？

## 3. 观点 / 评论

目标是提出一个能被讨论的判断。

- 开头尽快交代主张，不用宏大背景铺垫。
- 只保留能支撑主张的案例和资料。
- 处理最强反例，不把个人体验冒充行业统计。
- 允许保留作者的立场、犹豫和判断，不要把文章改成中性公文。
- 结尾停在最后一个有证据的判断，不强行升华。

核心问题：读者是否清楚你在判断什么，以及凭什么这样判断？

## 4. 调研 / 资料整理

目标是把分散来源整理成可核对的事实。

- 每个关键结论紧跟来源，不把多条来源混成一句。
- 区分原文说法、你的归纳和未经验证的推测。
- 记录来源日期、版本和访问条件。
- 来源冲突时并列呈现，解释采用哪一条以及原因。
- 不用资料数量制造可信度。五条重复的转载只算一条证据。

核心问题：读者能不能沿着来源复核你的结论？

## 5. 随笔 / 个人记录

目标是保存一次具体经验和作者自己的声音。

- 只写真实发生过的事，不编造“像真人”的小故事。
- 允许长短句、口语和情绪，只要它们属于作者本人。
- 具体写当时看见什么、做了什么、哪里改变了判断。
- 不要强行把个人经历提炼成普遍规律。
- 不要为了符合技术文章结构，删掉真实的犹豫和失败。

核心问题：如果删掉作者本人，这篇文章还剩下什么？

## 不要混用的规则

- 教程需要完整步骤，观点文章不必把每个观点排成编号列表。
- 实测需要环境和限制，随笔不必伪造实验表格。
- 调研需要来源密度，个人记录不必把每句话都包装成结论。
- STE 只约束说明性内容，不约束正常叙事。
- 阮一峰的短句和留白是技术解释的范例，不是所有文体的唯一声音。
