## 核心写作原则

### 1. 真实材料先行（不空写长文）
- **长文必须有硬事实支撑**：具体的终端输出、代码改动、实测数据、报错日志或机制对比。
- **缺乏材料强制写短**：缺乏硬核细节时，绝不空想扩写，强制收敛为 150–500 字的短篇速记，讲清一个事实即收工。

### 2. 阮一峰式的语言习惯
- **短句子**：每句尽量在 15–25 字之间，超过 30 字必须拆开，多用句号。
- **自然留白**：一段通常只有两三句话，留出充足的呼吸感，绝不堆大块文字。
- **平民视角大白话**：用日常事物类比技术，不用术语解释术语，多用口语小词（好用、省事、干净、搞定）。
- **坚决意译**：不要硬套英文句式（如不写“可读性高”，写“读着省力”；不写“对代码进行了重构”，写“重构了代码”）。

### 3. 彻底斩断 AI 套路
- **标题降维**：采用【对象 + 客观事实/动作】的极简结构，不替读者写读后感（禁“好懂多了”），不对仗写八股，不搞戏剧化假嗨。
- **干掉报幕式冒号**：中文冒号**只用于引出人类原话**。凡是用来报幕（如“道理很简单：”“一句话：”）的一律删除，直接讲主体。
- **禁加粗对仗金句**：绝不发射公众号式、机场成功学式的加粗口号（如 `**静帧便宜，渲染贵。**`），还原为质朴的过程说明与操作代价。
- **禁翻案腔**：不写“不是 A 而是 B”、“看似 A 实则 B”，直接陈述 B。
- **禁自嗨情绪预告**：读者笑之前不自称“这很好笑”，读者领会前不预设“这很有启发”，把感受权还给读者。
- **自然收尾，绝不假升华**：事情讲完就停，不总结中心思想，不展望行业未来（禁“未来已来”“无限可能”）。

### 4. 步骤说明遵循 STE 规范
- 解释操作步骤时，一律用**祈使句 + 编号列表**，每行一个动作。
- 前后名词叫法统一，指代明确，绝不中途换同义词显摆词汇量。

## 校验与自动化检查

在产出成稿或改稿后，使用配套的纯 Python 静态检查脚本进行规则自检：

```bash
# 1. 综合检查（同时检查翻译腔与文风硬伤）
python3 ~/skills/human-writing/scripts/check.py <文章路径或草稿路径>

# 2. 单项检查
python3 ~/skills/human-writing/scripts/check_prose.py <文件路径>
python3 ~/skills/human-writing/scripts/check_translationese.py <文件路径>

# 3. 运行评测套件（验证检查器拦截与放行是否正常）
python3 ~/skills/human-writing/scripts/test_skill.py
```

- 故意举的反例（如列毛病的对照表）可用 `{/* check:off */}` 和 `{/* check:on */}` 包裹，检查器会自动跳过。
- 引号里的词按“提及”处理，不计入违规。
