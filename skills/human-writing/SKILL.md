# 中文说人话写作规范 (Human Writing)

核心目标：**说人话、讲真事、通俗易懂、不端架子、杜绝套路**。

## 核心写作流程

### 1. 先选文体，再准备材料
- 先从 `references/modes.md` 选择主模式。不要把教程、观点和随笔强行写成同一种文章。
- 写观点、调研和长文时，先读 `references/argument.md`，把主张、证据、推理和反例列清楚。
- 按 `references/brief-template.md` 填写文体、读者、主张、证据、限制和来源。没有这些字段就不写长文。

### 2. 先写内容，再写句子
- 开头尽快交代读者要知道什么、相信什么或完成什么。
- 一段只承担一个推进动作。下一段接住上一段的信息，再引入新信息。
- 事实、判断和预测分开写。不要用单个案例证明过大的结论。
- 只有说明步骤使用 STE。正常叙事保留长短句和作者自己的节奏。

### 3. 分阶段修订
- 按 `references/revision.md` 的顺序修订：任务与读者 → 事实与来源 → 论证与结构 → 段落推进 → 句子与用词 → 删减与声音 → 标题与结尾。
- 不要一上来只改标点和同义词。结构没有站住时，句子越顺越容易掩盖问题。

### 4. 真实材料先行（不空写长文）
- **长文必须有硬事实支撑**：具体的终端输出、代码改动、实测数据、报错日志、可靠来源或可核对的生活细节。
- **缺乏材料强制写短**：缺乏硬核细节时，绝不空想扩写，讲清一个事实即收工。

### 5. 共同语言底线
- **清楚优先**：短句、自然留白和大白话是默认值，不是所有文体的固定句法。观点和随笔可以保留必要的长句、节奏和个人词汇。
- **具体优先**：重要角色尽量做主语，真正的动作尽量用动词。少写“进行了优化”，多写“重构了代码”。
- **意译优先**：不要硬套英文句式。读者不懂的术语先解释，解释后统一叫法。

### 6. 斩断 AI 套路
- **标题降维**：采用【对象 + 客观事实/动作】的极简结构，不替读者写读后感，不对仗写八股，不搞戏剧化假嗨。
- **干掉报幕式冒号**：凡是用来报幕的冒号一律删除，直接讲主体。
- **禁加粗对仗金句**：还原为质朴的过程说明与操作代价。
- **禁翻案腔**：少写“不是 A 而是 B”“看似 A 实则 B”，直接陈述真正的判断。
- **禁自嗨情绪预告**：不替读者宣布“好笑”“震撼”“有启发”。
- **自然收尾**：事情讲完就停，不重抄全文，不突然展望时代。

### 7. 步骤说明遵循 STE 规范
- 解释操作步骤时，使用祈使句和编号列表，每行一个主要动作。
- 前后名词叫法统一，指代明确。
- 用 `check_ste.py` 检查步骤长度、动作数量、被动句和含糊指代。普通叙事不套这层检查。

## 校验与自动化检查

写长文前先检查写作简报，成稿后再运行正文检查：

```bash
# 1. 长文动笔前检查写作简报
python3 ~/skills/human-writing/scripts/check_brief.py /tmp/article-brief.yaml

# 2. 成稿综合检查，包含翻译腔、文风与 STE 步骤
python3 ~/skills/human-writing/scripts/check.py <文章路径或草稿路径>

# 3. 单项检查
python3 ~/skills/human-writing/scripts/check_prose.py <文件路径>
python3 ~/skills/human-writing/scripts/check_translationese.py <文件路径>
python3 ~/skills/human-writing/scripts/check_ste.py <文件路径>

# 4. 运行回归评测
python3 ~/skills/human-writing/scripts/test_skill.py
```

- 故意举的反例（如列毛病的对照表）可用 `{/* check:off */}` 和 `{/* check:on */}` 包裹，检查器会自动跳过。
- 引号里的词按“提及”处理，不计入违规。
