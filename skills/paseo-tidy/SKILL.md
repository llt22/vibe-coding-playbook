# 整理 Paseo 工作区会话

## 流程

1. **出摘要**：在工作区目录运行

   ```bash
   python3 ~/skills/paseo-tidy/scripts/digest.py [cwd] [--all]
   ```

   未归档的会话会列出标题、状态、最后活动时间、接续关系（`接续自`、`parent-agent-id`、`worker`）、头尾几条用户消息和最后一条 AI 回复；已归档的只列一行，加 `--all` 才看内容。`←本会话` 标的是自己，每个会话会标出所在工作区。

2. **逐个判断**去留、标题、是否要合并（规则见下）。摘要看不出来时，再读原始记录：Claude 会话是 `~/.claude/projects/*/<sessionId>.jsonl`，codex/omp 会话用 `paseo logs <id>`。

3. **执行**：改名、归档、合并直接做，事后汇报。它们都能撤回，不用先问。

   ```bash
   paseo agent update <id> --name "具体事项" -q
   paseo archive <id> -q
   paseo send <id> "<要交接的内容>"      # 合并时用，只发给 idle 的会话
   ```

4. **汇报**：先说结论（剩几个、归档几个），再按主线列出留下的会话，然后逐个写归档理由，最后列出可以硬删的会话，等用户确认。

## 判断规则

**归档**
- 一次性任务已完成：Advisor/验收、一问一答、排查出结论的问题。
- 同一件事已由更新的会话接手。接续关系看摘要里的 `接续自` 和标签；Advisor 的 `worker` 被归档后，它也一起归档。
- 和本工作区无关、已经有结论的会话，比如个人杂事、别的项目。

**保留**
- `running` 的会话，只改名，不归档。
- 每条主线里最新、还在推进的会话。
- 总入口类会话，比如交接、看板。
- 在等外部回复的事项，比如等对方修网络、等客户给材料。
- 本会话。

**合并**：两个会话同时在改同一份产出（同一个文档、同一个工作流）时，留下长期负责那份产出的一方。把另一方改了什么、为什么改，用 `paseo send` 交给它，并提醒它改之前先读最新版，然后归档另一方。不要把两边的上下文硬拼成一个会话。

**标题**
- 只写具体事项，一眼能看出在做什么，尽量控制在 30 字以内。
- 会话已经按主线分到各工作区时，标题**不带**【主线】前缀，主线由工作区名体现，带前缀反而看不清。只有几条主线还混在同一个工作区里时，才用 `【主线】具体事项` 区分；拆分到工作区后把前缀去掉。
- 主线名（工作区名或前缀）沿用已有叫法。用户改过的叫法（比如「合同防篡改对比」）以后照用。
- 用户原话、链接、"hi"这类标题一律改掉。和项目无关的会话放进杂务类工作区。
- 已经合并或结束的会话，可以在标题末尾注明，比如「（已并入文档会话）」「（已结束）」，再归档。

## 按工作区分组

同一个项目目录下可以建多个 local 工作区，层级是 项目 → 工作区 → 会话。一个工作区里的会话太多、几条主线混在一起时，按主线拆成多个工作区。

```bash
# 建工作区：--path 必须写绝对路径，写 . 会被解析成 /
paseo workspace create --isolation local --path <项目绝对路径> --project <prj_id> --title "<主线>" --json
paseo workspace rename <wks_id> "<名称>"
# 移动会话（同一项目目录内）
~/skills/paseo-tidy/scripts/move.sh <会话id> <wks_id>
```

- `prj_id` 用 `paseo project ls` 查，现有工作区用 `paseo workspace ls --json` 查。
- `move.sh` 先归档会话，再带上目标 `workspaceId` 重新导入。daemon 会原地恢复同一条记录，所以会话 ID、标题和历史都不变。脚本跑完会核对结果，不对就报错。CLI 自带的 `paseo import` 没开放 `--workspace` 参数，所以脚本直接调用 Paseo 内置的客户端。
- `running` 的会话不能移，归档会打断它。脚本会拒绝，等它停下再移。本会话也一样，留在原处。
- 已归档的会话不用移，移动会把它恢复出来。
- 只有一两个会话的主线也可以单独建一个工作区，后面会话还会增加。交接、杂务这类留在原工作区，并把原工作区改成能看懂的名字。
- 移错了再 `move.sh` 移回去就行。`paseo workspace archive` 会连同里面的会话一起归档，只用来清理空的或测试用的工作区。

## 硬删

`paseo delete <id>` 不能恢复，必须等用户明确说"删"才执行，每次整理都重新确认，不会因为上次同意过就自动删。汇报时列出可以硬删的已归档会话。

## 坑

- `paseo inspect --json` 返回的字段名是大写开头的（`Name`、`Archived`），用小写取不到值。要批量取数据就直接读 `~/.paseo/agents/<目录>/*.json`，digest.py 就是这么做的。
- `paseo ls -a` 不按工作区过滤，会把别的目录的会话也列出来。要看本工作区就过滤 cwd，或者直接用 digest.py。
- codex 会话的 `paseo logs` 里，AI 回复不带 `[Assistant]` 前缀，脚本已经处理。
- 会话文件可能有几十 MB，只能逐行读，不能一次载入。
- 会话开头的 `<chat-history-summary>` 是分叉或续接时带过来的旧上下文，不算这个会话自己的工作。
