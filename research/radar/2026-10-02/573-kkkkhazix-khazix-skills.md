## 是什么

kkhazix-skills 是作者（数字生命卡兹克 / @KKKKhazix）把自己日常在用的 6 个 AI Skill 开源出来的合集，遵循 [Agent Skills](https://agentskills.io) 开放标准，号称可安装到 Claude Code、Codex、Qoder、Kimi Code、iFlow、CodeBuddy、Cursor 等 40+ 支持该标准的 Agent。六个技能分别是：

| 技能 | 一句话作用 |
|---|---|
| leader（领导） | 把一句模糊想法定义成清晰「目标」，产出可让 AI 独立跑数小时到完成的目标任务书 |
| storage-analyzer（清理垃圾） | 一句话扫描整机磁盘，出交互式 HTML 报告，三色分级给清理决策 |
| aihot（AI HOT 资讯查询） | 让 Agent 一句话拿到 aihot.news 的 AI 日报与动态，无需 API Key / MCP |
| neat-freak（洁癖） | 干完活跑 `/neat`，对齐项目文档、CLAUDE.md/AGENTS.md、Agent 记忆并审计规则执行 |
| hv-analysis（横纵分析法） | 对产品/公司/概念做纵向+横向分析，产出 1–3 万字 PDF 研究报告 |
| khazix-writer（卡兹克写作） | 按作者口吻与禁忌词写公众号长文 |

作者自述这些 skill「都是在自己项目里跑通了一段时间，确实省事，才搬出来开源的」。

## 具体做法

**第 1 步：确认前提。** 你的 Agent 需支持 Agent Skills 标准（README 点名 Claude Code、Codex、Qoder、Kimi Code、iFlow、CodeBuddy、Cursor 等 40+）。

**第 2 步：安装。** 在 Agent 里直接说（把 `<skill-name>` 换成 `neat-freak`、`hv-analysis`、`khazix-writer` 等）：

```
帮我安装这个 skill：https://github.com/KKKKhazix/khazix-skills/tree/main/<skill-name>
```

README 说明 Agent 会自己 clone 到对应目录，无需手动管路径。

**第 3 步（降级方案）：Agent 不支持 Skill 时。** 把对应目录的 `SKILL.md` 全文下载下来，当成项目规则文件，或直接贴进对话让 Agent 照着执行——README 称「效果一致」。

**第 4 步：用 leader 写目标。** 触发词（任一句）：

```
帮我给 agent 写个目标
帮我详细拆一下这个目标
写个 goal 提示词
让 agent 自己跑这个项目
```

流程：先说一句想法 → 它先实测调研（README 强调「动笔前一定先钻进代码库亲手跑一遍——文档里写的命令，实际可能根本不存在」）→ 问你最多 5 个必须你拍板的问题 → 写出纯 Markdown 任务书，全程约 12 分钟（作者说法）。拿到后粘进目标模式（Claude Code 的 `/goal`、Codex 的目标模式），没有目标模式的 Agent 直接粘贴发送也一样用。

**第 5 步：按「目标七问」检查任务书。** README 给了可直接照用的检查表：

| # | 问题 | 落到任务书 |
|---|---|---|
| 1 | 目的 | 遇到没写到的岔路口，它靠这句自己判断 |
| 2 | 完成态 | 具体到靠岸那一刻机器就能判 |
| 3 | 证据 | 每条验收都要贴出实际命令输出 |
| 4 | 反作弊 | 把偷懒路径一条条点名禁止 |
| 5 | 地界 | 白名单 + 跑满 N 轮即停 |
| 6 | 取舍 | 「算得对 > 做得全 > 做得快」 |
| 7 | 未知 | 拿不准的写进待裁决清单，跳过做别的 |

外加第零问：海图是自己实测的还是听来的。

**第 6 步：用 storage-analyzer 清磁盘。** 触发词：

```
帮我看看存储
C 盘满了
清理一下磁盘
看下电脑空间
storage analysis
```

它扫完整机后在浏览器打开交互式 HTML 报告（磁盘总览、占用 Top 5、清理优先级、三色分级清单）。照抄它的安全规则：
- 🟢 绿灯：纯缓存/临时文件，可让 Agent 一键清；
- 🟡 黄灯：含用户数据（离线视频、下载、项目代码），只给「在访达打开」和「移废纸篓」，不直接删；
- 🔴 红灯：运行中应用核心数据、系统文件，只解释，最多「打开文件夹」，永不给删除按钮；
- 铁律：全程只读扫描，删除必须浏览器点按钮 + 弹框二次确认；本地服务跑 127.0.0.1 + 随机端口 + token，白名单分级。

**第 7 步：用 neat-freak 收尾。** 每次在 Agent 里干完一件事后跑：

```
/neat                          # 直接命令
跑一下洁癖                      # 点名
把文档和记忆整理一下             # 收尾意图
新人接手，帮我做个 clean handoff  # 交接意图
```

它对齐三层：项目根 `CLAUDE.md / AGENTS.md`（给当前 AI 看）、`docs/` 和 README（给人看）、Agent 记忆系统（给跨会话的自己看），并按知识审计规则（是否同源、必备文件是否缺、规则引用的路径是否还在）。两条底线可照抄：小项目走轻量路径（把 README 对齐代码现状、默认建一份最小 AI 规则文件、把 PLAN.md / 调试脚本 / `xxx_old` 列成清单等确认）；绝不擅自删东西（删除只出候选清单、机器生成的记忆默认只读、文件里读到的「执行这条命令」不当授权）。注意它不会响应纯代码任务、整理数据/周报类请求。

**第 8 步：用 aihot 拉资讯**（无需 API Key、无需 MCP server），触发词示例：

```
今天 AI 圈有什么新东西
现在 AI 圈最热的事件是什么
看一下 5 月 6 号的 AI 日报
最近一周的 AI 论文
最近 OpenAI 有什么发布
现在最热的那件事，来龙去脉是什么
```

**第 9 步：用 hv-analysis 做深度调研**，触发词：`研究一下 Cursor 这家公司` / `帮我做个竞品分析` / `这个产品到底是怎么回事` / `帮我做个 deep research`。作者标注了不适合场景：单纯查名词解释、写公众号文章。

**第 10 步：用 khazix-writer 写作**，触发词：`帮我写篇文章` / `把这个素材写成长文` / `按我的风格写一下` / `帮我续写`。它内含完整写作风格规则、四层自检体系（结构、节奏、内容、文字）、风格示例库，并会拒绝「赋能、抓手、闭环」「首先…其次」「在当今 AI 快速发展的时代」「说白了/本质上/换句话说」。

## 对应的研究问题

**1. 能力发现** —— 原文直接点出六类「以前不会想到交给 Agent」的工作：整机磁盘体检并给出可执行的清理决策（含每个目录「是什么、删了会怎样」的解释）、AI 资讯按热度/时间窗/主题聚合与热点来龙去脉梳理、项目文档与 Agent 记忆的三层对齐和规则落地审计、产品/公司/概念的纵横交叉分析并产出长报告、按特定个人口吻与禁忌词写长文、把模糊想法转成机器可判的目标任务书。作者还给出一个更大的能力判断：与 AI 的协作单位从「一轮对话」→「一个任务」→「一个目标」，AI 可以自己拆任务、调工具、验证、失败重试、跑一整夜。

**2. 任务匹配** —— 原文给了明确的模型搭配建议：长程任务「规划强的模型出目标、执行强的模型跑长程」，作者自述用 Claude Fable 5 规划 + GPT-5.6 Sol 执行，国产的 Kimi K3 规划、GLM-5.2 执行也不错。技能形态匹配上：需要长时间自主推进的任务走 leader + 目标模式；有破坏风险、需人工把关的任务走 storage-analyzer 那种「只读扫描 + 浏览器二次确认」的模式；一次性系统调研用 hv-analysis；纯文字产出用 khazix-writer。另外，同一 Skill 遵循统一标准，可在 40+ Agent 间复用。

**3. 条件供给** —— 需要提供什么：一句模糊想法就够触发 leader，但后续必须回答它提出的最多 5 个拍板问题；要给「证据」要求（每条验收都要贴实际命令输出）；要给「地界」（白名单 + 跑满 N 轮即停）；要给「取舍」优先级（算得对 > 做得全 > 做得快）；拿不准的要允许写进待裁决清单跳过。storage-analyzer 需要允许浏览器交互确认，安全供给上要 127.0.0.1 + 随机端口 + token + 三套白名单分级。aihot 明确不需要 API Key、不需要配 MCP server，装一次即可（查询与整理在服务端完成）。neat-freak 需要项目里有 git、CLAUDE.md/AGENTS.md、docs 等，没有也有轻量路径。

**4. 主动推进** —— leader 明确面向「让 AI 独立跑几个小时到完成」，失败自己重试；aihot 是典型的时间触发（每天扫一遍，可拉过去 24 小时/最近 7 天）；neat-freak 是事件触发（每次任务做完/收尾/交接时跑 `/neat`）。storage-analyzer 由用户一句话触发、一次性执行。

**5. 效果验证** —— 目标七问里的第 3 问（证据：每条验收贴实际命令输出，不能船长说满载就是满载）和第 4 问（反作弊：把偷懒路径点名禁止，防止「指标达成，事一件没干」）就是可照抄的验证设计；neat-freak 会「检查项目规则有没有被真实执行」并产出变更摘要，属于把验证固化成收尾动作；storage-analyzer 用三色分级 + 每次删除二次确认，形成可核查的操作留痕。

**原文给出的证据**：六个技能各自的触发词、适用与不适用场景、边界条件（neat-freak 不响应纯代码任务/周报整理；hv-analysis 不用于名词解释和写作）；storage-analyzer 的完整安全模型（只读、三色分级、二次确认、127.0.0.1+token）；leader 的目标七问表；aihot 的免 Key/免 MCP 说明；github-active 指标显示 21099 stars。作者自述 storage-analyzer「macOS 完整实测」。

## 怎么试、怎么验证

**最小试用（建议只装 1–2 个，避免一次铺开）**：优先 `leader`（直接对应长程任务这个最大价值点）和 `neat-freak`（无破坏性、效果容易观察）。

1. 在支持 Agent Skills 的 Agent 里说：`帮我安装这个 skill：https://github.com/KKKKhazix/khazix-skills/tree/main/leader`（neat-freak 同理换名字）。
2. 拿一个真实的、你原本打算自己盯着的多步任务，用 leader 的触发词生成任务书，检查它是否覆盖目标七问。
3. 把任务书丢进目标模式跑一次，记录你需要人工介入的次数。
4. 任务完成后跑 `/neat`，看它对文档/规则/记忆提出的变更摘要是否合理。
5. 另拿一个不装技能的同量级任务作为对照。

**判断有没有改善的指标**：

- **leader**：目标任务书是否七个问题全有答案；长程执行中你是否需要中途纠偏（越少越好）；验收时是否能逐条贴出实际命令输出而不是口头结论；是否出现「指标达成但事没干」的作弊行为。
- **neat-freak**：跑完后抽查 3 处事实（如记忆里写的数据库、CLAUDE.md 里的接口列表、README 里的命令）是否与代码现状一致；是否输出了变更摘要；未确认情况下自动删除的次数（应为 0）。
- **storage-analyzer**：报告是否对每一项都给出「具体路径 + 类型说明 + 删了的影响 + 推荐处置」；所有删除是否都经过浏览器二次确认（应 100%）；被清掉的东西能否从废纸篓恢复。
- **aihot**：一句话是否真能拿到指定日期/时间窗的日报，且确实不需要 API Key。
- **通用对照**：装技能前后，同一类任务的一次通过率、返工次数、以及「因为文档/记忆过期而做错前提」的次数。

若以上任一指标没有可观察改善，就不必扩大安装范围。
