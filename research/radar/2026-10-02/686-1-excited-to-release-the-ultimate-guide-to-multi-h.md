## 怎么试、怎么验证

**最小试用方式（不依赖原文的方法细节，先验证它的前提）：**

1. 取同一模型（同一个版本、同一份权重或同一个 API 模型名，记录版本号）。
2. 准备一小批固定任务（建议 20–50 条，覆盖你实际工作里最常出现的 2–3 类任务），任务描述、输入材料、验收标准写死，保存为文件。
3. 分别在同一台机器上、用清单里已有的两个 harness（Claude Code 与 OpenCode）跑同一批任务，关闭或固定联网、权限、工具集等可配置项，逐条记录版本号。
4. 每条任务的产出交给同一套人工或自动评分标准判分；判分时隐藏它来自哪个 harness，减少偏见。
5. 如果愿意，再追加一个 Codex 作为第三个 harness，观察差异是否稳定。

**判断有没有改善的指标：**

- 同一模型、同一任务集在两个 harness 下的任务成功率差异（主要指标）。
- 平均工具调用次数、平均 token 消耗、端到端耗时、需要人工介入的次数。
- 失败模式分布：是答不对、还是不会用工具、还是中途跑偏——这决定了差异来自模型还是来自 harness。

**判读规则：**

- 若两个 harness 的成功率差异稳定且明显（例如在固定任务集上重复多轮仍保持同一方向的差距），则原文前提在你自己的场景里成立，此时再把 harness 作为任务匹配和效果验证的必控变量，并考虑是否值得进一步投入训练类方法。
