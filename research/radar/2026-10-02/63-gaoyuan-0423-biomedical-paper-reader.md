## 是什么

biomedical-paper-reader 是一个面向**单篇生物医学论文精读**的 agent skill（v0.1.2，MIT 许可），用技能文件（`SKILL.md` + `references/`）驱动宿主助手完成三件事：跟随原文的图表与论证读懂实验为什么做、判断证据支持到哪里、提炼可以借鉴或可检验的研究设计。默认中文输出。输入只需 PDF、DOI、论文链接或原文，**不要求事先写研究问题**；交付物是一份结构化精读报告 `report.md`（必要时附 `assets/` 图像）。

## 具体做法

**前提**：宿主助手支持文件读取，并能读取 PDF/图像；联网能力为可选项。以下命令与提示词均照原文引用。

1. 获取技能文件（前提：有 git 与网络）。

```bash
git clone https://github.com/Gaoyuan-0423/biomedical-paper-reader.git
```

2. 在支持文件读取的助手中指定入口。路径相对于你的工作目录，必要时改用 `SKILL.md` 的绝对路径。

```text
请使用 ./biomedical-paper-reader/SKILL.md 阅读这份 PDF，生成中文精读报告。
```

3. （可选）装成本地技能，让客户端能发现。前提：目标目录尚不存在；使用自定义配置目录时改用其对应的 skills 目录；若已存在同名版本，先比较内容并保留自己的修改。安装后的发现/刷新行为由客户端决定。

```bash
mkdir -p ~/.codex/skills
git clone https://github.com/Gaoyuan-0423/biomedical-paper-reader.git ~/.codex/skills/biomedical-paper-reader
```

识别后调用：

```text
使用 $biomedical-paper-reader 解析这篇论文：<DOI、链接或附件>。
```

4. 准备输入与附加材料：给出 PDF/DOI/链接/原文之一即可。**补充材料默认只用本地已有文件**——检查上传内容、论文同目录与用户指定的相关文件夹，确认属于该论文后按需分析；没有补充文件就只用正文完成报告，并说明哪些判断未核查附件；只有用户明确要求补取时才联网下载。不要因附件缺失就断言作者未做验证。

5. 处理文本：**直接复用可读的 PDF 提取结果**（检查阅读顺序、保留页序），不再优先使用 MarkItDown，也不要求先生成 Markdown 底稿；原 PDF 留作数字与图像核查；只有具体页面的提取质量影响解读时才更换处理方式。

6. 看图：**每张主图先概览，必要面板再放大**；完整阅读图注，关注核心结论、必要对照、阴性结果及图文冲突；已看清的内容直接复用，同一图组的待查面板成组准备；报告要区分“概览”和“具体核查范围”。

7. 按默认顺序写报告：①开篇导读（核心发现、看点、阅读建议、适用场景）②文章信息（身份、来源、已读与未获取材料）③研究概述（已有认识、缺口、切入点、总体设计）④全文逻辑路线图（跟随原文证据推进，标注图表）⑤逐图/逐结果精读（动机、方法、结果、逻辑、边界、原图定位）⑥研究总结与课题借鉴（贡献、局限、可迁移环节、待验证设计）⑦数据与复现入口（资源用途、实际获取状态、关键缺口）。

8. 判定纪律：先建立原文章节、图表和主张索引，再核对正文、Methods、图注及实际图像，最后写判断；**独立个体数与细胞/切片数、观察与因果、作者解释与新增假设分别处理**；方法检查点按内容启用，不要求每篇都出现空间组学、通讯、谱系或动物实验；无图论文按主表、结果小节或方法单元展开；背景历史、复杂算法、写作表达按相关性决定深度。

9. 交付形式：有文件工具时在独立论文目录下交付 `report.md`，必要图像放 `assets/`，报告内链接保持相对路径；没有文件工具时直接输出文本。

10. 按需调整：补充研究方向可获得更贴合的迁移建议，未补充时给条件式适用场景；用户要求速读时压缩篇幅，要求专题方法解析时加深对应部分。

## 对应的研究问题

- **能力发现**：把“精读一篇论文并产出结构化报告”整体交给 agent——逐图理解、评估证据边界、提炼可检验课题、生成带图表定位的路线图，这些原本多由研究者手工完成。README 还给出边界行为：材料不足时合并空章节、集中说明证据与关键缺口。
- **任务匹配**：适合“一次一篇、需要读 PDF/图像、要出结构化文档”的阅读任务；依赖宿主提供文本、文件、PDF/图像与可选联网能力，不要求固定 MCP、第三方 skill、Python 库或付费服务；给了 Codex 的本地技能目录安装路径。
- **条件供给**：需提供 PDF/DOI/链接/原文之一；优先提供本地补充材料（上传内容、论文同目录、指定文件夹）；是否具备文件工具决定输出 `report.md`+`assets/` 还是纯文本；可补充研究方向以换取更贴合的迁移建议；只有明确要求才下载附件。
- **主动推进**：README 只描述按需处理单篇论文，未给出由时间、事件或状态触发并持续执行的机制，**此项无依据**。
- **效果验证**：仓库含 `evals/cases.md`、`evals/fixtures/`（原创虚构材料）与 `evals/RESULTS.md`；验收关注真实行为而非只检查标题或关键词；用两篇真实论文试读加三份虚构短文检查来源缺失、观察证据与计算预测的适配。README 同时强调未实际执行的代码和数据不会被标为已经复现。

## 怎么试、怎么验证

**最小试用**：clone 仓库后按上文第 2 步，对一篇**自己已读过、心里有底**、含多张主图（或主表）的论文生成精读报告，逐项对照自己的理解；再对一篇只有摘要或片段可得的论文试一次，看它是否正确声明覆盖范围与暂定判断。

**判断有没有改善的指标**（可人工计数）：

- 覆盖：每张主图是否都被讲到、图注是否被引用、有无遗漏面板；
- 判定纪律：是否区分独立个体数与细胞/切片数、观察与因果、作者解释与新增假设；
- 诚实度：是否列出“已读与未获取材料”、未核查附件处是否说明、是否把未执行的代码/数据误标为已复现；
- 产出可用性：第⑥节是否给出可迁移环节与待验证设计，能否直接转成自己可做的课题；
- 代价：人工精读耗时 vs 生成加核对的耗时。

若多数项达到或超过自己人工精读的水平，可继续用于同类论文；只在个别论文类型上有效，就限定使用范围，并把不适用处记下来反馈到仓库 Issues（README 建议附论文 DOI/公开链接、出问题的输出、原文定位与期望处理方式）。
