## 是什么

recalc 是一个开源桌面应用（Apache 2.0），把电子表格做成调度多个 AI 编码代理的外壳：每个单元格可以是一个值、一条公式、一条 shell 命令、一个动作，或者一个 agent（Claude Code / Codex / pi）。代理把计划和结果写进单元格，你实时观看，点开任意单元格可进入它自己的终端，也可以直接改它填的单元格来“ steer ”，不用打断对话。不同 Claude Code / Codex 实例通过一个 MCP server 理解看板结构。

作者自述定位是“harness of harnesses”，目前处于 very early beta，macOS 为主，Linux 实验性，无 Windows。

## 具体做法（编号步骤；可直接复制的命令、配置、提示词原样放进代码块；写清每步的前提）

前提：macOS（Apple silicon 或 Intel）或实验性 Linux；已有一个可用的 Claude Code / Codex / pi 账号并登录过一次。

1. 安装 recalc（脚本会装到 Applications 并在 PATH 上加 `recalc` 命令；作者建议先读脚本）：
   ```
   curl -fsSL https://raw.githubusercontent.com/sshah03/recalc/main/install.sh | sh
   ```
   手工安装的替代路径：下载 `.dmg` 拖进 Applications，然后清一次隔离标记（beta 未签名）：
   ```
   xattr -dr com.apple.quarantine /Applications/recalc.app
   ```
   再通过 recalc → Install Command Line Tool… 装上 `recalc` 命令。

2. 准备代理：装好 Claude Code / Codex / pi 之一并登录一次。打开 Agent → Connect an Agent，看 recalc 是否识别到。

3. 用官方示例跑通“批量填充”这一基本动作：File → New Board… → Examples → 选 “Legal due diligence”，选中空的答案单元格，执行 Cell → Run Selection（⇧⌘↩），观察代理逐个填格。

4. 把看板接进自己的项目（让代理从自己的聊天里操作看板）：在项目目录下执行
   ```
   claude mcp add recalc -- recalc mcp
   ```
   若 PATH 里没有 `recalc`，Agent → Connect an Agent 会显示带完整路径的同一行命令。之后照常工作，代理会自己使用看板。

5. 掌握单元格前缀语法（这是全部配置的核心，照抄即可）：

   | 你输入 | 类型 | 行为 |
   |---|---|---|
   | `42` | 值 | 静态不动 |
   | `= {passed} > 0` | 公式 | 依赖单元格变化时更新 |
   | `$ npm test` | 命令 | 在你的终端跑，输出成为该格的值；输入变化时自动重跑（`$1,200` 会被当作金额） |
   | `! git push` | 动作 | 只有你手动运行才执行，用于任何会改变东西的操作 |
   | `@claude('summarize {A2}')` | agent | 调 Claude（或 `@codex`、`@pi`），答案写回单元格；只有你运行才执行 |

   跨格引用用 `{A2}`。

6. 搭一个“文件×问题”的只读网格：文件放侧边、问题放顶部，按 Run 让 agent 填满每个单元格；答案带原文定位，点单元格可看到引文高亮；勾选已核对的答案后代理不能再覆盖；完成后可导出到 Excel。

7. 给每个 agent 单元格配一个校验单元格（最值得抄的模式）：把跑测试的 `$` 命令格放在代理“说完成”的格子旁边，代码一变测试格自动重跑；代理说完成但测试红着，你立刻看到。README 还写明可以阻止一个 Claude Code 会话完成，直到它那一行变绿。

8. 设置成本上限：Set Agent Budget… 给看板设预算。README 说明 recalc 本身免费，费用来自你自己的 Claude/ChatGPT 套餐；界面上的美元数按 API 价格折算，用来衡量一个看板消耗了多少套餐额度。

9. 看板存放位置：默认 `~/Documents/recalc boards`，随改随存；在项目里用 File → Open Folder… 打开，看板落在项目内的 `.recalc` 文件夹，可提交也可忽略。任何项目目录里敲 `recalc` 都能打开。

10. 跑一遍带校验链的完整示例（虚构客户账目 → IRS 2026 草案 Form 1120-S，代理分类科目、公式建表并检查、校验通过后才执行填充 PDF 的动作）：
    ```
    recalc demo scorp
    ```

11. 想接本地模型跑私密文档，见 `docs/LOCAL.md`；想让代理懂“看板上该怎么干活”，把仓库根目录的 `AGENTS.md` 复制进自己的仓库。

安全前提（README 明说）：`!` 动作和 agent 单元格只有你手动运行才执行，代理不能成为它自己写的动作的第一个执行者；但 recalc 不是沙箱，命令以你的权限运行，要放在你本来就会跑这些命令的环境里。

## 对应的研究问题（对照上面五个问题逐条说明，只写有依据的）

**1. 能力发现（AI 能做哪些还没想到交给它的工作）**
- 同一组问题批量问上百份文档（文件放侧边、问题放顶部，一次 Run 填满整片单元格），每个答案附可点开的原文出处。
- 把“代理说完成了”这件事外包给旁边一个自动重跑的测试单元格来判定。
- 多个 agent 各占一行并行跑，在一屏内同时盯住，异常（提问、报错、完成）汇到一个 **Needs You** 列表。
- 让一个 **Driver** agent 根据一句 prompt 替你搭看板。
- 用一个看板当模型评测台：把“每个决策公布前冻结的卷宗”喂给不同模型预测 FDA 决定，给新模型加一列当参赛者，打分，再点开某个答案进 Terminal 问它为什么。

**2. 任务匹配（什么工作适合怎样的模型、工具和协作方式）**
- 批量抽取/审阅类任务 → 网格 + 带引用的 agent 单元格 + 勾选锁定人工已核结果。
- 只读的检查/运行 → `$` 命令格，随输入变化自动重跑。
- 会改变外部状态的操作 → 一律 `!` 动作，人工触发，代理不得先跑。
- 需要交互式追问的 → 点开单元格进它自己的 Terminal 继续问。
- README 演示文字提到“an agent column on Haiku”，即按列选择更便宜的模型跑批量列。

**3. 条件供给（需要提供哪些信息、工具、权限和反馈）**
- 工具：先装好并登录一个 agent CLI；MCP（`recalc mcp`）让代理知道看板存在及其结构。
- 信息：单元格之间用 `{A2}` 传值；`AGENTS.md` 明确告诉代理在看板上该怎么工作，可复制进自己仓库。
- 权限：`!` 动作必须人工执行，代理不能首发；但整体不是沙箱，按你的权限跑。
- 预算：Set Agent Budget… 给看板封顶；每次运行的成本按 API 价显示。
- 反馈：校验单元格变红即为反馈信号，可挡在代理“完成”之前。

**4. 主动推进（哪些工作可由时间、事件或状态触发并持续完成）**
- 状态触发：`$` 命令格在其输入变化时自动重跑；测试格随代码变化自动重跑。
- 事件汇聚：任何需要你的东西（提问、错误、完成的答案）落到统一的 Needs You 列表。
- 定时：每天检查一次新版本（可关）；这属于应用自身行为，不是工作流自动化。
- 明确边界：`!` 动作与 agent 单元格默认不自动执行，README 的立场是“会改变东西的都不自己跑”。

**5. 效果验证（怎样判断确实改善了结果）**
- 测试格红/绿作为完成门禁：代理宣称完成时测试失败会立刻暴露，甚至可阻止会话结束。
- 引用可回溯：每个答案链接到确切段落，点击高亮，人能低成本核验；勾选后代理不能覆盖，形成人工确认层。
- 公式交叉校验：10-K 示例里 16 个数字各带来源行，并用公式检查彼此一致，一直查到附注解释的 1440 万美元差额。
- 成本口径：界面美元数按 API 价格折算，用来衡量一个看板消耗多少套餐额度。

## 与已有做法的关系

清单中只有 **Claude Code（状态 adopt）** 相关。recalc 不替代 Claude Code，而是把它当成被调度的执行单元：为多个 Claude Code / Codex 实例提供共享表格界面、MCP 接口、并行编排、校验单元格与人工确认层。可以理解为在“直接用终端跑 Claude Code”之上加了一层可视化调度与结果核验；`claude mcp add recalc -- recalc mcp` 就是两者对接的具体接口。清单中没有其他编排/表格类条目。

## 怎么试、怎么验证

**最小试用（半天内可完成，全只读）**
1. 按上面步骤 1–2 安装并连上一个已有代理。
2. 先跑官方 “Legal due diligence” 示例，确认 Run Selection 能把一片空格填满并显示引用。
3. 换成自己的真实小任务：选 5–10 份文档、3–5 个问题，搭一张小网格，只用 `@claude(...)` 单元格，不碰 `!` 动作。
4. 在其中一行加一个校验单元格（例如 `$` 跑一个检查脚本，或一条 `=` 公式核对关键字段），观察它是否随上游变化自动重跑并变红。
5. 可选：在自己项目里执行 `claude mcp add recalc -- recalc mcp`，看代理是否能主动读写看板；先在小仓库试。

**判断有没有改善的指标**
- 引用可核验率：随机抽 20 个答案，能点开出处且引文确实支持结论的比例（对照：手工查文档的同等抽查）。
- 人工复核时间：完成同一批任务的总耗时（含搭网格时间）对比原来的手工/单会话方式；注意把一次性搭建成本单独记。
- 错误捕获数：校验单元格变红并成功拦截“假完成”的次数——这是它相对纯聊天式代理最直接的价值点。
- 覆盖率与漏项：网格里应有 N×M 个答案，实际填满且非空的比例。
- 套餐占用：Set Agent Budget 下每个看板折算的美元数，比较不同模型列（如 Haiku 列 vs 更强模型列）在同等质量下的消耗。
- 稳定性：一次试用期内崩溃/丢数据的次数（崩溃日志在 `~/Library/Logs/recalc/crash.log`，Linux 在 `~/.local/state/recalc/crash.log`）。

**升级为 adopt 的门槛**：以上指标稳定优于现有做法、连续使用两周无数据丢失、且已把校验单元格设为默认习惯；在此之前按 beta 对待，只用于可重跑、可丢弃的中间产物。
