## 怎么试、怎么验证

**最小试用方式**（不依赖该插件，验证的是模式本身）：

1. 挑一次真实的、你本来就要审阅的 Claude Code 计划（条目较多、含若干待确认问题的那种）。
2. 把计划文本手工整理成一页本地 HTML：顶层写计划目标，子节点按「阶段/文件/风险」折叠，默认只展开第一层；待确认问题做成 `<button>` 选项。
3. 用这一个真实计划跑通「读页面 → 点击作答 → 把选项结果贴回 Claude Code」的完整往返，至少做 5 次。
4. 如果体验成立，再去找该插件的仓库与安装方式，替换掉手工步骤。（在拿到安装信息前不要把它写进团队流程。）

**判断有没有改善的指标**（都能在 5 次试用内测出来）：

- 从计划出现到给出确认的**耗时**（对照你过去读纯文本 plan 的耗时）；
- 确认过程中的**往返轮次**（有没有因为漏读某条而反复澄清）；
- **误改率**：事后发现「当时没看清就点了同意」的次数；
- **漏项率**：折叠层级是否让你漏读了关键问题（这是树状折叠的主要风险，必须专门检查）。

如果耗时下降但漏项率上升，说明「一次展开一层」在减少信息过载的同时也隐藏了风险，需要保留一个「全部展开」的兜底视图再决定是否采用。
