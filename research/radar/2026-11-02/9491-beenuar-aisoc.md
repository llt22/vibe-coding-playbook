## 是什么

AiSOC 是一个可自托管的开源 AI 安全运营中心：摄取安全遥测 → 规则检测与关联成事件 → AI 智能体调查（每次提示词与工具调用都被记录）→ 提出处置动作，由人批准后才触达外部厂商。

对本项目的价值不在“安全”这个领域，而在于它把一套可审计、可回放、需人工批准的 LLM 智能体流水线做成了可运行、可做失败验证的开源实现，其中几个构件可以直接照抄到任何需要“说清 AI 为什么这么判断”的工作里：

- **Investigation Ledger**：记录提示词、工具调用、引用、结论、token 成本，并可导出为**签名证据包**（字节级一致，提示词以摘要形式，OCSF 1.9.0）。
- **依据核验**：结论引用了证据里从未出现过的指标时，降级为人工复核，而不是自动关闭事件。
- **提示词发送前校验**：原始日志、OCSF 载荷、形似密钥的值被拒绝，而不是事后脱敏。
- **受约束的工具调用**：模型只负责选工具、传参数，从不写 SQL；hunt 时模型只填封闭 schema，每个值都绑定为参数，因此“根本无法表达一条查询”。
- **执行权是挣来的**：规则必须用厂商形状的事件重放穿过真实连接器与引擎并被“看着触发”，才进入编译规则集，绝不从目录或 `enabled:` 标志推断。

## 具体做法（编号步骤；可直接复制的命令、配置、提示词原样放进代码块；写清每步的前提）

**步骤 1｜零依赖最小试跑（前提：只要能 `pip install`，无需 Docker）**

```bash
pip install aisoc-sandbox && aisoc-sandbox demo
```

README 称 30 秒内离线把一条告警走完智能体处理流程。这是成本最低的观察入口。

**步骤 2｜完整本地部署（前提：Docker Compose v2，Docker VM 内 8 GB 内存、20 GB 空闲磁盘，`python3` 3.9+，`bash`）**

```bash
git clone https://github.com/beenuar/AiSOC && cd AiSOC
make up
```

先跑 `make doctor` 检查主机工具、内存、磁盘、端口和各数据存储（方式是查询数据存储，而不是看容器是否在跑）。

Windows 或空白机器可以一行装完依赖：

```powershell
iwr -useb https://raw.githubusercontent.com/beenuar/AiSOC/main/install.ps1 | iex
```

```bash
curl -fsSL https://raw.githubusercontent.com/beenuar/AiSOC/main/install.sh | bash
```

也可以用 GitHub Codespaces 打开仓库，在终端里 `make up`。首次运行会下载约 2 GB 模型到一个 volume，只有 `make clean` 能清除。

**步骤 3｜拿到登录凭据（前提：已执行 `make up`）**

`make up` 会创建 `.env` 并生成其中 **15 个**密钥（凭据保险库、会话签名密钥、五个服务间凭据、四个数据存储密码），并创建管理员、打印一次密码（生成在本地、只显示一次、不存储）。丢失后：

```bash
make bootstrap ARGS=--reset-password
```

端口被占用不会中断安装：它会发布到空闲端口，打印占用的进程，并随之改变控制台地址（README 举例：5432 与 11434 都被占时，裸克隆 64 秒到已登录控制台）。

**步骤 4｜证明它真的能跑（前提：栈已启动）**

```bash
make smoke
```

它会发一条真实事件到 ingest API，让它穿过 Kafka、检测、关联、Postgres，再从公开 API 读回这条告警，每个阶段报 PASS/FAIL：

```
$ make smoke
[PASS] raw telemetry accepted by ingest
[PASS] event traversed the spine and became an alert
PASS: 10/10 stages
```

**步骤 5｜用样例数据观察分流（前提：已登录控制台）**

在向导里按 **Load sample data**：五个场景走真实连接器用的同一条 ingest 路径（不是插入行），故意覆盖从低到严重。它们标注来源为 `AiSOC`，如果租户已有真实告警就拒绝加载，并且**不会**把 setup 标记为完成。要更大的固定语料用：

```bash
make demo
```

它加载**合成**数据集（每行 `is_synthetic = true` 且在控制台标注），README 明确说这是流水线形状，不是基准、不是客户、不是真实事件。

**步骤 6｜接入真实数据（推送路线，前提：`make ingest-token` 取到凭证；租户由凭证决定，不由 header 决定）**

```bash
make ingest-token
```

```bash
curl -X POST http://localhost:8081/v1/ingest/batch \
  -H 'Content-Type: application/json' -H "Authorization: Bearer $AISOC_INGEST_TOKEN" \
  -d '{"connector_id":"edr-1","connector_type":"crowdstrike","events":[{"severity":"high",
       "title":"Encoded PowerShell from Office","host":"WIN-FIN-01"}]}'
```

**步骤 7｜接入真实数据（拉取路线，前提：有对应系统凭证）**

在 **Settings → Connectors** 配置 90 个点击式连接器之一（Splunk、Sentinel、Elastic、CrowdStrike、Okta、AWS、Kubernetes audit 等有厂商专用归一化与安装文档）；没有厂商配置文件的连接器走通用映射，解析 host、user、source IP。云上另有四个采集器读真实出口：CloudTrail 组织跟踪经 **S3 + SQS 通知**、**GCP Pub/Sub**（Cloud Logging sink）、**Azure Event Hubs** capture、**syslog/CEF** 监听；每个都保留可恢复游标和每轮预算，积压时形成背压而不是淹没 ingest。

**步骤 8｜迁移已有检测规则（前提：已有 Splunk/等规则集）**

`packages/aisoc-migrate` 负责翻译 Splunk SPL、Sentinel KQL、Elastic EQL，翻不动时**拒绝而不是近似**（因为“差不多对”的规则比缺失的规则更难发现）。README 给出：随附 2005 条 Splunk 规则中 1734 条可译，其中 1711 条是部分翻译。

**步骤 9｜让规则“挣得”可执行资格（前提：有可重放的厂商形状事件）**

只有当一条规则被厂商形状事件穿过真实连接器与引擎重放、并**被看到触发**，才进入编译规则集。反向自检：

```bash
--prove-gate
```

它会回退 Windows 连接器并要求 1687 条 Windows 规则全部静默。注意其含义是“可达”，不是“能检测出攻击”；仍有 **2** 条规则无法触发（从 119 条降下来，因为无法触发的规则不再计入可执行），两条都在等行为基线，这个棘轮只减不增。

**步骤 10｜让动作默认只预览、人批准后才执行（前提：想开自动响应时）**

由告警触发的 playbook 必须先预览再动作。三重开关必须同时同意——部署、租户、playbook——且每个默认关闭；缺一个就以预览运行，并把计划附在告警上。审批步骤是**可持久暂停**：运行挂起到 Postgres，重启后存活，在批准后恢复，过期则记录结果而不是挂死。审批人必须持有要求的权限层级，且不能是发起该动作的人。

**步骤 11｜换模型或加速（前提：有 GPU 或自有 provider）**

```bash
make up-gpu
make up-host-llm
```

还可以在控制台配自己的 provider（任何本地 OpenAI 兼容端点）。默认随网关发的是 Ollama 上钉死版本的约 2 GB `llama3.2:3b-instruct-q4_K_M`（CPU 推理）。默认安装不会把提示词发往任何地方，模型跑在旁边。

**步骤 12｜把“测量”本身做成可复算（前提：想引用它的任何数字）**

```bash
make test    # 每个服务的单测
make smoke   # 对运行中的栈跑黄金流水线
make stats   # 重算 README 发布的每个数字
```

README 声称每个计数都从代码树重算，README 与事实不符时 CI 失败。

## 对应的研究问题（对照上面五个问题逐条说明，只写有依据的）

**1. 能力发现：AI 已经能做哪些还没想到交给它的工作**

- 告警分级（给结论、置信度、理由原文）、事件调查、写处置建议。
- 跨数据源取证：模型调用**类型化工具**（lake 查询、图遍历、enrichment 查询），自己选工具、传参数，**从不写 SQL**。
- 假设驱动的狩猎：新情报到达时重扫已收集的历史 lake，一个假设不经任何人写查询就能变成一次 hunt——模型填一个封闭 schema，每个值绑定为参数。
- 阅读范围明确：读告警、其关联的兄弟告警、实体上下文、同一签名的历史结论。

**2. 任务匹配：什么工作适合怎样的模型、工具和协作方式**

- **按任务评估模型**：矩阵在同一锁定证据上给每个已配置模型打分，对照一条确定性基线底线（balanced accuracy 恰为 0.250）；未出资的行写 *not measured*，并附一条命令可在任何本地 OpenAI 兼容端点上复现。
- **输出结构化是被测量过的关键变量**：约 2 GB 的 `llama3.2:3b` 在 50 条告警上，把回复约束为 JSON 之前可用输出 44 次，约束之后 50 次（方法脚本 `scripts/measure_triage_reliability.py`），界面上标注是哪条路径答的。
- **模型不前沿也没关系**：明确写“它不是前沿模型”，用受限工具调用 + 封闭 schema 弥补。
- **协作方式**：copilot 模式（人批），可显式给某个动词授权自治；每次响应步骤在派发时按其自身能力契约分级，所以批准一个 playbook 不等于授权其步骤里恰好包含的任何动作。

**3. 条件供给：需要提供哪些信息、工具、权限和反馈**

- 资源：Docker Compose v2、8 GB（full 档 12 GB）内存、20 GB 磁盘、python3、bash。
- 凭证与通道：`make ingest-token` 的 ingest 凭证（租户由它决定）、连接器凭证静态加密、`.env` 里 15 个自动生成的密钥。
- 数据：遥测接入（推送或 90 个连接器/四个采集器）、lake（ClickHouse，full 档）、实体图（Neo4j，full 档）。
- 租户级调优反馈回路：控制台写入的禁用、地板（floors）、抑制会真实作用到实时引擎，“你关掉的规则就真的不再触发”。
- 输入卫生：提示词发送前校验，原始日志、OCSF 载荷、形似密钥的值被拒绝。
- 权限：RBAC 管每个变更路由；SAML/OIDC 带按连接租户与组映射、SCIM、控制台 MFA（TOTP + 恢复码，可按租户强制）；属性条件、限时提权和 workload identity 走同一条权限路径，条件只能收窄权限、不能授予。
- 无凭证的服务拒绝服务而不是无认证地服务。

**4. 主动推进：哪些工作可由时间、事件或状态触发并持续完成**

- **事件触发**：告警 → 关联 → 智能体调查并写 Investigation Ledger → playbook 可从结论启动。
- **时间触发**：调度连接器（对 stub 厂商轮询进 ingest，带反向验证）；68 个 hunt 的 YAML 库按计划对 lake 中的租户事件编译执行，且拒绝回退到 fixture。
- **状态触发**：新威胁情报到达 → 重扫已收集的历史；审批挂起可跨重启恢复、到期带记录。
- **边界**：历史回放**时间冻结**，在检索查询里强制证据截止（不是靠提示词），披露模型知识截止，并且**不能执行真实动作**（变更边界是写适配器）。把新情报应用到旧遥测是另一种可排练的模式，其发现绝不计为原事件时刻的预测。

**5. 效果验证：怎样判断确实改善了结果**

- 分阶段 PASS/FAIL 的黄金流水线（`make smoke`，10 阶段），而不只是“容器起来了”。
- **归属**：每份结论评分卡写明实际服务的模型（网关证明或自报，带显式来源状态）；缺归属、零真实调用或确定性回退的运行，不能当作某个具名模型的成绩；无法绑定到有归属调用的测量不能授权关闭事件。
- **分母公开，且不舒服的方向胜出**：全cohort 召回把弃权和失败留在恶意分母里；关闭声明带其污染率；告警压缩给三个标注过的数字（75.3% 旧分组、33.3% 生产键、24.5% 检测形状 cohort——修补缺失标识符时是**收窄**分组而不是放宽）。未测量写 *not measured*，永不写 `0`。
- **Stable 有定义且有门禁**：一行只有满足“每次 PR 都跑、无路径过滤、驱动真实生产路径打真实基础设施、且有一个靠把东西弄坏看它变红证明过的负控制”才算 Stable（此前有三行描述的能力实际不存在）。
- **可观测的反射路径**：从排队延迟到验证共九个命名阶段，加一份决策契约，携带支持证据、矛盾证据、缺失前置条件和升级理由。
- **接地检查**：结论引用证据里没有的指标 → 降级人工复核。
- README 自陈局限：demo 与样例事件不是真实事件，基准数字是**基底自一致性度量，不是实时智能体准确率**。

## 怎么试、怎么验证（最小试用方式和判断有没有改善的指标）

**最小试用（两条路线，按成本递增）**

1. **零依赖 30 秒版**（先做这个）：

```bash
pip install aisoc-sandbox && aisoc-sandbox demo
```

观察一条告警走完智能体处理流程时，到底记录了哪些字段（提示词、工具调用、引用、结论、token 成本）。把这份记录结构抄成你自己智能体任务的日志模板。

2. **完整栈版**（需要 Docker 资源）：`make doctor` → `make up` → `make smoke` 看是否 10/10 PASS → 控制台 Load sample data，观察五档严重度如何被分流（若一上来全是危机，就学不到分流在分离什么）→ 配置一个连接器或按步骤 6 curl 推一条真实事件。

**判断有没有改善的指标**

- **流水线 PASS 阶段数**：`make smoke` 是否 10/10；任一阶段 FAIL 就不要往下走。
- **结构化输出可用率**：迁移到你自己的任务上，先跑 20–50 条真实样本，统计“结论可直接使用”的比例，再对比“把回复约束为 JSON / 固定 schema 后”的比例。原文在 50 条告警上从 44/50 提到 50/50，这是可复现的对照方式（方法在 `scripts/measure_triage_reliability.py`）。
- **引用可核验率**：每条可核查的断言能否指到某条 ledger 记录；剩下多少被标成 *uncited*（原文的做法是标注而不是丢弃）。
- **降级率**：因依据核验不过而降级人工复核的比例——太高说明模型/证据供给有问题，为零反而要怀疑核验是否真的在跑。
- **人工负担与压缩比**：定义并公布你自己的分母（原文给了三个口径就是提醒这一点），比较接入前后的单位时间处理量与人工复核占比。
