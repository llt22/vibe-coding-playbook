## 是什么

Simon Willison 发布 datasette-agent 0.5a0（2026-11-03），一个给 Datasette 用的 LLM agent。这一版最主要的新功能叫 **panel**：agent 的对话窗口打开后，可以“停靠”在 Datasette 的页面旁边，例如某张表的数据页或查询页（原文：*"it lets the agent chat open and then sit next to pages from Datasette, for example a table or query page"*）。

## 怎么试、怎么验证

**最小试用（不改代码，只验证交互模式）**

1. 用 GitHub 登录 agent.datasette.io；如无法访问或不适用，改用一个自己的聊天窗口 + 一个数据库客户端并排摆放，手动充当“panel”，作为对照基线。
2. 选一张自己的小表（10 万行以内、字段含义清楚），做三件事：(a) 改一个已有查询；(b) 让 agent 生成一个小应用；(c) 在 panel/聊天里对产物提一次修改。
3. 全程记录三件事：从“看到结果”到“说出下一句指令”的间隔；需要手动复制粘贴上下文（表结构、报错、查询结果）的次数；每处改动达标所需的对话轮数。
4. 同样的三个任务，在“聊天窗口与数据库工具分开、需手动粘贴上下文”的条件下重做一遍。

**判断是否改善的指标**

- 单个小改动的端到端耗时（同屏组与分离组对比）；
- 每处改动所需对话轮数；
- 手动粘贴上下文的次数（目标为 0，这是“产物即上下文”是否真的成立的直接证据）；
- 产物无需返工即可使用的比例；
- 出错时 agent 能否看到报错并自行修正（若看不到，说明 panel 只解决了“看得见”，没解决“喂得进”，该模式的价值会大打折扣）。

**判定门槛**：若同屏组在耗时或轮数上稳定优于分离组，且粘贴次数接近 0，则该交互模式值得写入手册；若差距主要来自模型本身而非“是否同屏”，则只能作为界面建议而非工作法。由于原文未提供任何本地部署方式，此验证只能在 demo 或自建对照组上完成。
