## 怎么试、怎么验证

**最小试用方式**（基于唯一可辨认的一步自行设计，属于验证性试验，不是原文方案）：

1. 选一个低风险、有测试环境的产品模块。
2. 建一个测试账号或 API 凭据，只授予该模块的读写权限；不给生产数据写权限。
3. 让 Agent 按一组固定场景（登录、下单、改配置等核心路径）跑一遍，输出问题清单（位置、复现步骤、期望与实际）。
4. 同时收集同期的客户反馈，人工把两份清单合并去重，看 Agent 那份里有多少是客户反馈没覆盖到的。
5. 连续跑 2 周，人工给每条 Agent 报告打标：真问题、误报、重复。

**判断有没有改善的指标**：

- Agent 独立发现的真问题中，客户反馈未覆盖的比例（衡量“能力发现”的增量价值）。
- 误报率与重复率（衡量人工筛选成本是否低于自己找问题的成本）。
- 从问题出现到被记录的时间，与纯靠客户反馈的基线对比。
- 工程师每周花在“小修小补”上的小时数变化。

如果误报和重复占了大头、人工筛选成本超过收益，就说明这条思路在当前产品上不成立，不必继续扩展。
