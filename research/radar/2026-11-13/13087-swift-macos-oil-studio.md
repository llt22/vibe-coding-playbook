1. **动手前先做技术选型调研。** 让 AI 调研成熟开源项目和技术栈上限，明确区分 MIT/Apache 与 GPL/AGPL 等协议风险；按业务需求和性能需求选语言，即使开发者本人不熟悉该语言。前提：先写清业务约束和性能底线。
2. **建立多模型分工。** 用沟通感和产品能力强的 Claude 做主对话、写人能看懂的方案，并保持主上下文干净；通过 oil-delegate 调用 Codex（GPT 模型）做方案挑刺、写代码和边界 Review。原文称每天能跑掉 10 亿+ GPT Token，同时节省 Claude 额度。前提：需要有稳定的第二模型调用通道和成本控制。
3. **用 Git Worktree 并行开发多个功能。** 把计算逻辑测试和 UI 测试拆开；把高频调试操作封装成 CLI 脚本，并支持桌面端后台静默运行；定期删除凑数的表面单测。前提：仓库支持 worktree，且测试能按逻辑层和 UI 层分离。
4. **把反复踩坑的问题沉淀成规则。** 人工介入重点放在治理流程，而不是逐行救火；把问题写进 AGENTS.md 和 Review.md，用 oil-ui 统一交互和样式规范。前提：团队或项目愿意维护规则文件，并在 Review 中执行。
5. **定期清理过期文档。** 错误文档比没有文档更可怕；定期让 AI 对照代码巡检文档，删除或更新过时内容。前提：有文档目录和代码变更记录可供对照。
6. **对疑难 Bug 止损，并给发版兜底。** 久修不好的 Bug 让两个强模型交叉排查并给出置信度；置信度低、维护成本高的功能直接换方案实现。发版时用程序硬校验卡住测试和版本号更新；桌面客户端增加崩溃自动回退的“安全模式”引导更新。前提：发版流程可脚本化，客户端具备回退或安全模式能力。
