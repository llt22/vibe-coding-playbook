## 是什么

推文介绍的是字节跳动联合纽约大学等团队的一篇论文 Veritas: A Verifier Generation Harness for Agent Tasks。按推文说法，它做的是「让专门的 agent 自动生成验证器程序」，用于 RSI（迭代式自我改进）循环中判断「这一版比上一版更好还是更差」。推文归给它的机制有四点：

1. 生成评测代码之前，先强制声明验证器在运行期真正能拿到的输入接口；
2. 确立「状态对比优先」的原则：执行轨迹最容易被 agent 伪造（例如 agent 在输出里声称订单已退款，但只有数据库实际状态不会说谎）；
3. 任务描述里默认的行业常识由系统自动检索并挂载，防止生成的验证器漏检；
4. 引入通过 RSI 循环蒸馏出的测试准则，例如「生成的验证器面对初始环境就判 PASS」时立即触发重构。

推文还主张：在固定基础模型的前提下，Veritas 生成的验证器在绝大多数基准上超过 Codex CLI、Claude Code、Gemini CLI、OpenCode 等 7 款主流通用 harness。

**试用范围**：挑 5–10 个已有明确状态可查的任务（如批量改配置、数据修复、依赖升级、文件迁移），保留原流程做对照。

**判断是否改善的指标（以下为建议度量，非原文给出）**：

1. 伪造通过率：人工抽查「agent 声称完成但真实状态未变」的案例数，试用前后对比；
2. 初始环境误判 PASS 次数：约束 B 拦下了多少次坏验收脚本；
3. 返工率与下游失败率：验收 PASS 后仍需人工返工的比例；
4. 验收成本：每个任务编写/生成验证器的时间与 token 消耗；
5. 只有 1 与 3 显著下降且 4 没有同幅度上升，才算「确实改善了结果」。
