## 是什么
pxpipe 是一个开源代理，插在 Claude Code 和模型之间。Claude Code 每一轮都会重发同一大批静态文本：系统提示、CLAUDE.md 指令、工具 schema。原文称约 48,000 字符，约 25,000 文本 token/轮。pxpipe 拦截这些静态块，在本地渲染成一张清晰 PNG，改以视觉 token 计价（原文称约 2,700 token，约 1/9），作者给出的单次会话账单是 $42.21 → $6.06。

本质是一条“计费口径套利”思路：同一段内容，按文本 token 计价贵，按图片计价便宜，于是把不变的前缀换成图片。

## 对应的研究问题

- **能力发现**：提示了一条容易被忽略的用法——把“不变的上下文”当成可重新编码的资产（文本→图片→视觉 token），而不是只能压缩文字。可迁移到任何“每轮重发长固定前缀”的场景（超长 CLAUDE.md、大工具集、固定规范文档）。
- **任务匹配**：适配对象是“静态前缀占比高、轮数多”的编码智能体会话；对每轮内容都在变、前缀很短的短对话，收益很小甚至为负（多一层代理、多一次图片编码）。原文只举了 Claude Code 一例。
- **条件供给**：需要（a）能在客户端与模型之间插入本地进程的权限，（b）本地把文本渲染成清晰图片的能力，（c）代理能识别哪些块是静态可替换的。原文没有说明 pxpipe 如何判定“静态”，这决定了它是否会把该保留的文本也图片化。
- **主动推进**：原文未涉及任何时间/事件/状态触发的持续执行机制，无依据。
- **效果验证**：原文给了可对照的两个量：会话账单（$42.21 → $6.06）和输入 token（约 25,000 → 约 2,700），并主张工具调用准确率不降——后者只是主张，无数据。

**可信度疑点**（不编造，仅指出无法核实之处）：原文出现的模型名 “Claude Fable 5.2”“Opus 5.5” 与已知命名不符，无法核实；仓库链接断行；全文只有推文正文，没有 README、安装说明、issue 或第三方复现。若打开仓库发现与实际描述不符或已不存在，本条目应降级为 drop。

**未说明但会决定成败的条件（需实测）**：
- 与提示词缓存的关系：静态前缀本可被缓存，缓存命中价格远低于首次输入；把前缀换成图片后缓存是否还生效、图片是否每轮重传，直接决定 9 倍差距能否落到账单上。
- 图片清晰度/分辨率与模型识别质量的关系：渲染糊了会不会让工具 schema 读错。
- 不同模型对图片的 token 计价与上限（单图 token 上限、多图叠加）。
- 长会话下每轮都带图，是否反而增加延迟。
- 隐私面：图片在本地生成，内容仍会随请求上传，与纯文本无本质差别，但需确认代理不额外留存。

**适用条件**：静态前缀大（长 CLAUDE.md、多个 MCP 工具 schema）、会话轮数多、任务可容忍少量工具调用错误。短会话、一次性问答不适用。

## 怎么试、怎么验证

**最小试用（成本控制在几美元内）**：
1. 选一个真实小任务（如修一个 bug、加一个小功能），固定仓库快照与提示词。
2. 基线：原样 Claude Code 跑一次，记录账单与指标。
3. 实验：`pxpipe warp -- claude` 跑同一任务，同模型、同轮数上限。
4. 若第 2、3 步成本接近或实验更贵，直接停，不必再扩大样本。

**看哪些指标**：
- 主指标：单会话总花费（实验相对基线的降幅；原文单例为 -86%，可把“降幅 >50%”设为值得继续的门槛）。
- 主指标：输入 token 数（原文称约 1/9）。
- 防退化指标：工具调用失败/重试次数、需要人工纠偏的次数，不得高于基线。
- 结果指标：任务是否完成、测试是否通过、最终 diff 是否被接受（人工或 CI）。
- 辅助：每轮延迟、代理自身日志是否报错。

**判定规则**：成本明显下降且质量不降 → 小范围默认化（写成 shell 别名或包装脚本，只在长会话任务用）；成本降但错误率上升 → 只在只读/低风险任务用，或放弃；成本没降（疑似被缓存或图片重传抵消）→ 放弃，不写进手册。

**注意事项**：所有对照必须同任务、同模型、同轮数；单例不足以定论，至少 2–3 个不同规模的任务再下结论。
