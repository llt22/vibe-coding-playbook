## 是什么

SparseRead 是一个面向 AI Agent 的“阅读控制机制”设想：核心主张是不采用“先把资料读进上下文再压缩”的做法，而是在外部内容进入上下文之前，就先判断哪些内容值得读进去。作者把它定位为 Agent Harness 里的一层机制，而非单纯多接一个搜索工具。

原文场景：让 Claude Code 排查一个几百文件、几十万行的项目里的 Bug，真正有用的可能只有几十行，但 Agent 为找到这几十行会先烧掉几万到几十万 Token，越跑越慢越贵。

## 具体做法（编号步骤）

原文只给了三条原则性动作，没有给出任何可复制的命令、配置、提示词或接入方式，需要自行落地：

1. **先明确阅读意图**
   - 做法：读之前先让 Agent 说清“当前任务需要什么信息、哪些证据已找到、哪些还缺失”，不要不加区分地读取所有内容。
   - 前提：任务已被拆成可表述的信息需求；否则“意图”无从写起。
2. **按需定位证据**
   - 做法：针对代码、长文档、表格等不同资料，采用各自的搜索、定位、局部读取方式。
   - 原文举例：排查登录 Bug 时，优先定位相关代码和报错日志，而不是先把整个仓库读一遍。
   - 前提：手上有可用的搜索/定位工具（如 grep、符号检索、按页/按表读取）。
3. **控制阅读预算**
   - 做法：在外部内容进入上下文之前就限制读取量；若现有信息不足，可以扩大搜索范围，必要时退回完整读取。
   - 前提：需要能设定并按任务调整读取上限（文件数、Token 数、范围），同时保留“兜底全文读”这个退路。
