## 是什么

Ravenseat 是一个面向 Claude Code 的开源、本地优先的多 Agent 开发调度器，针对的问题是：同时开多个 Agent 写代码后，人还得自己盯进度、查冲突、做验收。

按推文正文，它宣称提供六项能力：

1. 并行开发：自动分配任务，每个 Agent 使用独立 Git worktree
2. 独立验收：Agent 不能自己宣布测试通过，由调度器验证实际提交的代码
3. 失败恢复：测试失败后启动新 Agent 尝试修复
4. 断点续跑：任务、计划、决策保存在文件中，压缩上下文也不丢
5. 冲突管理：提前检测文件冲突，统一控制合并
6. 人工审批：需人决策的任务单独排队，不阻塞其他任务

## 具体做法（编号步骤；可直接复制的命令、配置、提示词原样放进代码块；写清每步的前提）

原文未给出任何命令、配置、提示词或操作流程，无法直接照抄。以下是**按原文功能描述自行搭建的最小复现路径**，属于推断，不是原文内容；实际使用时请以仓库 README 为准。

前提：本机已装 git 与 Claude Code，且有一个能跑自动化测试的代码仓库（有 `npm test` / `pytest` / `make test` 之类可非交互执行的命令）。

1. **先只做隔离**：每个并行任务单独开一个 worktree，一个 Agent 只在一个目录里干活，从根上消除同目录写冲突。
   ```bash
   git worktree add ../wt-task-a -b task/a
   git worktree add ../wt-task-b -b task/b
   ```
   每个 worktree 目录分别起一个 Claude Code 会话。

2. **验收外置**：Agent 只负责改代码并提交，**不允许自行判断通过**。由你（或调度器）在该 worktree 里跑真实测试，以退出码为准：
   ```bash
   cd ../wt-task-a && <你的测试命令>; echo "exit=$?"
   ```
   这是原文最核心的一条主张（“必须有真实测试结果”），也是唯一可以不经工具、纯手工立即落实的一条。

3. **失败重开而非追问原 Agent**：测试失败时，新开一个 Agent 会话，把失败输出原样贴进去让它修。原文称调度器会自动这么做；手工版就是“失败日志 → 新会话”。

4. **状态落盘**：在仓库里维护一个任务/决策文件（原文只说“保存在文件中”，未给文件名与格式），至少记录：任务描述、当前状态、已做的关键决策、失败过几次及原因。上下文被压缩或会话重开后，从这个文件恢复，而不是靠回忆。

5. **合并前查重叠**：在合并两个分支前，先看两边改了哪些文件，重叠就串行处理。
   ```bash
   git diff --name-only main...task/a
   git diff --name-only main...task/b
   ```

6. **人工审批单独排队**：把“必须由人拍板”的任务（改公共接口、动配置、删数据）标出来放进一个待办列表，其余任务继续跑，不让它们互相阻塞。
