最小试用方式：

1. 选一条 staging 或临时环境中的真实迁移，最好包含较大表、可能加索引或改表结构的操作，但不要直接用生产关键迁移。
2. 用同一模型、同一迁移任务，分别跑“普通 Claude Code”和“安装 `database-architect` 后的 Claude Code”。
3. 记录 agent 是否提前指出锁风险、破坏性变更、滚动部署问题；是否在临时数据库完成试跑；是否给出可执行的迁移步骤。
4. 由人工按事先写好的评分表复核，而不是沿用原文未定义的 10 分制。

判断改善的指标：

- 是否发现普通流程漏掉的真实锁风险或破坏性变更；
- 临时库试跑是否通过，是否暴露出迁移失败或数据风险；
- 人工复核评分是否更高，且没有引入新的高风险 SQL；
- 迁移准备时间是否可接受，是否减少部署前返工；
- 在 staging 执行时是否出现额外锁等待、失败或需要回滚。

只有在至少一条真实迁移上出现“更早发现风险且人工复核认可”的结果，才值得扩大到更多迁移类型；否则应停留在小范围试验。
