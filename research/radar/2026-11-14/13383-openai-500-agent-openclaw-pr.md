## 怎么试、怎么验证

**最小试用方式**（在拿到原文后执行；当前只能算设计演练）：

1. 选**一个**常驻 Agent 任务作为试点，最好是“定期触发 + 有写操作”的，例如定时检查某个仓库并提 PR。
2. 把执行侧与触发/调度侧分开部署，执行侧默认无出网、无凭据读取权。
3. 出网改为白名单，逐个域名放行并记录被拒请求。
4. 把该任务需要的凭据放进 Broker 类服务，只给 Agent 短期、限定范围的令牌。
5. 接入第二模型对写操作做前置审查，同时定义一份“必须转人工”的动作清单。
6. 为 Agent 建独立身份，记录每次触发、每次工具调用、每次配置变更。
7. 先跑 2 周，与“无沙箱、无审查”的裸跑版本做对照。

**判断改善的指标**：

- 越权或被拒的网络与文件访问次数（以及是否被有效拦截而非静默失败）；
- 敏感凭据被 Agent 直接读取的次数（目标为 0）；
- 人工审批次数与平均等待时长（Auto-review 的目标是降低这个数，同时不增加事故）；
- 写操作被第二模型拦下的比例，以及其中被人工判定为“确实该拦”的比例（衡量审查模型是否有效，而非只统计拦截数量）；
- 事后可追溯率：随机抽取 N 次操作，能否从日志还原“谁触发、改了什么、谁批准”；
- 任务成功率与回滚次数（安全机制不能以明显牺牲产出为代价）。

以上指标为本次调研给出的验证框架，并非原文内容。
