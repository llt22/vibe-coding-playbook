## 是什么

一条 X 推文（@cabbitar，382 赞 / 50 转 / 13 回复），转述「某人用 Claude Code + OpenCV 把摄像头改造成 AI 目标跟踪设备并开源了工作流」。作者用 7 个 step 描述了整条链路：

1. 用一条命令把 OpenCV 封装成 MCP 工具，让编码 agent 能直接读帧、检测、跟踪；模型反编译摄像头，找出官方 App 用的隐藏视频流；
2. OpenCV 以 30fps 直拉该流；
3. 每帧做一个「廉价检查」（有没有东西动、够不够大值得关心），没新东西就不调昂贵模型；
4. 只有通过闸门才让大模型看这一帧并命名目标（“cat”“person with a red bag”），也可由人直接输入要跟什么；
5. OpenCV 逐帧锁定跟踪框，大模型每 2 秒复核一次「还是不是同一个目标」；
6. Mac 上有个指挥中心实时显示画面 + 跟踪框 + 置信度条 + 轨迹 + 日志；
7. 底层兜底：跟丢则大模型重扫全帧找回，断流则重连并保留原目标，每条轨迹存成带时间戳和坐标的 CSV，叠加框可直接给 OBS。

实质上这是一条「感知分层 + 按需调用」的成本控制工作流，而不是一篇教程。原文承诺「Clone his workflow below / read the guide」，但给出的材料里没有仓库链接、没有代码、没有 guide 正文。

## 对应的研究问题（对照上面五个问题逐条说明，只写有依据的）

1. **能力发现**：原文展示了两类「没想到交给 AI」的工作——(a) 让编码 agent 通过 MCP 获得本地计算机视觉能力，自己去读帧、检测、跟踪；(b) 让模型去反编译设备、侦察出官方 App 使用的隐藏视频流。两者都是把「原本要人写代码/抓包」的活直接派给 agent。
2. **任务匹配**：给出了明确的分工原则——高频、低语义的「有没有变化」交给本地 OpenCV（零模型成本、30fps 全帧覆盖）；低频、高语义的「这是什么/还是不是它」交给大模型（按需触发 + 每 2 秒复核）。即：便宜模型/无模型做筛，贵模型做判断。
3. **条件供给**：(a) 工具与权限——必须先把 OpenCV 挂成 MCP 工具（第 1 步命令），agent 才有「手」；(b) 输入信息——人可以直接用自然语言指定要跟踪什么（“person with a red bag”）；(c) 反馈——置信度条、轨迹路径、日志面板构成人对系统的观测面；(d) 前提条件——设备网络可达、在授权范围内允许反编译。
4. **主动推进**：这是原文最强的一块，三种触发方式都有：**帧级状态触发**（每帧廉价检查，有变化才升级）、**时间触发**（每 2 秒周期性复核）、**异常事件触发**（丢目标→重扫，断流→重连并保持目标）。加上 CSV 持续落盘，构成可无人值守连续运行的闭环。

## 怎么试、怎么验证

**最小试用（建议 1 天内做出雏形，不碰真摄像头）**

1. 先只用本地录好的视频文件，不做 RTSP 拉流、不做反编译，把这步风险摘掉。
2. 跑通第 1 步命令，确认 MCP server 起来了、agent 能看到「读帧/检测」类工具：
   ```bash
   claude mcp add opencv -- uvx opencv-mcp-server
   ```
   若包不可用，退化为自己写 3 个本地脚本（取帧 / 运动检测 / 裁剪保存），让 agent 通过 shell 调用，效果等价。
3. 实现闸门：帧差或背景减除 + 面积阈值，把「有事件」的帧裁出来落盘。
4. 只对落盘的帧调用一次大模型做命名，人工指定目标描述（如“穿红衣服的人”）。
5. 加一个固定周期复核（对应原文的 2 秒）+ 丢目标重扫的分支。
6. 全流程记录：总帧数、触发帧数、模型调用次数、每次调用耗时、跟踪中断次数。

**判断有没有改善的指标（原文没给，自己定基线，用「关掉闸门、每帧都调模型」作为对照组）**

- **成本侧**：模型调用次数下降比例（应接近「触发帧数 / 总帧数」）、单小时处理成本；
- **质量侧**：目标命中率、误报率（把空景判成目标）、ID 切换次数、丢目标后的恢复耗时（原文声称靠重扫找回，这是最该被打脸的假设）；
- **时效侧**：从事件发生到面板出框的端到端延迟，是否满足你的场景；
- **稳定性**：连续跑 2 小时，断流重连是否真的保住了原目标。

只要「调用次数大幅下降 且 命中率下降在可接受范围」，这套分层结构就值得纳入手册；若恢复耗时或 ID 切换明显变差，则说明 2 秒复核的周期对你的场景太稀，需要调参或改回逐帧低成本跟踪 + 更长周期语义校验。
