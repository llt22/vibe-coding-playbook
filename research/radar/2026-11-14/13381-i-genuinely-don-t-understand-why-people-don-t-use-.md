## 是什么

一条推文提出的个人知识库工作流：不再把 AI 当问答机，而是把它当“记忆体”——所有读过的文章、论文、帖子、播客都剪进一个本地文件夹，由 Claude Code 负责读原文、写笔记、把新笔记与已有内容建立链接、归档进一个会随内容增长的 wiki；之后所有提问都对这个库发问，并每周让它主动排查知识库内部的矛盾。

它的核心不是某个工具，而是分工：人只负责“把原料丢进 raw”，结构化、写摘要、建链接、归档这些维护动作交给 agent，人来消费 outputs。原文明确说这是为了消灭三件事：打标签、分类、死笔记（no tagging / no sorting / no dead notes）。

## 具体做法（编号步骤；可直接复制的命令、配置、提示词原样放进代码块；写清每步的前提）

> 前提：原文未给出安装与权限细节。按原文可推知的最小前提是——本地可安装 Obsidian；Claude Code 能在本地某个文件夹内读写文件；浏览器装有 Obsidian Web Clipper（原文点名该工具）。

1. **建库**：下载 Obsidian，新建一个 vault（一个普通本地文件夹即可）。
2. **建三个顶层目录**，角色固定：
   - `raw/`：原始素材，只进不改。
   - `wiki/`：agent 自己写的笔记与归档。
   - `outputs/`：回答、产出物落地的地方。
3. **在库根目录放一个 `CLAUDE.md`**，用途按原文是“告诉 Claude 这个 wiki 怎么运转”（how to run the wiki）。
   - 注意：原文**没有给出 CLAUDE.md 的内容**，只给了它的位置和职责。这一步必须自己补写，至少要说清：raw 只读、wiki 由 agent 维护、每条新素材要做摘要 + 与既有笔记建立链接 + 归档、输出写到 outputs。
4. **采集**：用 Obsidian Web Clipper 把网页文章剪进 `raw/`。
5. **入库**：对 Claude Code 下达指令，原文给出的原话是：
   ```
   ingest the new sources
   ```
   即让它读 raw 里的新增素材、写笔记、链接到此前保存的内容、归档进 wiki。
6. **检索**：对着整个库提问，原文描述是“Ask it anything about everything you saved”。
7. **每周质检**：每周让它排查一次库内矛盾。原文原话是：
   ```
   once a week let it hunt for contradictions
   ```
   即让 agent 找出不同笔记之间互相冲突的结论，交给人判断。

原文把总成本描述为“五分钟”，但这只是搭空壳的时间，不含写 CLAUDE.md 规则和调提示词的时间——这部分原文没写。

## 怎么试、怎么验证

**最小试用（建议两周）**

1. 建一个库，只放 `raw/`、`wiki/`、`outputs/` 三个目录和一个 `CLAUDE.md`；如果不想装 Obsidian，直接用普通文件夹 + 剪藏工具替代。
2. 预埋一批“已知答案”的原料：选 15–20 篇你这几周真实读过、且一个月后你确实想再找回来的文章剪进 raw（其中故意放 2–3 篇观点互相冲突的同主题文章，用于测矛盾排查）。
3. 写好 CLAUDE.md 后跑一次 `ingest the new sources`，人工检查 wiki 里生成了什么。
4. 每天新增 1–2 篇，重复 ingest，观察一周后 wiki 的结构是否开始自我一致。
5. 第二周做一次检索测试和一次 `hunt for contradictions`。

**判断有没有改善的指标（都可自己记，不需要原文数据）**

- **找回速度**：对 10 个“我肯定读过但忘了在哪”的问题，从提问到拿到正确来源的耗时；与直接在浏览器历史/搜索里找的耗时对比。
- **命中率**：上述 10 个问题中，回答能指到 raw 里真实存在的那一篇的比例（防止 agent 编造）。
- **孤儿率**：wiki 中没有任何入链的笔记占比，以及每条新素材平均建立的有效链接数——直接检验“no dead notes”这个主张。
- **矛盾排查的精度**：预埋的 2–3 处冲突是否被找出；同时记录它报出的“矛盾”里，人工判定为真矛盾的比例（防误报刷屏）。
- **维护成本**：每周你花在修 CLAUDE.md、纠正分类、清理错误笔记上的分钟数；如果这个数持续高于你原先手动整理的时间，就说明这条工作流对你不成立。
- **留存检验**：两周后再问一次第一周的问题，看答案是否稳定、来源是否仍可追溯。
