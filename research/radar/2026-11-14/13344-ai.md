## 是什么
原文主张：让 AI 改代码的关键不在模型多会写，而在写入前有一道跨不过去的人工审批门。它用一个文件、三个工具（读文件、跑测试、写文件）搭一个能修真实小 bug 的 Agent：读和跑测试只读，写文件必须打印完整提案并停在确认提示，用户点头后才写入磁盘；路径围栏要写在代码里，测试作为验收标准。原文还给出一个购物车 add 方法的示范：加 2 本再加 3 本，期望 5 实际 3，初始测试一败三胜，修复后四胜；成本约 0.0098 美元。

## 具体做法
前提：原文只给流程与参数，没有给可直接复制的安装命令、工具 schema、主循环代码或审批门实现；以下按原文整理为可执行的设计步骤。所有版本号与模型名需先核实可用性，尤其是原文声称的 Python 3.12、Gemini SDK 3.0.0、测试框架 9.2.0、Gemini 3.8 Flash。

1. 开隔离环境并固定版本。把 API key 放进环境变量，不要写进代码。原文前提：Python 3.12、Gemini 软体开发套件 3.0.0 版、测试框架 9.2.0 版、模型 Gemini 3.8 Flash；主循环上限十二步。
2. 准备一个小型示范项目：购物车，加入方法写错——同一商品加第二次时数量被覆写而不是累加。测试写成：先加 2 本笔记本、再加 3 本，预期总数 5，购物车却报 3。
3. 先跑一次测试，确认初始状态是“一败三胜”，再往下做。原文把这步当作后续修复的基准。
4. 实现三个工具，职责分开：
   - 读文件：只读；路径围栏写在代码里，每条路径都要解析并检查是否落在项目文件夹内，落在外面直接拒绝；读取上限 8000 字（原文表述）。
   - 跑测试：只读；测试指令写死在程序里，模型可以叫它执行但改不了它；120 秒超时；只返回输出的尾部 3000 字（原文表述）。
   - 写文件：唯一会改变世界的工具；必须先打印完整提案，停在确认提示，用户亲自读完并点头后才写入。没有审批门就不要让模型碰写入。
5. 写主循环，上限十二步；任务写清楚：修来源文件、绝对不要改测试。原文任务约束可表述为：
```
任务：修來源檔案，絕對不要改測試。
```
6. 运行 Agent：它先跑测试看到失败，再读测试文件、读购物车程序文件，说出病因，然后打印完整提案并停在确认提示；此时磁盘上的文件一个字都还没变。
7. 人工审查提案后再确认写入。原文特别提醒：Agent 可能为了改一个方法里的三行而把整个文件重写一遍，存档文件还可能带着一行旧注解（说这里故意埋了一个错误），修完后这句话已不对；自动点头的人会把过期注解一起送进去。必须亲自读提案。
8. 写入后让 Agent 再跑一次测试，看到“四胜”才算通过。原文成本参考：7017 个输入代币 + 1202 个输出代币，约 0.0098 美元，不到一分钱。
9. 路径围栏不要只写在提示词里。原文明确说：跟模型说“请不要读项目以外的文件”只是建议，不是强制执行；围栏要由代码解析路径并拒绝越界。

## 对应的研究问题
- 能力发现：AI 可做“跑测试→读测试与源码→定位病因→提出补丁→写入后复跑测试”的小型修 bug 闭环；原文示范的是购物车 add 方法覆写数量的错误。
- 任务匹配：适合有可靠测试、改动范围小、可隔离运行的代码修复；模型负责诊断与提案，人负责审批写入；读/跑测试可自动，写文件必须人工审批。
- 条件供给：需要隔离环境、固定版本、API key 放环境变量、项目路径围栏、固定测试命令、读取上限、测试超时与输出截断、明确任务约束（只修来源、不改测试）、以及能暂停的审批提示。
- 主动推进：主循环可连续走到十二步，由“测试失败”触发诊断与提案；但原文的流程在写入前必须停下等人，不是无人值守的持续自动化。
- 效果验证：用测试作验收标准，修复前“一败三胜”、修复后“四胜”；同时用人工审查提案防止过度重写和过期注释；原文还记录 token 成本。

## 怎么试、怎么验证
最小试用：在一个临时仓库或容器里放一个小型项目和一个失败测试，按“读文件只读+跑测试只读+写文件必须人工审批+代码级路径围栏+主循环十二步”实现最小 Agent，只让它修一个失败测试对应的小 bug，禁止改测试文件。
验证指标：
- 测试结果：修复前失败/通过数，修复后目标测试是否通过、全量测试是否通过；测试文件 hash 是否保持不变。
- 变更范围：diff 行数、改动文件数；是否只改必要方法；是否出现整文件重写；是否带入过期注释。
- 安全：越界读取尝试是否被代码拒绝；未审批写入次数必须为 0；写入前是否确实停在确认提示。
- 效率与成本：主循环步数是否不超过 12；人工审批耗时；输入/输出 token 与费用是否在预算内。
- 人工审查：每次提案被人工发现的无关注释、无关改动、测试篡改意图数量。
判定改善：目标测试通过且全量测试通过、测试文件未被改、写入均经人工确认、diff 局限在必要范围、成本可接受；若出现整文件重写、试图改测试、越界读取或未审批写入，则视为失败并收紧围栏。
