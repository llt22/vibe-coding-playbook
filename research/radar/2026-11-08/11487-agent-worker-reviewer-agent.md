## 怎么试、怎么验证

**最小试用方式**：不必先读完全文再动手。挑一个你已经在跑的单 Agent 流程，构造 20–30 条有标准答案的任务，保持模型与单任务 Token 上限一致，做 A（单 Agent）/ B（Worker + Reviewer）两组对照，各跑一遍。Reviewer 提示词要求它只输出会导致任务失败的实质问题，禁止风格类点评。

**判断有没有改善的指标**：

- 主指标：整体任务通过率（同等预算下 B 是否高于 A）。
- 成本指标：每条任务的 Token 消耗、端到端耗时——若 B 通过率略高但 Token 翻倍，按“单位 Token 通过率”比较也不划算。
- 过程指标：失败后自愈率（首次失败但最终通过的比例），对应论文标题中的 recovery。
- 质量指标：人工抽查的幻觉/事实错误条数，验证“多一层把关兜住幻觉”这一假设本身是否成立。

**判定规则**：只有 B 组在同等 Token 预算下通过率明显提升、且幻觉率下降，才把 Reviewer 层写进流程；若只是通过率持平或上升但成本大幅上升，则改为单 Agent 内部自检一轮；若如原文所示通过率下降，直接放弃该层，并把这条对照实验作为团队架构评审的常规检查项。
