## 是什么

imozuru 是一个运行在 Claude Code 里的「芋づる式（顺藤摸瓜）」调研技能（skill），MIT 许可，README 自述 92 stars。它针对的默认行为是：只对 AI 说「调べて」，AI 通常搜索几条、读前几篇、返回摘要。imozuru 反过来要求 AI 按人类信息检索研究（Bates 的 berrypicking、Ellis 的探索行为模型、Kuhlthau 的探索过程）的做法：先确定领域的术语、核心人物、场所，再顺着引用、链接、作者一条条追，把命中原文（PDF、文章、YouTube 字幕）原样落到本地，**不做摘要**，只用「哪个文件第几行」指向证据，判断留给读原文的人。

流程（README 的 mermaid 图，中文转述）：写问句与要答的主张 → 建地图（术语·人·场）→ 追（引用·链接·作者）→ 落原文 → 判断「要答的主张是否都配上了原文」→ 未配齐就继续追，配齐或饱和则生成抜き書き（摘录）页面。

## 具体做法（编号步骤；可直接复制的命令、配置、提示词原样放进代码块；写清每步的前提）

1. **安装技能。前提：已有 Claude Code 环境、可联网。** 用 skills CLI：
   ```sh
   npx skills add MaryCache/imozuru
   ```
   手工安装则把仓库内 `skills/imozuru/` 复制到：
   ```
   ~/.claude/skills/imozuru/
   ```

2. **准备可选外部命令。前提：Python 3.10+；脚本只用标准库，下面几条命令「有则用」。** README 给出的对应关系是：

   | 命令 | 用在哪 | 没有时 |
   |---|---|---|
   | `pdftotext`（poppler 或 Xpdf） | PDF 转文字 | PDF 正文取不到，标 `FAIL` |
   | `pdftoppm`（poppler 或 Xpdf）+ `tesseract` | 无文字层的老 PDF 做 OCR | 该 PDF 标 `FAIL` |
   | `yt-dlp` | 下 YouTube 字幕 | 视频标 `FAIL` |
   | ax（github.com/yusukebe/ax） | HTML 转 markdown | 退回标准库转换，标题和表格形态保留较差 |

   追引用的 `chain.py` 用 OpenAlex API，**不需要 API key**。

3. **先写问句，并定下「答它需要的主张」3～6 条。前提：这是人来做的一步，也是停止判据的依据。** README 的规则：主张不能一味往软里写，至少 1 条要把委托里的用词原样放进去；一半以上要写成「不读原文就答不出来」的形式。这些写进 `map.md`。

4. **在 Claude Code 里下委托。前提：第 3 步的主张已定。** 可直接照用的提示词原样：
   ```
   芋づる式に調べて: 歌ってみたの MIX で、上手い人がどういう順番で処理しているか
   ```
   ```
   Gaussian Splatting ってよく聞くけど全然わからない。論文とか解説の流れを掘ってほしい
   ```

5. **建地图（2 条不同的探法并跑）。前提：有至少两种检索语言或入口（如英语 + 日语）。** 分别收集术语、人物、场所（论坛/会议/社群）、该领域定番资料，写进 `map.md`。README 的理由：AI 检索容易在方向尚未收敛时就固定一条路，之后不断自我强化而失败（引 Zhou 等 2026 HypoSearch），所以迷的时候用不同假设并跑两路检索，回来再比。

6. **追引用链并落原文。前提：地图里已有起点文献/作者/场所。** 动作：参考文献往「后」追、被引往「前」追、按作者追、按场所通读。论文领域和「只有个人博客/视频」的领域用同一套动作（顺文章里的链接、「参考了某某的文章」往下挖）。落下的原文放 `sources/`，并给每条原文打类型标记：
   - 〔論文〕过审/会议论文、arXiv 预印本
   - 〔本人〕本人亲历记录（自己试/做/测的过程）
   - 〔観察〕看别人作品后整理出的特征
   - 〔まとめ〕汇集或改写他人见解的文章
   - 〔公式〕工具或产品官方文档

   404、登录墙的条目，看内容后剔除。

7. **按证据决定停手。前提：第 3 步的主张清单在手。** 满足其一即停：
   - 全部「要答的主张」都配上了原文的位置（README 称此停止条件出自 Roh & Han 2026 的 HALT）；
   - 饱和：两条不同探法（如英/日）列出的资料中，**7 成以上**已经在地图里（借用 Kastner 2007 由两次独立探索的重叠估计总量的思路）。README 明确说 7 成是「边试边定的目安，依据还弱」。

8. **生成抜き書き页面，并做机器核对。前提：`sources/` 里已有原文。** 摘出的句子按主张排列成 HTML；`report.py` 会核对摘句是否在原文指定行的原位置逐字存在，只要有 1 个词被改写，就不生成页面直接停。想先单跑脚本：
   ```sh
   python3 skills/imozuru/scripts/report.py examples/demo
   ```
   结果落在 `~/research/<話題>/`：
   ```
   map.md         問い・要る主張・用語・人・場・原文の表・次の手がかり
   log.md         周ごとに、何を探して何が出たか・判断とその理由
   sources/       落とした原文
   extracts.json  抜き書き
   report.html    抜き書きのページ
   ```

9. **开启监视（可选）。前提：已经知道该领域的常去场所。** 命令形如：
   ```
   /imozuru watch react
   ```
   对挖出来的场所（Qiita、Zenn 的标签、note、YouTube、博客、arXiv）拉 RSS 新着，并列时附上原文开头一行。

10. **使用禁区（README 明写的注意点）。** 检索用的子代理会去搜 Web，问句内容会作为检索词外泄，涉及机密或个人数据的调研不要用；不用任何规避付费论文的手段，取不到就报「届かなかった」；落下的原文是本地阅读副本，不要再分发。

## 对应的研究问题（对照上面五个问题逐条说明，只写有依据的）

- **能力发现**：README 明确针对一个「没想到交给 AI」的任务形态——不是让 AI 检索+摘要，而是让 AI 做原文的定位与搬运（落文件、指到行），判断交给人。它也把「不摘要是刻意的」写进设计理由（过早收敛，Kuhlthau 1991）。
- **任务匹配**：给的是「Claude Code 技能 + 本地脚本 + 并行检索子代理」的组合：搜索角色可以按不同假设并跑两路；`chain.py` 用 OpenAlex 做引用链；`report.py` 做逐字核对。工具与人分工明确：agent 落原文和指位置，人读原文下判断。
- **条件供给**：需要（a）Python 3.10+ 与 Claude Code 的 `~/.claude/skills/` 目录；（b）可选二进制 `pdftotext`/`pdftoppm`+`tesseract`/`yt-dlp`/`ax`，否则对应格式直接 FAIL；（c）网络与 OpenAlex 访问（无需 key）；（d）最关键的输入是人先写出的「要答的主张 3～6 条」；（e）反馈回路写在 `log.md`（每轮找什么、出什么、判断与理由）。
- **主动推进**：`/imozuru watch <話題>` 按 RSS 持续盯已发现的场所（Qiita/Zenn 标签、note、YouTube、博客、arXiv）并附原文首行。README 未给出调度频率、触发条件的更多细节。
- **效果验证**：停手条件本身就是可判定的验收线——所有「要答的主张」是否都配上原文位置；两条独立探法的资料重合是否 ≥70%；抜き書き是否通过逐字核对（有改写即不产出）。

## 怎么试、怎么验证（最小试用方式和判断有没有改善的指标）

**最小试用（半天内可完成）**

1. 挑一个你确实不熟、但资料在网上公开的题目（最好是你能判断原文好坏的那种）。
2. 按上面的步骤 1 安装，步骤 2 至少装上 `pdftotext` 和 `yt-dlp`。
3. **先写基线**：直接用「/调べて：<题目>」让 AI 给一份摘要，记录它引到的原始资料数量和你能追溯到的链接。
4. 再定 3～6 条「要答的主张」，用 imozuru 跑一遍，产出落 `~/research/<話題>/`。
5. 对着 `map.md` 的原文表逐条读原文，检查 `report.html` 里的摘句是否真的支撑主张。
6. 另挑一个小脚本场景验证环境：
   ```sh
   python3 skills/imozuru/scripts/report.py examples/demo
   ```

**判断有没有改善的指标**

- **可达性**：拿到手的原文里，有多少篇是「直接问 AI 摘要」时拿不到、或只能看到二手转述的（对比第 3 步基线）。
- **对齐度**：3～6 条「要答的主张」中，有几条配上了可点的原文位置；不足 100% 时，缺的是哪几条、卡在付费墙还是搜索路径。
- **忠实度**：`report.py` 是否通过逐字核对（含改写就不产出的规则本身就是硬指标）；人工抽查若干条摘句与原文行号是否一致。
- **收敛速度**：两条独立探法（英/日）列出资料的重复率是否达到 7 成、用了多少轮；与基线相比，「能停下来」的时间点是否更早且理由可查（看 `log.md`）。
- **人的行为变化（最终判据）**：你是否真的去读了原文、并因此改变了原来的判断；如果只是拿到一堆文件仍靠 AI 摘要下结论，说明这个流程的收益没有兑现。
- 触发回退的条件：脚本大量 `FAIL`（PDF/视频取不到）、或摘句核对频繁不过、或两条探法重合长期低于 7 成，说明当前题目/环境不适配，先停。
