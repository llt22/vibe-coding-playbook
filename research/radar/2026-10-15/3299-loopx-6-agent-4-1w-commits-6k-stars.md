## 怎么试、怎么验证

**最小试用方式（基于现有材料能提出的最保守版本）：**

1. 先取得完整原文或 loopx 仓库，确认 agent 到底接管了哪几个环节、用什么触发、如何防止坏提交进入主干。在这一步之前不要照搬“凌晨和周末无休”的节奏。
2. 在自己的项目里选一条低风险链路（例如“提 issue → agent 改代码 → 自动跑测试 → 开 PR”）做小范围试验，仍然保留人工合并这一道闸。
3. 只在自动化验证覆盖足够（测试能在无人值守时判定对错）的模块上放开无人值守运行；否则先只在有人在线的时间段运行。
4. 记录每次 agent 触发的来源（定时 / 事件 / 状态变化）和终止原因，用于判断“主动推进”是否真的产生有效工作，而不是产生噪音提交。

**判断有没有改善的指标：**

- 有效提交占比：被合并且未被回滚的提交数 / 总提交数。单纯看 commit 总数会被高频小提交误导，必须看这个比值。
- 人工介入成本：每完成一个可交付变更，人需要花多少时间审查、修复和返工。
- 缺陷指标：回归缺陷数、回滚次数、CI 失败率随时间的变化。
- 结果指标：至少一个与用户价值相关的指标（例如功能上线周期、用户留存或任务完成率），而不只是 stars。
- 对照方式：同一项目在开启/关闭无人值守迭代的两段时间做对比，或在两个相似模块上做对照，避免把自然增长算成 agent 的功劳。
