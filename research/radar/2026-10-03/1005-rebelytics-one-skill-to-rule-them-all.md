## 是什么

task-observer 是一个「元技能」（meta-skill）：它本身不完成具体工作，而是在你的 Claude 会话中并行运行，观察你如何使用其它技能，产出结构化观察日志，并提出两类建议——新建技能候选、修改已有技能。作者称它是 Augmented Expertise 方法论的落地实现。

关键设计：它**不直接改动你已安装的技能**。流程是「会话中观察 → 写入观察日志 → 人工复核 → 生成 staged 更新 → 你安装后才生效」。作者也强调只装文件不等于激活。

## 具体做法（编号步骤；可直接复制的命令、配置、提示词原样放进代码块；写清每步的前提）

1. **取文件。** 下载最新 release 附带的 `.skill` 包，或把仓库下载为 ZIP（Code → Download ZIP）/ clone。前提：必须把 `SKILL.md`、`references/`、`scripts/` 三个部分放在一起；只装 `SKILL.md` 能跑但会降级，技能会提示缺了哪些文件。

2. **按平台安装。**

   - 命令行安装（Vercel 的 skills CLI，需要 Node.js）：
     ```
     npx skills add rebelytics/one-skill-to-rule-them-all --skill task-observer
     ```
     加 `-g` 可安装到你的所有项目。
   - Claude 应用（web、桌面、手机、Cowork）：在 Settings → Customize 上传 `.skill` 包（或把 `SKILL.md`、`references/`、`scripts/` 放进一个文件夹再打包上传）。
   - Claude Code：把文件夹放到 `.claude/skills/task-observer/`（项目级），或放到你的用户级技能目录，保留 `references/`、`scripts/` 子目录。
   - 其它系统：按平台要求保持目录结构不变，让 AI 引导你配置。

3. **激活（这一步最容易漏，只安装不够）。** 把 `references/environments.md` 里的激活指令加进你的 `CLAUDE.md`（或平台等价文件），或者安装 session-start hook。原文理由：仅靠 description 匹配会严重欠触发。

4. **在新会话里验证它真的会被调用。** 原文明确说：安装所在的那个会话无法证明它生效。要在**新会话**里确认技能在第一次工具调用**之前**就被调用。

5. **跑几轮真实工作，然后看日志目录。** 观察日志落在：
   ```
   [你的共享文件夹]/skill-observations/observation-log/
   ```
   一条观察一个小文件；建议的技能更新落在：
   ```
   [你的共享文件夹]/skill-updates/
   ```
   判断激活是否发生的硬性外部信号：几轮真实工作后 `skill-observations/observation-log/` **还不存在**，说明激活从未发生。

6. **每次会话结束问一句。** 原文给的提示词：
   ```
   Any observations logged?
   ```
   作者说这一问有时会让技能补出之前没记下来的改进点。作者自己的习惯是每次归档会话时都问一次。

7. **安排定期复核会话，应用所有未处理的观察。** 作者的排期是周一、周三、周五早上，并建议按自己的需要调整。规则：交互式复核里你逐条批准每个改动；定期复核只把「不需要你决策」的观察应用到 staged 副本；**在你安装更新包之前，任何改动都不会上线**。

8. **利用跨领域原则日志。** 不属于某个具体技能的观察会被记成 cross-cutting principles，放在单独的日志里；新建或更新任何技能时都会自动对照这些原则检查。用得越久，整个技能库的质量下限越高。

9. **平台差异要提前知道。** Cowork（含 Dispatch）和桌面版 Claude Code 是完整体验，观察日志写到文件系统、跨会话留存。Claude.ai web、桌面/手机 Claude Chat 没有文件系统访问，走「handoff doc 模式」：会话结束产出一份结构化交接文档，你另开一个会话用它去更新技能。

10. **不确定怎么配就先别装。** 原文建议：把仓库内容（技能、README、用户指南）直接喂给你用的 AI，让它按你的具体环境给出配置方案；即使平台不支持 skills，这套方法论也能套到 AI 能访问的其它知识库上。

## 对应的研究问题（对照上面五个问题逐条说明，只写有依据的）

**1. 能力发现：直接相关。** 观察器专门找「还没有技能覆盖的空白」：你手动做或在重复做的事，会被标为新建技能的候选，并帮你把它建出来。即使你还没有任何技能也能用——它会开始替你识别候选。这是把「AI 还能接手什么」变成持续自动发现的一种机制，不过粒度是「技能候选」，不是任务级建议。

**2. 任务匹配：部分相关。** 原文给了明确的平台匹配：Cowork、Dispatch、Claude.ai web、Claude 手机端、桌面版 Claude Code 是「测试并设计针对」的环境；无桌面版的 Claude Code 被用户确认可用；其它兼容 skills 的平台（ChatGPT、Gemini CLI、Cursor 等）列为「可能兼容但有前提」，因为技能内容假设了 Claude 架构（`<available_skills>`、skill-creator 引用）；社区另有人做了 Codex 版本。协作方式上它属于「机器提议 + 人复核」而非自动改技能。

**3. 条件供给：直接相关，也是原文最实的部分。** 需要提供：完整的文件结构（`SKILL.md` + `references/` + `scripts/`）；`CLAUDE.md` 中的激活指令或 session-start hook；文件系统访问（只有 Cowork / 桌面版 Claude Code 有完整体验，web/手机降级为交接文档模式）；一个作为日志落盘位置的共享文件夹；以及你定期做复核会话的时间。

**4. 主动推进：直接相关。** 它随每次工作会话自动运行（前提是激活指令保证真的触发）；支持定时复核会话，对无需你决策的观察自动应用到 staged 副本；新技能会自动对照 cross-cutting principles 检查。

**5. 效果验证：部分相关，但只到「技能是否真的在跑」这一层。** 原文给了明确的生效验证：在新会话确认技能在第一次工具调用前被调用；若几轮真实工作后 `skill-observations/observation-log/` 仍不存在，说明从未激活。改进效果本身没有定义指标，只有作者自述。

## 怎么试、怎么验证（最小试用方式和判断有没有改善的指标）

**最小试用方式：** 选一个你会连续用几天的 Claude Code 项目，按第 2 步的命令安装（或先只把 repo 内容喂给 AI，让它按你的环境给配置），按第 3 步在 `CLAUDE.md` 加激活指令，然后正常干活 3–5 个会话，中间照常结束会话，最后安排一次复核会话。

**验证（分两层）：**

1. 生效验证（硬性，先过这关）：新会话中技能在第一次工具调用前被调用；`skill-observations/observation-log/` 出现文件。任一不满足就是没激活，先解决激活，再谈效果。
2. 产出验证：观察条数、被接受并装入的技能改动数、新建技能候选数。
3. 改善验证（原文没给指标，需要自定并设基线）：先跑一段不装观察器的会话作基线，装上后比较——同类纠正是否仍在后续会话重复出现；原本手工重复做的事是否被新技能接管；同一个坑是否还在多个项目里被反复写进 project memory（按原文信号，重复出现即说明该沉淀成技能）。

**决策点：** 如果连续几个会话只产出零散、无法行动的观察，或者你的技能只有少数几个、直接编辑更快，就按作者给的边界退出或降级——不要为了这个元技能额外背一套日志和复核流程。
