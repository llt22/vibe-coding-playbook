2. **最小试用（取证成功后）**：不要复刻 2,200 Agent 的规模。在一个**自带测试套件**的小型迁移任务上（例如把一个数百行的 Python 模块重写为带类型标注的实现，或把一个脚本迁到另一种语言），用 3–5 个 Agent + 每 Agent 独立沙箱，跑一轮，观察：

   - 人工返工次数与耗时
   - Token 与沙箱成本折算成人民币

3. **判断改善的指标**：
   - 主指标：单位产出的总成本（Token 成本 + 人工返工工时 × 人力单价），需低于单人基线。

   - 过程指标：Agent 产出被自动判错淘汰的比例——这个比例越高，说明该任务越适合这种打法；若几乎不淘汰，说明验证闭环太弱，规模放大只会放大错误。
4. **放弃条件**：如果任务无法自动判对错，或人工返工量随 Agent 数量线性上升，则说明这套方法不适用，停止。
