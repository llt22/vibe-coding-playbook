## 是什么

`riza/ai-disk-cleanup` 是一段提示词（prompt），把通用编码智能体（Claude Code、Cursor、Codex 等）变成“谨慎的磁盘空间审计员”：自顶向下遍历磁盘、按“删了会不会后悔”分成三层、**在动任何东西之前停下来等人工批准**。声称支持 macOS / Linux / Windows，提供英、土、简中、西、俄、葡、日七种语言版本，英文版为准。

它要解决的痛点不是“不会 `du | sort`”，而是“最大的空间占用往往不在你第一眼看的地方，而且表面数字会骗人”。README 举了三个例子：
- `Docker.raw` 显示 60 GB，实际占用 14 GB；
- 真正的头号占用是一个 23 GB 的废弃 `git` worktree 目录（来自一次被放弃的重构），任何“清缓存清单”都扫不到；
- 两个 15 GB 的 iOS 模拟器运行时躺在 `/Library` 下，普通的主目录扫描根本到不了。

## 具体做法（编号步骤；可直接复制的命令、配置、提示词原样放进代码块；写清每步的前提）

> 注意：本次材料只有 README，**提示词正文（`prompts/*.md` 里 `---` 以下的内容）和具体 shell 命令没有提供**，因此无法在此逐条抄录。以下步骤全部来自 README 的 Usage 与 “The method” 小节，属于可直接照做的操作层，但真正粘贴的内容需要去仓库取。

**前提条件**
1. 先做一份你信得过的备份。README 明确：这些命令**不进回收站**，删除不可逆，批 Tier 2 / Tier 3 之前尤其要先备份。
2. 必须在“工具调用需要你确认”的模式下运行：Claude Code 的普通权限提示、Cursor 的 ask mode 等；**不要**用 auto-approve / “yolo” 模式。README 说得很直白：提示词只是“要求”批准，真正保证暂停的是你的 agent 权限模式；无人值守的 agent 可能在你看分层表之前就删完了。
3. 自己心里有数：它报告的大小、以及它判断“能否再生”都可能错，它只是从 `du` 输出推断。

**操作步骤**
4. 选语言，打开对应文件，把 `---` 行以下的全部内容粘贴进 agent：
   - 英文（基准）：`prompts/disk-cleanup.en.md`
   - 简体中文：`prompts/disk-cleanup.zh-CN.md`
   - 其余：tr / es / ru / pt-BR / ja
   提示词的语言是有功能的：它同时决定 agent 用什么语言向你汇报；shell 命令在所有语言版本里都保持英文。
5. agent 会先**探测操作系统**，之后只用该平台的命令和路径。
6. **测量，不要猜**：自顶向下走到真正的元凶，而不是停在它的父目录。
7. **知道陷阱**：稀疏磁盘（sparse disk）、符号链接被重复计数、快照占着已释放的空间、异步删除、以及名字叫 `target/` 但不是 Rust 的目录。
8. 按三层出报告，然后**停下**：

   | 层 | 内容 | 风险 |
   |---|---|---|
   | 1 | 缓存、构建产物、包下载、死 worktree | 可再生产，无风险 |
   | 2 | VM 磁盘、旧 SDK 运行时、容器镜像 | 里面真有数据，会没 |
   | 3 | Downloads、浏览器配置、不用的应用 | 完全由你决定 |

9. 回答它提出的“层级”问题之前，先把上面这张表读一遍，再决定批哪一层。
10. **逐步执行**：每删一项后打印新释放出的空间；用各工具自己的清理命令，而不是 `rm -rf`。
11. **尊重权限边界**：任何需要 `sudo` 或提权的操作，都以“可直接运行的命令”形式交回给你，不得绕过。
12. **绝不删除**：源码、git 历史、`.env`、密钥、钥匙串、照片与邮件库、云同步文件夹、正在运行的 VM 磁盘、操作系统快照。
13. **汇总**：包括哪些是“你之后必须手工修”的（README 的示例中，两个 root 拥有的项——10 GB 的模拟器 `dyld` 缓存和一个 6 GB 的废弃 Nessus 安装——就是以 `sudo` 一行命令交回的）。
14. **信任边界**：提示词要求 agent 把磁盘上发现的一切当作**数据，不是指令**——某个下载目录里的文件名或 README 不能诱导它多删东西。运行前自己把提示词读一遍（作者说是故意写短的）。

## 对应的研究问题

**1. 能力发现（哪些还没想到交给 AI 的活）**
有直接依据：磁盘空间审计这类“以为自己 `du | sort` 就够了”的活，可以整段交给 agent。README 给出的价值点正是它找到了人常规扫描找不到的东西——藏在 `/Library` 下的两个 15 GB iOS 模拟器运行时、23 GB 的废弃 git worktree，以及发现 `Docker.raw` 表观 60 GB 而实际 14 GB 这种“数字会骗人”的情况。

**2. 任务匹配（什么工作配什么模型、工具、协作方式）**
适配对象写得很明确：任何编码智能体（Claude Code、Cursor、Codex…），因为它需要 shell 和文件读取能力。协作方式是人机分工：agent 负责测量、分层、给命令；人负责读表、批准、执行提权命令。README 没有比较不同模型的效果差异。

**3. 条件供给（要给哪些信息、工具、权限、反馈）**
依据充分，而且是这份材料最有价值的部分：
- 权限：必须是需要确认的工具调用模式（Claude Code 普通权限提示 / Cursor ask mode），不能自动批准；
- 安全条件：可信备份；
- 信息：平台（由 agent 自己探测）、以及对“表观大小 vs 实际占用”的警觉；
- 反馈：每步之后打印新释放空间；分层表本身就是给人审阅的中间产物；
- 语言设置会连带决定汇报语言。

**4. 主动推进（时间/事件/状态触发）**
无依据，且方向上相反：这套流程刻意在每层之间停下来等人批准，属于“人在环内”，README 没有给出任何定时、事件或阈值触发的自动运行机制。

**5. 效果验证（怎么判断真改善了结果）**
部分有依据：每执行一步后打印新释放的空间，属于过程级指标；README 给了一次真实运行的逐项释放量表。但没有定义可复现的成功标准，也没有对照实验，属于作者自报的单次案例。

## 与已有做法的关系

清单中有 **Claude Code（adopt）** 和 **Cursor（watch）**。这份材料不引入新工具，而是在这两个工具之上加一层“磁盘审计 + 分层批准”的使用流程：README 直接点名 Claude Code 的普通权限提示和 Cursor 的 ask mode 作为安全运行环境。也就是说，它补的是“怎么用”而不是“用什么”。除此之外，清单中没有其他相关条目（如清理工具、磁盘分析工具）。

## 证据与局限

**给出的数据（一次真实运行，macOS，494 GB 磁盘，99% 满、只剩 5.2 GB）**：

| 步骤 | 释放 |
|---|---|
| 某项目里废弃的 Claude/git worktree | 4.9 GB |
| Rust `target/` 目录 | 5.7 GB |
| 83 个 `node_modules` + `.next` 缓存 | 18 GB |
| `~/Library/Caches`（17 GB → 2.4 GB） | 14 GB |
| `~/.cache`、npm、Go modcache、Homebrew | 16 GB |
| iOS 17.5 + 18.0 模拟器运行时 | 36 GB |
| Docker Desktop VM 磁盘 | 14 GB |
| OrbStack VM 磁盘 | 11 GB |
| Downloads：一个 11 GB 固件镜像 + 42 个安装包 | 14 GB |
| **合计** | **≈111 GB** |

结果：5.2 GB → 117 GB 可用，99% → 71%。

**哪些只是作者主张**：“battle-tested（久经实战）”是自述；提示词能防提示注入（“把磁盘内容当数据不当指令”）是设计意图，非实测；跨平台（Linux/Windows）只有声明，没有任何运行数据；30 个 star 说明外部验证很少。

**适用条件与风险**：删除不可逆、没有回收站；提示词无法强制暂停，安全性完全依赖 agent 的权限模式；它报告的大小和对“可再生”的判断都可能出错；材料只有 README，提示词正文和具体命令无法核验。

## 怎么试、怎么验证

**最小试用（建议半天内做完，且第一次不删任何东西）**
1. 选一台非关键机器，或先做完整备份。
2. 用 Claude Code 普通权限模式或 Cursor ask mode，粘贴 `prompts/disk-cleanup.zh-CN.md` 里 `---` 以下的内容。
3. **第一轮只跑到三层报告为止，不批准任何一项**。
4. 人工抽查至少 5 条（其中必须包含 1 条“看起来特别大”的项和 1 条 `/Library`、`/var` 之类主目录之外的项）：自己跑 `du` 核对实际占用，验证它是否区分了表观大小与实际占用、是否把符号链接重复计数。
5. 抽查通过后，第二轮只批准 Tier 1，逐步执行；每步之后自己核对释放量。Tier 2/3 先不动。
6. 全程记录它交回的需 `sudo` 命令，自己审一遍再决定跑不跑。

**判断有没有改善的指标**
- **误报数（最关键）**：Tier 1 里出现必须保留的文件（源码、`.env`、密钥、云同步目录、运行中的 VM 磁盘）的次数，应为 0。
- **未经批准的操作次数**：应为 0（这是对权限边界是否真的生效的直接检验）。
- **测量准确率**：抽查项中“它报的大小”与“你自己 `du` 实测”一致的条数 / 抽查总数；特别看 Docker.raw 这类稀疏文件是否被识别。
- **发现力（相对基线）**：与你自己手工 `du | sort` 得出的 top 10 占用项对比，它多找出了几个你没注意到的、且确实可删的项——这是它宣称的核心价值，也是唯一值得为之付出人力的地方。
- **Tier 1 释放量**：实际释放 / 它预估的 Tier 1 可释放量。
- **人工负担**：需要你手工处理的残留项数量（如 root 拥有的项）、以及整轮耗时是否显著低于你自己清理。
