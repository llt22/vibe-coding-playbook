## 怎么试、怎么验证（最小试用方式和判断有没有改善的指标）

**最小试用（前提：读完 README，确认有可用的安装与接入方式之后再做）：**

1. 选一个你自己熟悉、规模中等、你有明确修改任务的真实仓库（不要用玩具仓库，也不要一上来就上主仓）。
2. 先记录**基线**：不用任何索引，让 Claude Code 完成同一个修改任务，记录工具调用次数、读文件数、总 token、是否改对。
3. 再接入 Repowise 的索引，让 Claude Code 做**同一个任务**（同提示词、同仓库快照）。
4. 固定版本号（推文提到 v0.52–v0.56，说明变动频繁），把版本写进记录里，避免下次对比时环境已经变了。

**判断有没有改善的指标：**

- 定位成本：完成同一修改所需的文件读取次数 / grep 次数是否下降。
- 上下文成本：输入 token 总量是否下降（这是原文“别再瞎翻文件”最直接的对应指标）。
- 结果质量：修改是否正确、是否引入回归、是否改动了不该改的地方。
- 维护成本：代码变更后索引需要多久重建、是否需要手动触发——如果这一步代价高于省下的检索时间，就不值得。
- 稳定性：连续多个任务是否都能受益，还是只在某些任务上有用。

**升格条件：** 如果能抓到 Repowise 的 README 并得到可复制的安装/接入步骤，且上述对比中定位成本与上下文成本有可重复的下降而不牺牲正确率，本条目可以从 study 升为 try。
