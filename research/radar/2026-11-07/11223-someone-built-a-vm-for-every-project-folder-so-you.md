   - 前提：存在安全的密钥代理或注入通道；否则 agent 在 VM 内可能无法访问必要服务。
5. 让工具检测项目工具链，自动准备对应环境。

最小试用方式：

2. 按“每项目一个隔离环境、只挂载项目目录、网络白名单、密钥不落入执行环境”的原则搭建一次编码 agent 运行环境。由于原文没有给出 devvm 的具体命令，试用时应先阅读其仓库文档，不能仅凭推文操作。
3. 让同一个编码 agent 完成一组固定任务，例如安装依赖、运行测试、修复一个已知小 bug、执行构建。
4. 分别在宿主机直接运行和隔离 VM 中运行，记录差异。

判断是否改善的指标：

- 安全性：agent 是否还能访问项目目录之外的文件；是否能直接读取宿主机密钥；网络请求是否只命中允许列表。
- 可复现性：同一任务在 VM 中是否每次都能从干净环境构建成功。
- 任务完成率：固定任务的成功率是否下降；若下降，说明隔离过度或环境准备不足。
- 准备成本：首次创建 VM、安装工具链、配置网络白名单所需时间。
- 故障恢复：环境损坏后能否快速重建，而不影响宿主机。
