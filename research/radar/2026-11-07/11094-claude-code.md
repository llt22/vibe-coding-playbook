## 怎么试、怎么验证

由于原文没有可复制流程，只能试它的**度量与放权顺序**，而不是试它的具体配置。

最小试用方式（建议在一个仓库、一个 5 人以内小组、4–8 周窗口内做）：

1. **先建基线，再改流程**。在引入任何 AI 审查前，先连续记录 4 周的三个数：每周合并 PR 数、回滚率（自行固定口径，例如“被 revert 的 PR 数 ÷ 合并 PR 数”，并写进文档）、以及线上事件数。
2. **只改一个变量**：在 PR 上增加一轮 AI 审查，人类仍保留最终合并权，但把“逐行通读”改为“只读 AI 摘要 + 争议点 + 高风险改动”。原文的方向是压缩人的阅读量，这一步就是照它做的唯一切口。
3. **设定停手条件**：一旦回滚率或事件数相对基线上升超过预设阈值，就退回人工逐行审查，避免把度量变成事后解释。
4. **同时记录人类审查耗时**（每人每周在 review 上的小时数），这是原文明确要优化的目标量，否则无法判断“省下来的时间”是否真实存在。

判断有没有改善的指标（与原文口径对齐）：

- 主指标一：合并 PR 数（吞吐是否上升）；
- 主指标二：回滚率（质量是否守住，原文要求是不升高，其自身报告为下降 40%+）；
- 护栏指标：线上事件数、人类每周 review 小时数；
- 反指标：PR 平均规模（若吞吐上升只是因为 PR 被切得更碎，则不算真实改善，需同时报告）。

只有当“合并 PR 数上升”与“回滚率不升”同时成立，才可判定为改善；仅吞吐上升而回滚率上升，应视为把成本转移到了线上。
