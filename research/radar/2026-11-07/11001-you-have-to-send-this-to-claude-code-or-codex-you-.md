## 是什么

一条推文，给出一个可以直接粘进 Claude Code 或 Codex 的 `/goal` 提示词：让编码智能体遍历仓库里所有 open issue 和 TODO，用「自动驾驶分级」（L1 起）评估每一条在自己不介入的情况下能推进到哪一步，然后直接把该条目推进到那一步。

它的价值不在于某个新工具，而在于把「无人值守持续推进」整理成两件可复用的东西：

1. 一个针对仓库积压任务的一次性提示词入口（`/goal`）；
2. 一套「先给任务定自主度等级、再按等级执行」的授权框架，把「模型能自己做多少」变成为明确的、可先声明的分级。

- **任务匹配**：明确指向有仓库读写权限的编码智能体（Claude Code / Codex），任务是 issue 与 TODO 这类有文本载体、可枚举的积压工作；不涉及其他模型或非编码场景的说明。

- **传播数据不等于有效性**：约 97 点赞、7 次转发、21 条回复，只能说明有人关注，不能说明方法有效。
- **适用条件**：issue/TODO 描述较清晰、仓库有可跑测试、能用版本控制回滚的项目；对需要外部权限、涉及密钥、需求本身有歧义的任务，分级再细也不该放开自动执行。
- **风险**：模型自评等级容易偏乐观，且「做到哪一步」缺少客观判定标准，容易产生看似完成、实际不可用的产出。

## 怎么试、怎么验证

**最小试用（半天内可完成）：**

1. 选一个自己的中小型仓库，导出 open issue 与 TODO 清单存档，作为基线。
2. 第一轮只发分级版提示词（不执行），让人工对同一条目独立分一次级，比对差异。
3. 第二轮放开 L1–L2，限定分支、禁止推主干，观察实际产出。
4. 第三轮再试 L3（独立分支实现 + 跑通现有测试）。

**判断有没有改善的指标：**

- 分级与人工判断的一致率（衡量「自我评估」可不可信）；
- 无人值守期间产生的分支/提交中被人工接受的比例，以及被直接丢弃或大改的比例（返工率）；
- 现有测试通过率、事后发现的回归数量；
- 人工复核单条 issue 的平均耗时，与人工从零处理相比是否下降；
- 一夜间实际关闭/推进的 issue 数（注意区分「标记完成」与「真正可合并」）。

只要返工率不降或分级一致率偏低，就应退回「只分级不执行」，不要直接进入无人值守模式。
