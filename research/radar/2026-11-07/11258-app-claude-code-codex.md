## 是什么

这是一条面向独立开发者的推文，核心主张只有一句：在开始写下一个网站或 App 之前，先把一段提示词粘贴进 Claude Code 或 Codex，用“我要把它做得像 Linear”这类表述，把界面的风格、质感和交互基准固定下来，再让 AI 动手。

它属于**上下文供给技巧**：不改变模型本身，而是在任务开始前给模型一个可参照的产品作为参照目标，减少“AI 默认审美”和“通用 Bootstrap 风”带来的返工。

## 怎么试、怎么验证

**最小试用方式（30–60 分钟）**：
1. 选一个你近期要做的小页面（如设置页或列表页），准备两版需求描述，内容完全相同。
2. A 组：直接让 Claude Code 或 Codex 按描述实现。
3. B 组：先贴入“参照产品 + 参照维度 + 不参照部分 + 令牌先行”的风格固定提示（见上文第 4 步框架，需自行补全），再实现。
4. 两组产出后，由同一个人（最好不是你本人）在不知道分组的情况下评分。

**判断是否改善的指标**：
- **返工轮数**：从首版到“能接受”之间，你发出的修改指令条数——这是最直接的成本指标。
- **硬编码率**：产出代码中出现硬编码色值、字号、间距的次数；越低说明“令牌先行”的约束真的生效了。
- **风格一致性**：抽取 5 个界面元素，检查是否来自同一套令牌。
- **主观接近度**：盲评者判断“这更像参照产品还是更像通用模板”，二选一即可。

**判定标准**：若 B 组在返工轮数上明显更少，并且硬编码率更低，则该技巧值得固化成团队模板；若两组差异不大，说明瓶颈不在“缺少参照物”，需要另找供给方式（如直接提供设计令牌文件或截图）。
