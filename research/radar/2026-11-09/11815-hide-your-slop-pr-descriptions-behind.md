## 是什么

Simon Willison 描述了一个处理 AI 生成 PR 描述的具体做法：Claude Code、Codex 等编程智能体写出的 PR 描述往往准确、全面，包含问题、方案和验证步骤，但篇幅太长，读者容易产生“我不想读这么多”的反应。作者的做法是：PR 开头只保留一段经过人类编辑判断的高层说明，必要时加截图；把完整的代理生成说明折叠进 GitHub Markdown 支持的 `<details><summary>` 中；`summary` 里写模型名和 effort，例如“Claude Opus 5.5 Medium”。这样信息仍然保留，但评审可以先看人类筛选过的短摘要。

## 具体做法（编号步骤；可直接复制的命令、配置、提示词原样放进代码块；写清每步的前提）

1. 前提：PR 托管在 GitHub，PR 描述使用 GitHub Markdown；已经有一段由编程智能体生成的完整 PR 描述；你有编辑 PR 描述的权限。
2. 让代理生成完整描述，保留问题背景、解决方案和验证步骤。原文没有要求删除这些内容，而是要求把它们放到折叠区。
3. 人工写或挑选开头段落：用最短的文字说明这个 PR 是做什么的、为什么值得看。原文示例包括一句话问题描述和截图。作者强调这段开头代表“人类判断”，不一定是自己从头写的，也可以从代理输出中挑选。
4. 把完整代理描述放进 `<details><summary>`。`summary` 写模型名和 effort，让读者知道折叠内容来自什么代理配置。可直接使用如下结构：

```html
<details>
<summary>Claude Opus 5.5 Medium</summary>

## The hook
Plugins implement `register_agent_reference_types(datasette)` ...

</details>
```

5. 记住标签顺序：`summary` 是可点击的摘要行，`details` 包裹其余全部内容。作者建议口头记作“details-summary”，即先 details 后 summary。
6. 可选：把“人类开头 + 折叠完整代理说明”固化为团队 PR 模板。原文只展示个人用法，没有给出团队模板配置。
