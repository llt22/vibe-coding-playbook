## 怎么试、怎么验证（最小试用方式和判断有没有改善的指标）

**最小试用（半天到一天量级）：**

1. 挑一个你自己 agent 里「最可疑」的 skill（不是最重要的，而是最可能已冗余的），再挑 20–50 条有客观判据的历史任务组成固定任务集，任务集前后不许换。
2. 固定模型、提示词、预算上限，先关闭该 skill 跑一遍，再开启跑一遍。样本太小就每边重复 2–3 次，取均值并看波动范围。
3. 记录四个数：成功数、总成本（token/费用/耗时任一，全程同一口径）、修复率、单成功成本。
4. 判定：修复率提升不明显（差异落在重复跑的波动范围内）且单成功成本上升 → 移除该 skill；修复率明显提升且提升幅度能解释成本增量 → 保留；两个指标都变差 → 立即移除。
5. 移除后重跑一次全量，确认没有隐藏回归，然后把「模型升级后重跑本对比」写进例行流程。

**判断有没有改善的指标：**

- 主指标：**单成功成本**（总成本 / 成功数）——这是本线索的核心创新点，比单纯看修复率更能反映「技能是否成了负担」。
- 护栏指标：**修复率**不得显著下降；若下降，需换算成「多花的成本是否买到了相应的成功率」。
- 过程指标：同一任务集上的重复跑波动范围，用来区分真实差异与噪声——原文未提供，需自建基线。
- 长期指标：技能清单规模与整体单成功成本随模型升级的变化趋势，验证「定期复检」这件事本身是否有效。
