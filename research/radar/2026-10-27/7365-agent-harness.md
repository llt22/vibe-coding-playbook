## 怎么试、怎么验证（最小试用方式和判断有没有改善的指标）

**最小试用**（这是按上述评测约束设计的自检流程，非原文步骤）：

1. 固定一个已有的 Agent 流程作为基线，冻结其全部 prompt、工具与脚本。
2. 划分三份任务集：**反馈集**（Agent 可见、可反复针对它改）、**开发集**（用于挑选改动，可选）、**留出集**（冻结，任何人不得查看，也不得进入 Agent 上下文）。三者任务类型同分布但样本不重叠。
3. 让 Agent 或人工按同一节奏迭代 2 轮，每轮结束后只在反馈集/开发集上评分并保留改动。
4. 每一轮结束时，用同样的评分脚本各跑一次开发集与留出集，记录两个增量。
5. 全程记录每轮的具体改动内容，便于事后归因。

**判断指标**：

- 主指标：留出集增益（Δ_holdout）是否显著大于 0；
- 迁移比：Δ_holdout / Δ_dev。原文这一比例约为 0.33（2.8/8.4），可作为“迁移不佳”的参照量级；如果你的比值接近或低于这个水平，应优先怀疑改动只适配了可见任务。
- 轮间趋势：第二轮相对第一轮的留出增益是否衰减。若开发集继续涨而留出集停滞，即为过拟合信号。
- 稳定性：同一配置多次重复运行的留出分数方差；在小样本基准上，务必用多任务或多个随机种子确认 2~3 分级别的差异不是噪声。

**判定“确实改善”**：留出集增益在重复运行下稳定为正，且与开发集增益的差距不随时间扩大；只看开发集涨分不能算改善。
