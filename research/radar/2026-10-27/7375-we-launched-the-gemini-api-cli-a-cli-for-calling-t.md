最小试用（单点、可回退）：

1. 只在一个宿主机（建议已有的 Claude Code 环境）里装 CLI，不接其他宿主；
2. 选一个当前需要人工切工具才能完成的具体任务作为对照，例如“把一份 PDF 转成结构化摘要”或“生成一张示意图”；
3. 记录基线：人工用网页/GUI 完成该任务的耗时与返工次数；
4. 让宿主通过 shell 调用 CLI 完成同一任务，重复 5 次，记录同样指标。

判断是否改善的指标：

- **任务耗时**：端到端（含人工纠错）而非仅命令执行时间；
- **人工干预次数**：一次成功需要几次纠正智能体臆造的参数；
- **失败模式**：参数错误、鉴权失败、输出文件找不到的比例；
- **可复现性**：同一提示词重跑 5 次，结果格式是否稳定；
- **上下文成本**：宿主为学会用这个 CLI 需要多少 token 的说明/试错。

放弃条件：若人工干预次数高于基线，或智能体频繁臆造子命令、需要反复贴文档，说明该 CLI 的“自描述性”不足，此时应优先等待其补 help/文档，而不是继续打磨提示词。
