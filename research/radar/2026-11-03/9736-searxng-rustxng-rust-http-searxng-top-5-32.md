## 是什么

RustXNG 是一个用 Rust 编写的自托管元搜索（metasearch）加正文抽取引擎，作者主张它可以替代 SearXNG。按推文描述，它的关键特性是：

- HTTP 接口与 SearXNG 兼容（意味着既有 SearXNG 客户端/封装可能直接换 base URL 使用）；
- **一次请求同时返回排序后的结果列表和页面正文**，top 5 页面的正文合计约 32,000 字符；
- 移植了 SearXNG 的 226 种引擎类型、352 条设置项，默认启用 180 种；
- 每个引擎带超时、失败后退避停用、以及自动恢复。
- 仓库：GitHub `sahenjp/RustXNG`，许可证 AGPL-3.0-or-later。

对 agent 工作流的意义在于把「搜索 → 挑链接 → 抓取 → 抽正文 → 截断」这条多跳链路压成一次调用，减少工具调用次数和 HTML 解析环节。

## 怎么试、怎么验证（最小试用方式和判断有没有改善的指标）

**最小试用方式**（前提：仓库文档已补齐安装与接口说明）：

1. 在隔离环境按仓库文档部署一个实例，只保留少量引擎（从默认 180 个里裁到与现有 SearXNG 配置相同的引擎集合），保证与对照组条件可比。
2. 准备同一批固定查询（建议覆盖：事实型、多跳调研型、时效型各若干条），对 SearXNG 与 RustXNG 各跑一遍，top-k 固定为 5。
3. 记录每次请求的原始返回，保留正文，供后续人工与自动评测。
4. 在同一批查询上跑下游任务（例如让模型基于返回内容回答同一组问题），对比两种检索源下的答案质量。

**判断有没有改善的指标**：

- 调用次数：是否从「搜索 + N 次抓取」降为 1 次；
- 延迟：单次请求 P50 / P95，与「SearXNG + 自建抓取」链路的端到端延迟对比；
- 正文抽取成功率与截断比例：返回正文长度分布、空正文/报错页占比；
- 结果质量：top 5 与对照组的重合度、人工标注的相关性；
- 稳定性：引擎失败与自动恢复的日志条数，长跑（如数小时）后的可用率；
- 下游效果：同一组问题的答案正确率/引用准确率是否不降。

**判定标准**：若「1 次调用替代多次调用」且下游答案质量不下降、P95 延迟不劣于原链路，则可进入小范围试用；若正文抽取成功率低或引擎频繁进入退避停用，则维持 study，等仓库成熟后再评估。
