## 怎么试、怎么验证

最小试用方式（前提：先拿到仓库中的 prompt 原文）：

1. 只取其中“三类风险”的划分和那条 HARD BLOCK，翻译成自己智能体系统提示里的一小段禁止清单，不做整套移植。
2. 在一个低风险工作流上启用（例如仅允许读文件、写草稿目录，禁止外发与删除）。
3. 同时保留一份不带护栏的对照配置。

判断有没有改善的指标：

- 越权尝试次数：模型试图执行被禁止动作的次数（应由护栏拦截并记录）。
- 人工打断次数：同一任务下需要人介入的次数是否下降。
- 误伤率：护栏错误拦截正常操作的次数，这是软约束过多的典型副作用。
- 提示注入用例拦截率：用一组已知的注入样本测试，看是否被硬禁止挡住。

如果 HARD BLOCK 能稳定拦住越权而不明显抬高误伤率，说明这套分层值得进一步吸收；如果误伤频繁，说明 71 条软约束式的写法不适合直接搬到自己的场景。
