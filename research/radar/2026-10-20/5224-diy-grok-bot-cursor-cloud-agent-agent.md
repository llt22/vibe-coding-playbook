## 怎么试、怎么验证（最小试用方式和判断有没有改善的指标）
以下**是基于原文流程骨架设计的最小验证方案，不是原文内容**，仅用于把这条线索变成一个可判断的试验：

- **最小试用**：只取“规划—确认—执行—回报”四段。选一个真实的小任务（例如给内部工具加一个小功能），先让规划型 agent 输出一份计划，人工确认后，再交给另一个编码 agent 执行并运行测试，最后要求执行方回一条“改了什么、测了什么、结果如何”的消息。全程手动交接即可，不必先搭自动化。
- **对照**：同一任务用你当前的单 agent 做法跑一遍，比较两次结果。
- **观察指标**：
  1. 计划被人工修改的比例（衡量规划质量）；
  2. 执行方第一次交付就能通过测试的比例；
  3. 人工在两次交接之间的介入次数（衡量交接信息是否足够）；
  4. 从计划确认到测试通过的实际耗时；
  5. 交接过程中丢失或误解信息的次数。
- **判定**：如果第 3、5 项明显低于当前做法，并且第 2 项不下降，说明“规划/执行分离”在你的场景里成立，可以进一步自动化回报环节；否则说明瓶颈在于计划书写或上下文传递，而不是角色分工。
