## 是什么
这是一套给 AI agent 用的“文件化经验库”：把踩过的坑写成短经验卡，按现象触发，让 agent 在动手前定向读取，避免重复试错。它不是技能、记忆插件、知识库或 RAG，核心是“钩子常驻 + 索引消歧 + 卡片按需读”，并强调反面清单（试过且失败的路）而不是只写正向流程。

## 具体做法
1. **建目录（前提：每个需要它的工作区）**：在工作区建立 `procedures/`，放入 `INDEX.md`（只做易混现象消歧，不逐卡列）、`_模板.md`，建议再加 `_inbox.md`。README 指向仓库 `templates/INDEX.template.md`、`templates/card-template.md`；本次只拿到 README，未见模板文件本身，需以仓库实际文件为准。卡片骨架如下：
```markdown
# 分类-现象

> **触发**：<任务里会出现的现象>
> **验证**：<怎么确认这次真的成了——别拿「没报错」当成了>

## 首选
<可直接复制的那一条：命令 / 参数 / 路径。不带解释。>

## 被挡时
<首选被挡时的兜底，1~2 条，按方便程度排。>

## 别再来
| 弯路 | 为什么不通 |
| --- | --- |
| <真试过并失败的> | <报错原文 / 为什么不成立> |

## 注意
- <为什么会错 —— 这条最贵>
- <判据是什么>

证据：<会话 id / commit / 文件路径>
```
2. **挂钩子（前提：agent 会读 AGENTS.md / CLAUDE.md 或等价指令文件）**：把下面 4 条约定写进全局指令文件，让所有工作区共享机制；钩子约 0.6 KB，是整套机制唯一常驻内容。
```markdown
## 经验流程（procedures）

各工作区 `procedures/` 存踩过的坑，不常驻注入，按需读。

- **动手前**：任务撞上「网页抓不到正文 / 插件改了不生效」这类现象，先**搜**触发词，别凭记忆答：
  拿任务里的现象词搜 `procedures/*.md`（Windows：`Select-String -Path procedures\*.md -Pattern "<现象词>"`），
  命中哪张 read 哪张。卡少或搜不动时，列目录看文件名挑卡，一样算数。
- **踩到坑的当时**：只要不是「照着卡做就顺了」而是又试错了几轮 → 立刻往 `procedures/_inbox.md` 记一行。
  **别等收尾** —— 收尾要靠回忆，回忆不可靠。**记一行也算数。**
  **记 inbox 是记笔记、不是"动手改文件"** —— 就算被要求「只读 / 先别动手」，也照记不误。
- **收尾时（是检查，不是回忆）**：看 `_inbox.md` —— 够格的照 `_模板.md` 整理成卡
  （**文件名就是索引**：`分类-现象`），小意外留着下次。
- **不扫描、不复制**：不做启动式全库扫描；检索一律**定向** —— 拿现象词去搜，命中几张读几张。
```
3. **可选：从历史会话挖第一批素材（前提：使用 DeepSeek Harness 等兼容会话日志，且工具未因宿主升级失效）**：
```bash
node tools/scan-sessions.mjs calls <workspace> "<关键词正则>"
```
按“复发”筛选：同一现象在多个会话出现过才优先成卡。
4. **写第一批卡（前提：先有真实踩坑记录）**：从最近 2~3 个坑开始，不要一次写 13 张；每张 ≤2 KB，六段结构；删叙述，保留命令、参数、路径、报错原文、判据、证据。自查是否写成复盘报告。
5. **验证钩子是否生效（前提：能新开会话并观察工具调用）**：用 `tools/procedures-probe.mjs` 监控新会话，或人工观察；问 3~5 个分属不同卡片的现象，看是否出现 `<<< HIT` 或是否去读 `procedures/`。没有触发时先改钩子位置/措辞和触发词，不要急着加卡。
6. **踩坑当下记 inbox，收尾只检查**：不要指望收尾回忆；踩到坑时立刻在 `procedures/_inbox.md` 记一行“现象 + 一句话解法”。收尾时看 inbox，够格的（复发的 / 代价大的）按模板整理成卡，小意外留着。入库和出库都建议人审，不把写卡权限完全交给 agent。
7. **定期体检（前提：攒到十几张卡以后）**：
```bash
node tools/procedures-audit.mjs
```
该命令只出清单，不写、不删、不改卡；退出码 1 表示有 P0/P1，可接 CI。删卡/并卡要 agent 出清单、人审后才动。

## 对应的研究问题
- **能力发现**：把“agent 反复踩同一个坑”显性化为可管理的经验资产；经验卡记录“上次怎么趟过来”和“别再来”的反面清单，属于可交给 agent 的排障知识。依据：README 的 SPA 抓取案例和卡片结构。
- **任务匹配**：适合“有明确失败现象、会复发、需要定向排障”的任务；不适合把全部经验常驻注入，也不适合把读卡包成常驻 schema 的工具。依据：索引/卡分层、反模式 1/2、技能与经验卡对比表。
- **条件供给**：需要提供文件目录、agent 指令文件中的钩子、卡片模板、`_inbox.md`、真实报错/命令/路径/判据和会话证据；还需要人审入卡与删卡。依据：三零件、模板、反模式 7。
- **主动推进**：机制可由“任务现象词”触发动手前读卡；踩坑当时写 inbox 是更可靠的自发路径；定期体检和探针可做状态检查。依据：钩子 4 条约定、实测“首轮 5/5 命中”“inbox 自发发生”。注意收尾补卡两次实测未自发。
- **效果验证**：可用探针看是否触发、命中率、是否乱翻、读卡体积；用 audit 检查结构缺段/断链/体积/触发词覆盖/对象失效/结论偏旧；用复发率和重复试错次数判断是否减少重复踩坑。依据：第五节实测数据、第七节体检。

## 与已有做法的关系
清单中有 Claude Code（adopt）、Cursor（watch）、DeepSeek（try）、DeepSeek Harness（watch）。README 明确说机制通用、工具专用：Claude Code / Cursor / Codex / Gemini CLI 等可把 `templates/AGENTS-snippet.md` 写进其指令文件，工具层跳过；DeepSeek Harness 全套可用，`tools/` 为其编写；`procedures-audit.mjs` 只看文件、跨平台通用，`scan-sessions.mjs` / `procedures-probe.mjs` 依赖特定宿主日志格式。与记忆插件只在“记忆插件本身带经验沉淀/教训记录/错误归档”时冲突，其余可并行。

## 证据与局限
证据：README 给出端到端验证（新会话首轮查 procedures，5 题命中 5/5，对照题不命中不乱翻，读 6 张卡约 12 KB）；索引从 5.2 KB 降到约 0.8 KB；13 张卡从 77.8 KB 压到 26.6 KB（−65%）；38 张卡精简时一次移出 9 张（24%）；两次收尾补卡实测未自发，而踩坑当下记 inbox 自发发生。局限：这些多为作者自测，样本和统计口径有限；触发依赖 agent 自律，触发词匹配模糊；跨工作区不自动共享；工具层会随宿主升级失效；卡片会过期，淘汰需人判断；本次只拿到 README，未验证仓库模板和脚本实际可用性。适用条件：有重复性排障任务、agent 会读指令文件、团队愿意维护短卡并做人审。

## 怎么试、怎么验证
最小试用：选 1 个重复排障多的仓库，建 `procedures/`，写全局钩子，只写 2~3 张复发卡；用 3~5 个现象问题新开会话验证是否读卡。连续试运行一段时间，记录：重复试错轮次是否下降、同类坑复发次数是否下降、读卡命中率、无关读卡/乱翻次数、每张卡体积和维护耗时。判断改善：同一现象第二次出现时能直接命中首选或“别再来”，且没有把大量未使用卡塞进上下文；若完全不读卡，先查钩子和触发词，不要用全量注入掩盖。
