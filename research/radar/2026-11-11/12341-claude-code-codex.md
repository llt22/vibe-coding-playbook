## 怎么试、怎么验证

**最小试用方式**（注意提示词需自拟，原文未给出）：

1. 挑 1 个自己最熟悉的中小项目，确保你对它的结构和已知问题心里有数——这样才判断得出智能体说得对不对。
2. 明确一个产出目标（例如“列出这个项目里最可能出问题的三个地方，并给出文件路径”），把它写成固定提示词，接在 `Read this entire project and` 之后。
3. 在当前模型上跑一次，保存输出。
4. 换一个模型/新版本，提示词一字不改再跑一次。
5. 自己当评审，逐条标注每条结论是“对且我没注意到”/“对但我早知道”/“错”。

**判断有没有改善的指标**：

- **有效发现率**：两次输出中被你判为“对且我没注意到”的条目数，新模型是否更多。
- **错误率**：编造的文件名、函数名、不存在的依赖数量，越低越好。
- **定位精度**：给出的问题是否带准确定位（文件+行/函数），而不是泛泛而谈。
- **稳定性**：同一模型跑两次，结论是否大体一致；如果两次差异极大，说明这个提示词的输出不足以作为跨模型比较的基准。
- **耗时/成本**：一次通读消耗的 token 与时间，是否值得每周或每个模型版本做一次。

如果跑下来“有效发现率”接近 0、错误率偏高，说明截断后自拟的提示词没有承载原做法，应改用更具体的审视目标，而不是直接判定该做法无效。
