## 是什么
这是一个把 B 端设计系统、组件规范和交互法则打包成 AI 可执行规则的 GitHub 仓库，目标用户包括 Cursor、Claude Code、Windsurf、Codex 等编程智能体。README 声称它补的是“组件库有什么零件”和“页面怎么组装”之间缺失的设计决策约束，包含六大页面模板骨架、组件选型七大否定判据、视觉硬门禁、模块化参考文档、开箱即用模板和自动化检查脚本。当前材料只有 README，未包含 SKILL.md、.cursorrules、模板和脚本正文。

## 具体做法（编号步骤；可直接复制的命令、配置、提示词原样放进代码块；写清每步的前提）
1. 前提：目标任务应是 B 端企业后台页面，例如查询列表页、分步/分组表单页、单据/高级详情页、指标工作台与看板、设置页、异常与结果页。README 明确这些页面骨架是该 Skill 的主要适用对象。
2. Cursor 用户：将仓库中的 `.cursorrules` 复制到项目根目录，或在 `.cursor/rules/` 目录下添加指向 `SKILL.md` 的引用。前提：你能访问仓库中的这些文件；README 只给出路径，未在正文中展开 `.cursorrules` 内容。
3. Claude Code / Antigravity / Codex 用户：将本 Skill 链接或放置到你的提示词 / Skill 检索路径下，然后在与 AI 对话时输入：
   ```text
   请严格遵循 b-end-design-system 规范，为我生成一个客户合同管理列表页。
   ```
   前提：该 Skill 已能被对应工具检索到；README 没有给出更细的目录配置命令。
4. 任意大模型用户：直接粘贴 README 给出的通用 Prompt。前提：模型支持较长系统/用户提示词。原文提示词如下：
   ```markdown
   请你扮演一名资深高级 UI/UX 设计专家与前端工程架构师。
   在接下来的页面设计与前端代码生成中，你必须 100% 遵守以下设计系统硬门禁：
   1. 页面骨架：从查询列表、分组表单、高级详情、指标看板六大骨架中精准选型，杜绝组件乱堆；
   2. 浮层选型：查看详情与轻编辑首选侧边抽屉(Drawer)以保留背景上下文；高危删除才使用确认弹窗，且严禁开启点击遮罩静默关闭；
   3. 原子规范：一个操作区最多 1 个 Primary 按钮；Badge 严格坚守 80% 浅底深字黄金法则；数值金额列绝对右对齐；
   4. 视觉质感：使用 0.5px 精细微边框，内外容器遵循同心圆角公式 R_outer = R_inner + Padding，去除所有占位说明废话。
   ```
5. 生成后按仓库给出的检查资产复核：使用 `references/07-design-system-audit-checklist.md` 中的 15 项视觉与交互交付硬门禁，以及 `scripts/audit-design-rules.py` 自动化检查脚本。前提：已取得这些文件；README 未给出脚本运行命令、依赖和输出格式，需要打开脚本确认后再运行。
6. 按 README 的组件选型否定判据做人工自检：选项少于 5 个优先单选框平铺，选项过多用带搜索下拉；查看详情首选 Drawer，高危删除才用 ConfirmDialog；小于 1 秒不展示骨架屏，1—3 秒按钮 Spin，大于 10 秒给百分比和取消出口；关键报错不要藏在 Tooltip；原地改状态用 Button，跨路由跳文档用 Link，改动即生效用 Switch，随整表提交用 Checkbox。
7. 按视觉硬门禁复核：一个独立操作区最多 1 个 Primary 按钮；Badge 使用浅底深字；金额和数值列右对齐；边框使用 0.5px 精细微边框；内外容器圆角满足 `R_outer = R_inner + Padding`；弹窗不要机械垂直居中。
