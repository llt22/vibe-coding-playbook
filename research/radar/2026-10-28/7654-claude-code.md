## 怎么试、怎么验证

**最小试用（建议 2 周、单个仓库）**

1. 在仓库根写一份项目说明，只列三块：约定、目标、非目标；先用现有团队规范填，不追求完整。
2. 约定“开 PR 前必须由新会话 agent 审一遍”，把审查输出贴进 PR 描述，并记录 agent 提出的问题清单。
3. 打开 AI review（PR 自动评论）并设置 CI 为合并前必过。
4. 只做前后对比，不改变其他变量（人员、评审规则、发布节奏）。

**判断有没有改善的指标**

- PR 首次 CI 通过率（上升说明提交前自查变好）；
- AI review 提出的问题中被人工采纳的比例（衡量有效信号，避免噪音堆积）；
- 合并前返工轮次与从开 PR 到合并的时长（应下降或持平，若明显上升说明流程过重）；
- 人工 reviewer 的评审耗时（目标是减少其在低级问题上的投入）；
- 上线后回滚/事故次数（质量底线，不能变差）。

若“采纳比例低 + 合并时长上升 + 事故数无变化”，说明这条流程在当前团队只是增加了环节，应停用或缩到高风险 PR 上。
