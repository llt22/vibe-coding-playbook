- 任务选“结果可判”的：补测试、按规范重构一个函数、生成提交信息、做一次代码审查。

**判断指标**（建议同时看，不要只看“感觉更专业”）：
1. **一次通过率**：产物是否第一次就能跑通测试/通过 lint。
2. **人工纠正轮次**：需要你打断并纠正的次数。
3. **无关改动行数**：diff 里与任务无关的改动——这是区分“被规范约束住”与“只是话变多了”的关键指标。
4. **产出长度/自述文字占比**：如果 skill 版只是输出更长的解释而代码质量无变化，则不值得引入。
5. **总耗时**：含阅读与纠正的时间，不只是生成时间。
6. **覆盖面**：该 skill 声明的检查项，产物实际满足了几项（逐条打勾，而不是笼统评价）。

**结论口径**：跑 3–5 个同类任务后，若“纠正轮次”和“无关改动行数”稳定下降，说明这套 skill 确实把规范约束进了行为，可继续读第二个 skill；若只在措辞上更像规范文档，则停在 study，不进手册。
