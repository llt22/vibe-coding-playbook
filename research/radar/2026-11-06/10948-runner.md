## 怎么试、怎么验证

最小试用方式（不依赖 Runner，先验证“分工”这个思路本身是否值得）：
- 取 3 个同类小任务（加功能 + 写测试这类规模），每个任务都跑两遍：A 组由单个 Agent 完成实现与自查；B 组由实现 Agent 加一个独立审查 Agent 两段式完成。

判断是否改善的指标：
1. 缺陷发现数：B 组审查环节提出的有效问题条数（有效 = 修改后测试或行为确实变化）。若长期接近 0，说明分角色审查没有增益。
2. 一次通过率：改动首次跑通测试的比例。
3. 人工介入次数：两轮之间人工转述上下文、催办、纠错的次数。这是 Runner 类工具最该压缩的成本项，也是判断它是否值得引入的核心依据。
4. 总耗时与 token 成本相对 A 组的倍数。
5. 改动冲突次数：多 Agent 触碰同一文件时是否出现互相覆盖。

推进条件：只有在第 1 项指标为正、第 3 项人工介入确实构成主要瓶颈时，才值得去取 Runner 的仓库做真实接入测试；否则维持单 Agent 加人工审查即可。
