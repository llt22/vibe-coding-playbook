最小试用（以下为建议方案，不是原文内容）：

1. 选一个已有测试的小仓库，保留现有测试作为第一道门。
2. 写一个 pre-commit 钩子，把 `git diff --cached` 送给一个独立会话的模型，要求它只输出“阻断/放行 + 理由 + 指出的具体行”。
3. 第一周设为只提示、不阻断，人工复核每条告警。
4. 观察误报可接受后，再改为阻断，并保留临时绕过通道。

判断指标：

- 拦截项中经人工复核确属真问题的比例（精确率）
- 误报率与开发者绕过率（`--no-verify` 使用次数）
- 每次提交增加的审查耗时
- 启用前后逃逸到主干或 PR 的坏逻辑数量对比

若精确率低或绕过率高，说明该卡点尚未达到可阻断的成熟度，应停留在提示模式。
