## 是什么

原文指出多代理并行编码时的一个数据层问题：代码可以靠分支隔离，但多个代理若直接写同一份共享数据，会发生“丢失更新”。例子是 Claude Code 和 Codex 同时读取同一条记录，Codex 先保存，Claude Code 仍基于旧副本保存，结果覆盖掉 Codex 的修改，而且两个代理都不报错，后续查询也看不到 Codex 的改动。

作者推荐的思路是使用带 Git 式版本模型的数据层：Omnigraph。它被描述为一个开源图数据库，让每个代理在自己的分支上写数据，合并前检查是否基于最新 main；冲突时标记并让代理从最新 main 重试，每次合并形成可 diff、可回滚的 commit。原文称其用 Rust 编写，代理可通过 MCP、TypeScript SDK 或 CLI 连接。

1. 找出多代理会共同读写的共享数据。前提：存在多个代理并行处理同一批记录或图数据。
2. 禁止代理直接写 main。按原文描述，应设置 policy gate 阻止对 main 的直接写入。
3. 每个代理从最新 main 拉出自己的数据分支，并在该分支内读写。前提：数据层支持类似 Git 的分支隔离。
4. 代理完成修改后发起合并，而不是原地覆盖共享数据。
5. 合并时检查该分支是否基于最新 main。若代理开始时读的是旧版本，应标记冲突，而不是让旧副本覆盖新修改。
6. 冲突后让代理从最新 main 重试，再重新提交合并。
7. 将每次合并记录为 commit，用于 diff 和回滚。前提：数据层提供提交历史和回滚能力。
