## 怎么试、怎么验证

**最小试用方式**（在一周内、一个真实小任务上跑通，不引入任何新工具）：

1. 选一个 30–90 分钟量级的编码任务（例如修一个已有 bug 或加一个小功能），并选一个同类型的历史任务作为对照基线。
2. 开头只让 Claude Code 输出实现计划（改哪些文件、分几步、每步怎么验证），人工确认后再放行写码。
3. 在流程约束中要求：每完成一步，贴出该步的验证证据（测试命令与输出、运行结果或 diff），无证据不算完成。
4. 任务结束后，人工或让模型把本次最有价值的一条经验写成一行，追加到项目 CLAUDE.md。
5. 下一个任务开始时，检查新会话是否真的用上了这一行（观察模型是否引用或遵循）。

**判断有没有改善的指标**：

- 任务中途停滞或需要人说“继续”的次数（对照基线）。
- 首次交付即通过验证的比例（一次通过率）。
- 人工返工/返修的轮次与耗时。
- CLAUDE.md 新增条目在下一次任务中被实际复用的比例（复用率过低说明“每次追加一行”只是在制造噪声）。
- 计划阶段耗时占总耗时的比例（若计划时间超过实现时间且一次通过率没提升，说明流程过重）。

**判定门槛建议**：只有在上述指标中至少一到两项相对基线明显改善、且没有显著拉长总耗时时，才把这套习惯固化进手册；否则维持 study。
