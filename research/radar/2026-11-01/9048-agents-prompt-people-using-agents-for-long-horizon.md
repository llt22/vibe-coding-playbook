## 对应的研究问题

- **能力发现**：agent 承担公司大部分后台工作，能处理跨天（最长约十天）、间断推进、多交接的任务；能用代码查询与加工数据，产出财务计划类交付物；还会反过来主动提示人推进事项。
- **任务匹配**：按内部基准为任务路由不同前沿模型（Claude 为主，兼用 Anthropic/OpenAI）；高风险、涉及资金移动的任务不匹配给 agent，留给人类。
- **条件供给**：按客户的持久记忆（已发生/下一步/短期/长期/责任人）；运营知识转为 agent 上下文；沙箱加严格格式护栏支撑的数据访问；人类反馈与 agent traces。
- **主动推进**：记忆系统显式跟踪“未来几天要做什么”和“长期跟踪什么”，支撑有状态、跨天、多交接的持续推进；文中提到主动服务、发现隐藏费用的客户案例，但正文只有标题级信息。
- **效果验证**：用 traces 加人类反馈形成改进闭环，meta-agent 提 harness 修改建议，员工反馈转成 evals，内部基准用于选模型，合规与可审计性默认开启；原文未给任何量化改善指标。

## 怎么试、怎么验证

**最小试用方式**：挑一个长周期、多交接的流程（例如项目级或客户级的方案制定），先不纳入任何资金/高风险动作。做三件事：

1. 建一张最小记忆表，字段为：实体 ID、已发生事件、下一步、未来几天、长期跟踪、责任人——按第 2 步的原文口径设计。
2. 先用现成 harness（托管 agent 或 Claude Code 一类工具）跑流程，不急着自建。
3. 加一层确定性规则，禁止 agent 调用高风险工具；采集 trace 与人工反馈，人工记录每轮 agent 输出是否被采纳。

**判断有没有改善的指标**（原文未给指标，以下为建议）：交接遗漏次数；人提醒 agent 的次数与 agent 提醒人的次数之比；从启动到交付的时长与返工轮次；人工审批前 agent 输出的采纳率；prompt injection/越权测试的通过率。若要进一步验证第 6 步，可对比“有无 meta-agent 提改进建议”两种情况下 harness 修改的采纳率与效果变化。
