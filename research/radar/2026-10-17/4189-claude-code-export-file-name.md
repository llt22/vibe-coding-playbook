## 是什么

Claude Code 内置的 `/export` 命令：执行 `/export file_name` 会把当前整个会话历史导出成一个纯文本文件。推文给出的两个用途是：

1. 把这个文件当作另一个代理的上下文，接着往下干活；
2. 分析这个文件，把其中的做法沉淀成自定义技能（custom skills），改进自己的 Claude Code 工作流。

本质上是一条「把会话上下文变成可移植资产」的入口命令，价值不在导出动作本身，而在导出之后的复用。

## 怎么试、怎么验证

最小试用方式：

1. 正常完成一次有代表性的多轮工作（例如一次需要反复调试的任务），不要为了试用而试用。
2. 会话结束前执行 `/export file_name`，确认文件生成、内容完整、可读。
3. 开一个新会话（或另一个代理），把该文件作为上下文，让它接着做这件任务的下一步，全程**不额外补充背景说明**。
4. 另找一次同类任务作为对照，不导出、不投喂，直接在新会话里靠人工复述背景继续。

判断有没有改善的指标（都比较容易手工记）：

- 重建上下文所需的人工提示轮数：投喂文件后是否显著减少。
- 重复解释次数：新会话里还需要你重复说明几次「之前做过什么、为什么这么做」。
- 从「要开始下一步」到「模型真正在做正确的事」之间的时间。
- 导出内容的可用率：文件里有多少内容是无关噪声、需要人工删减（噪声太高说明导出不适合直接投喂，适合先做筛选）。
- 用途 B 的验证更弱一些，可统计：从导出文件里提取出的可复用步骤，是否在下一次同类任务中真的被用上。

如果减少的轮数和时间都不明显，说明这次会话本身的上下文价值不高，或者对方代理需要的是结构化摘要而不是原始转录，那就把 verdict 降回观察。
