**最小试用方式**

1. 选一条现成的多 Agent / Subagent 链路，规模控制在一周内可改完（一个主 Agent + 1~3 个专家 Subagent）。
2. 冻结其他变量：同一模型版本、同一套工具、同一份任务输入集，先跑出旧架构的基线。
3. 只做一处改动：把专家 Subagent 的职责合并进主 Agent 的指令/技能中，取消 Subagent 调用，形成单 Loop。
4. 用同一批任务（建议 20~50 条，含成功与失败案例）在新旧两版各跑一遍，记录指标。
5. 若结果是“变快但成功率下降”，说明该结论在你的场景不成立，保留原架构或只合并低风险职责。

**判断有没有改善的指标**

- 效率：端到端完成时间（对齐推文的“运行速度”）、模型调用次数与 token 消耗；
- 效果：任务成功率、输出需人工返工的比例、失败模式的类型与分布（是否出现原来被 Subagent 分工挡住的错误）；
- 稳定性：同一输入重复运行的结果一致性。

**判定标准**：只有在成功率与返工率不劣于基线、且完成时间或调用成本明显下降时，才算“改善”；若仅速度提升而质量下降，应判为未改善。
