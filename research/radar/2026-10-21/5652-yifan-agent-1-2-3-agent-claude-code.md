## 怎么试、怎么验证

**最小试用**：挑一类已知会卡住的任务（如跨多文件的 bug 定位，或 agent 互评式代码评审），跑两组对照：

- A 组（基线）：不设止损，让 agent 一直跑到自然结束，记录总耗时与结果。
- B 组（本文做法）：设 1–2 小时方向预算，到点无进展即终止，拆 3 个不同方向的子 agent 并行；评审类任务额外设“最大轮次 + 连续无新增问题即停”。

各跑 5–10 次同类任务，成本不高即可完成。

**判断改善的指标**：

1. 首次可验收产出的时间（B 组应显著更短）；
2. 任务总时长与总 token 成本（并行会抬高成本，需看是否被时长下降抵消）；
3. 卡死率：超过预算仍无产出的任务占比；
4. 3 路并行中有产出的分支数（若长期只有 0–1 路有效，说明方向切分方式有问题，而不是阈值有问题）；
5. 人工介入次数；
6. 评审类任务的收敛轮次与“来回互评不收敛”的发生率。

若 B 组在第 1、3、6 项上稳定优于 A 组且成本可接受，即可把阈值和时间盒写进手册；否则应先调整方向切分方式，再判断这条经验本身是否成立。
