## 怎么试、怎么验证（最小试用方式和判断有没有改善的指标）

**最小试用方式**：选 2 个已知根因、中等难度的 Bug（一个本地可复现、一个需跨模块对比），每个 Bug 跑两次——A 组不加约束直接让 Claude Code 修，B 组加载上面那段约束提示；同一模型、同一初始仓库状态，记录全过程。

**判断改善的指标**：

1. 从报错到修复的**交互轮次**与**总 Token 消耗**（B 组应更低）。
2. **改动扩散度**：修改的文件数与行数（B 组应更小）。
3. **回归情况**：修复后是否引入新的失败用例。
4. **根因陈述质量**：Agent 给出的根因是否被日志或复现结果直接支撑，而不是猜测。
5. **回退率**：被推翻的假设是否被干净回退（考察第 3 步是否真被执行）。

若 B 组在轮次和改动扩散度上明显更低、且根因陈述有证据支撑，才可考虑升级为可写入手册的条目；若差异不明显，则维持“思路研读”。
