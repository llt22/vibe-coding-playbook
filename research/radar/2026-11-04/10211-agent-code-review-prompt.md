## 具体做法（编号步骤；可直接复制的命令、配置、提示词原样放进代码块；写清每步的前提）
1. 前提：准备 issue 内容和本次代码改动 diff；为每次 review 新开会话或清空历史，确保 Agent 不被上一轮上下文影响。原文要求“独立审查者、不被上下文影响”，新会话是落实方式。
2. 把下面两条规则原样放进 prompt：
```
1. 对这个 issue 中的代码改动做一轮 review，你每次 review 应该都当成一个独立的审查者，不要被上下文所影响；
2. 安全相关的审查是必要的，但是不应该过度审查，不需要做航天级别的防护，一些非常边界 case（你自己来判断）可以不作为 block
```
3. 让 Agent 按上述规则审查，并把意见区分为“block”和“不作为 block”两类，便于人工复核。原文只规定“边界 case 可以不作为 block”，未给输出模板；这是试用时为复核补的最小格式。
4. 人工复核所有 block 意见和边界 case 判断，尤其是安全相关意见。前提是团队接受由 Agent 自判边界；安全关键系统不应只靠这两条规则放行。
