**最小试用（半天内可完成，单人即可）**

1. 先到 `mattpocock/skills` 仓库确认 `/grill-me` 是否存在、如何接入（原文未提供，必须自行核实；如果核实不到，本线索降级为纯思路）。
2. 取一个**真实但还没开工**的小需求（半天到两天量级），先用语音口述，完整说出你的初步想法。
3. 走一遍 `/grill-me`，把 agent 提出的追问逐条记录下来；重点记录“它问到了你原来没想到的点”有几条。
4. 根据追问补全需求，写成一份 spec 并保存到文件（原文这一步缺失，先用你自己团队现成的 spec 模板顶上）。
5. 按这份 spec 开工，记录执行过程中因需求不清而产生的返工。

**对照组**：同一位负责人的另一个同等量级需求，走原流程（不经过 agent 拷问）。

**判断有没有改善的指标**

- 构建前被提前发现的歧义或漏洞条数（只看新流程是否显著多于 0）；
- 从想法到 spec 定稿的耗时（是否没有被拖长太多，超过 30% 就应该重新考虑这条流程）；
- 开工后因“需求理解错”导致的返工次数或返工工时；
- spec 评审轮次（目标是减少，而不是增加）。

如果第 3 步的“问到了没想到的点”持续为 0，说明 `/grill-me` 在这类需求上没有增量，属于 prompt 或 skill 不匹配，而不是流程无效——应换需求类型再测一次，再下结论。
