## 是什么
`aidbg` 是面向 AI/程序驱动的 Windows x86/x64 命令行调试器。核心不是人类交互，而是让 agent 可靠驱动调试会话并解析结果：每条命令输出一行 JSON（JSONL），同一 exe 自动识别 x86/x64，支持批处理 `-c`、脚本 `--script` 和 MCP 服务器 `--mcp`，并声称默认固定基址与 IDA/Ghidra 静态地址逐字节一致；还列出反反调试、快照回退、IAT 重建和直接调试 DLL 等能力。

## 具体做法（编号步骤；可直接复制的命令、配置、提示词原样放进代码块；写清每步的前提）
1. **构建**：前提是 Windows 10+、安装 Visual Studio 2019/2022/18 的 MSVC 工具链，并在仓库根目录执行。README 称脚本会自动定位 VS 并编译内置 DLL 宿主。
```
build.bat Release
```
2. **跑一条最小批处理调试链**：前提是已生成 `aidbg.exe`，准备一个你有权调试的测试 exe；把 `tests\target.exe` 换成实际路径。`--json` 让每条命令输出一行 JSON，多个 `-c` 按顺序执行。
```
aidbg --json ^
  -c "file tests\target.exe" ^
  -c "run" ^
  -c "break accumulate" ^
  -c "continue" ^
  -c "regs" ^
  -c "stack 5"
```
`break accumulate` 是 README 示例；若目标没有该符号，应换成实际函数名或地址。
3. **把输出交给 agent 解析**：前提是 agent 能逐行读取 stdout。按 README 的契约，每条命令输出一行 JSON，字段稳定；不要让模型解析人类可读文本，直接按 JSONL 解析 `regs`、`stack` 等结果。
4. **需要连续流程或交互式工具调用时**：批处理用 `-c`，可编程脚本用 `--script`，MCP 客户端用 `--mcp` 启动 MCP 服务器。前提是已有 MCP 客户端；本材料只给出 `--mcp` 开关，没有给出完整启动参数和客户端配置，具体要查 `Manual.md`，不要照抄臆造的配置。
5. **调试 DLL**：README 的能力表给出 `file foo.dll [export]` 的内置宿主加载，并称会自动建立“加载 → DllMain”断点链。前提是目标 DLL 和导出参数正确；具体命令参数以 `Manual.md` 为准。
6. **反反调试与自查**：README 称可用 `hide` 配置档（兼容 `scylla_hide.ini`）和 `detect` 自查（al-khaser 清单）。前提是仅在授权环境使用；具体命令见 `Manual.md`，本材料未展开。
