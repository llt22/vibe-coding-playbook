# 做陌生领域调研时，让 AI 交原文和行号而不是摘要

> **未经实测**：本手册由 ai-work-radar 根据自动调研合并生成并持续修订，步骤尚未有人实际跑过。服务修订时基于自己保存的上一版重写，直接改这个文件会被覆盖；实测过的做法请写到 experiences/。
>
> 解决的问题：让 AI 在你完全不熟的领域做调研时，不把判断交给摘要，而是先定要答的主张，再顺引用链把原文落到本地并指到行，由你读原文下判断。
> 先试这一步：先为题目写下 3～6 条『要答的主张』（至少 1 条用委托原词、一半以上写成不读原文答不出的形式），再按下面的安装命令装 imozuru 跑一遍。
> 最近修订：2026-10-15

## 解决什么问题

默认让 AI「调べて」时，它通常搜索几条、读前几篇、返回摘要。你拿到的是二手转述，无法追溯，判断被 AI 代替，也难以知道它漏了什么。imozuru 反过来：先确定领域的术语、核心人物、场所，再顺着引用、链接、作者一条条追，把命中原文（PDF、文章、YouTube 字幕）原样落到本地，不做摘要，只用「哪个文件第几行」指向证据，判断留给读原文的人。依据是 README 的 mermaid 流程与设计理由（引 Kuhlthau 1991 的过早收敛）。

## 适用与不适用

**适用**

- 你不熟、但原始资料在 Web 上公开可取的题目（论文、个人博客、视频均可）。
- 你愿意自己读原文并据此改判断。
- 有 Claude Code 环境、可联网。
- 想给 AI 的调研画一条可判定的停止线：主张是否都配上原文位置。

**不适用**

- 涉密或个人数据课题：检索用子代理会把问句内容作为检索词外泄。
- 需要绕付费墙才能拿到的文献：README 明确不用规避手段，取不到就报「届かなかった」。
- 只想快速拿一份摘要的场景：imozuru 刻意不摘要（README 称早期摘要会过早收敛）。
- 环境无法装可选命令、且题目资料大量是 PDF/视频：对应格式会标 FAIL。

## 前置条件

- 已有 Claude Code 环境，可联网。
- Python 3.10+（脚本只用标准库）。
- 可选外部命令「有则用」，没有时对应格式失败：

  | 命令 | 用在哪 | 没有时 |
  |---|---|---|
  | `pdftotext`（poppler 或 Xpdf） | PDF 转文字 | PDF 正文取不到，标 `FAIL` |
  | `pdftoppm`（poppler 或 Xpdf）+ `tesseract` | 无文字层的老 PDF 做 OCR | 该 PDF 标 `FAIL` |
  | `yt-dlp` | 下 YouTube 字幕 | 视频标 `FAIL` |
  | ax（github.com/yusukebe/ax） | HTML 转 markdown | 退回标准库转换，标题和表格形态保留较差 |

- 追引用的 `chain.py` 用 OpenAlex API，不需要 API key。
- 最重要的输入：你先写出的「要答的主张」3～6 条。

## 操作步骤

1. **安装技能。前提：已有 Claude Code 环境、可联网。** 预期：技能装入 Claude Code 的 skills 目录。用 skills CLI：

   ```sh
   npx skills add MaryCache/imozuru
   ```

   手工安装则把仓库内 `skills/imozuru/` 复制到：

   ```
   ~/.claude/skills/imozuru/
   ```

2. **准备可选外部命令。前提：Python 3.10+；脚本只用标准库，按上表准备「有则用」的命令。** 若题目含 PDF/视频，至少装上 `pdftotext` 和 `yt-dlp`。预期：缺命令时只影响对应格式，会标 `FAIL`，不影响其他格式；`chain.py` 走 OpenAlex API，不需要 API key。

3. **先写问句，并定下「答它需要的主张」3～6 条。前提：这是人来做的一步，也是停止判据的依据。** 做法：主张不能一味往软里写，至少 1 条要把委托里的用词原样放进去；一半以上要写成「不读原文就答不出来」的形式。这些写进 `map.md`。预期：你手里有一份可逐条勾销的主张清单。

4. **在 Claude Code 里下委托。前提：第 3 步的主张已定。** 可直接照用的提示词原样：

   ```
   芋づる式に調べて: 歌ってみたの MIX で、上手い人がどういう順番で処理しているか
   ```

   ```
   Gaussian Splatting ってよく聞くけど全然わからない。論文とか解説の流れを掘ってほしい
   ```

   预期：Claude Code 按 imozuru 技能流程开始建图、追链、落原文。

5. **建地图（2 条不同的探法并跑）。前提：有至少两种检索语言或入口（如英语 + 日语）。** 动作：分别收集术语、人物、场所（论坛/会议/社群）、该领域定番资料，写进 `map.md`。理由（README 引 Zhou 等 2026 HypoSearch）：AI 检索容易在方向尚未收敛时就固定一条路，之后不断自我强化而失败；迷的时候用不同假设并跑两路检索，回来再比。预期：`map.md` 里有两路各自的地图，便于比对重合。

6. **追引用链并落原文。前提：地图里已有起点文献/作者/场所。** 动作：参考文献往「后」追、被引往「前」追、按作者追、按场所通读。论文领域和「只有个人博客/视频」的领域用同一套动作（顺文章里的链接、「参考了某某的文章」往下挖）。落下的原文放 `sources/`，并给每条原文打类型标记：

   - 〔論文〕过审/会议论文、arXiv 预印本
   - 〔本人〕本人亲历记录（自己试/做/测的过程）
   - 〔観察〕看别人作品后整理出的特征
   - 〔まとめ〕汇集或改写他人见解的文章
   - 〔公式〕工具或产品官方文档

   404、登录墙的条目，看内容后剔除。预期：`sources/` 里有可点回原文的文件，而不是摘要。

7. **按证据决定停手。前提：第 3 步的主张清单在手。** 满足其一即停：

   - 全部「要答的主张」都配上了原文的位置（README 称此停止条件出自 Roh & Han 2026 的 HALT）；
   - 饱和：两条不同探法（如英/日）列出的资料中，7 成以上已经在地图里（借用 Kastner 2007 由两次独立探索的重叠估计总量的思路）。README 明确说 7 成是「边试边定的目安，依据还弱」。

   预期：你能说出为什么现在可以停；如果没满足，继续追。

8. **生成抜き書き页面，并做机器核对。前提：`sources/` 里已有原文。** 动作：摘出的句子按主张排列成 HTML；`report.py` 会核对摘句是否在原文指定行的原位置逐字存在，只要有 1 个词被改写，就不生成页面直接停。想先单跑脚本：

   ```sh
   python3 skills/imozuru/scripts/report.py examples/demo
   ```

   结果落在 `~/research/<話題>/`：

   ```
   map.md         問い・要る主張・用語・人・場・原文の表・次の手がかり
   log.md         周ごとに、何を探して何が出たか・判断とその理由
   sources/       落とした原文
   extracts.json  抜き書き
   report.html    抜き書きのページ
   ```

   预期：`report.html` 里的摘句能对回原文行号；若有改写，不产出页面。

9. **开启监视（可选）。前提：已经知道该领域的常去场所。** 命令形如：

   ```
   /imozuru watch react
   ```

   动作：对挖出来的场所（Qiita、Zenn 的标签、note、YouTube、博客、arXiv）拉 RSS 新着，并列时附上原文开头一行。README 未给出调度频率、触发条件的更多细节。预期：后续该领域出新资料时，你能看到新着与首行，决定是否继续追。

10. **使用禁区。前提：任何调研开始前先判断题目是否涉密/含个人数据。** 规则：

    - 检索用的子代理会去搜 Web，问句内容会作为检索词外泄，涉及机密或个人数据的调研不要用；
    - 不用任何规避付费论文的手段，取不到就报「届かなかった」；
    - 落下的原文是本地阅读副本，不要再分发。

    预期：不把不该外泄的题目交给检索子代理，不绕付费墙，不再分发本地副本。

## 怎么判断变好了

可观察指标：

- **可达性**：拿到手的原文里，有多少篇是「直接问 AI 摘要」时拿不到、或只能看到二手转述的（先做基线：用「/调べて：<题目>」让 AI 给摘要，记录它引到的原始资料数量和你能追溯到的链接）。
- **对齐度**：3～6 条「要答的主张」中，有几条配上了可点的原文位置；不足 100% 时，缺的是哪几条、卡在付费墙还是搜索路径。
- **忠实度**：`report.py` 是否通过逐字核对（有改写就不产出的规则本身就是硬指标）；人工抽查若干条摘句与原文行号是否一致。
- **收敛速度**：两条独立探法（英/日）列出资料的重复率是否达到 7 成、用了多少轮；与基线相比，「能停下来」的时间点是否更早且理由可查（看 `log.md`）。
- **人的行为变化（最终判据）**：你是否真的去读了原文、并因此改变了原来的判断；如果只是拿到一堆文件仍靠 AI 摘要下结论，说明这个流程的收益没有兑现。

最小试用（半天内可完成）：

1. 挑一个你确实不熟、但资料在网上公开的题目（最好是你能判断原文好坏的那种）。
2. 按步骤 1 安装，步骤 2 至少装上 `pdftotext` 和 `yt-dlp`。
3. 先写基线：直接用「/调べて：<题目>」让 AI 给一份摘要，记录它引到的原始资料数量和你能追溯到的链接。
4. 再定 3～6 条「要答的主张」，用 imozuru 跑一遍，产出落 `~/research/<話題>/`。
5. 对着 `map.md` 的原文表逐条读原文，检查 `report.html` 里的摘句是否真的支撑主张。
6. 另挑一个小脚本场景验证环境：

   ```sh
   python3 skills/imozuru/scripts/report.py examples/demo
   ```

试多久：本材料未给具体时长；最小试用建议半天内完成一轮，之后按你的调研周期重复。触发回退的条件：脚本大量 `FAIL`（PDF/视频取不到）、或摘句核对频繁不过、或两条探法重合长期低于 7 成，说明当前题目/环境不适配，先停。

## 常见坑

- **没定「要答的主张」就开跑**：停止判据缺失，容易变成无止境搜或过早摘要。先写 3～6 条，再装、再跑。
- **期望 AI 给摘要**：imozuru 刻意不摘要，只落原文、指到行；判断要你读原文来做。
- **没装 `pdftotext`/`pdftoppm`+`tesseract`/`yt-dlp`**：对应 PDF/视频会标 `FAIL`，不是技能坏了，是缺命令。
- **把 7 成饱和阈值当硬标准**：README 自承这是「边试边定的目安，依据还弱」；它只是停止参考之一，不是精确判据。
- **用涉密/个人数据题目**：检索词会外泄；不用规避付费论文的手段；落下的原文不再分发。
- **只攒文件不读原文**：最终判据是你是否读了原文并改变判断；只拿文件仍靠 AI 摘要等于收益没兑现。
- **未验证脚本可用性就上真实题目**：本次材料只抓到 README，`examples/demo/` 与脚本本体未看到，脚本能否在本地跑通、报告能否生成无法证实；先用 `report.py examples/demo` 验证环境。
