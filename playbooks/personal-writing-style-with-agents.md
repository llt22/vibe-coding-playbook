## 解决什么问题

模型写出来的内容常常“一眼像 AI”，缺少个人写作风格。这篇手册给出一套可照做的流程：把个人历史文本导出为本地语料，用能遍历目录的编码 Agent 读取并提炼成一份可复用的风格规则文件，再在后续写作时作为固定上下文引用。注意：这套流程解决的是“上下文里没有你的风格样本”的问题，不是提升模型本身能力。

## 适用与不适用

适用：
- 有足够量且风格相对一致的个人历史文本（例如 X 发帖存档）。
- 希望模型起草的内容更接近自己平时的句式、标点、开场结尾、用词和语气。
- 愿意人工审阅规则文件，不接受模型直接代写。

不适用：
- 发帖量少，或历史帖风格混杂（多语言、多体裁、多账号）——提炼出的规则会失真。
- 没有任何验证意愿，只想“十分钟搞定”——原文的“10 分钟”只是作者主张，没有给出验证。
- 账号内容敏感，且不先做裁剪——X 存档包含的不只是公开帖文，直接放进 Agent 工作目录可能被读入模型上下文。

## 前置条件

- 拥有该 X 账号的登录与设置访问权限，能下载存档。
- 已安装 Claude Code，并有可写入的工作目录。
- 准备一个只含公开帖文的子集（例如最近 200–500 条），不要一上来用完整存档。
- 接受产出物是一份 Markdown 规则文件（如 style.md），并且需要人工审阅。

## 操作步骤

这里分两部分：1–3 步是调研原文给出的操作（其中第 2 步的命令是按描述补写的等价操作，第 3 步提示词原文被截断）；第 4–6 步是为让流程跑通而补写的，不是原文内容。建议先按“做法 A”跑通最小流程，再决定是否进入“做法 B”的盲测验证。

### 做法 A：最小跑通（原文 1–3 步 + 补充 4–5 步）

1. 下载 X 存档（原文）。前提：能进入账号设置。预期结果：得到一个存档压缩包。
   ```
   Settings > Your account > Download an archive
   ```
   注意：存档体积可能较大，且包含远超公开帖文的数据，处理前先确认内容范围。

2. 解压存档，在该文件夹中打开 Claude Code（原文描述；下面命令是按描述补写的等价操作，非原文逐字给出）。前提：已安装 Claude Code，目录可写。预期结果：Claude Code 在当前存档目录启动，能读取目录内文件。
   ```
   unzip <archive>.zip -d x-archive
   cd x-archive
   claude
   ```

3. 粘贴提示词（原文，已截断，完整内容未知）。前提：已进入存档目录并启动 Claude Code。预期结果：原文没有说明；按原文只能确认它要求模型“读遍存档里所有帖文，学习我如何写”。
   ```
   Read every post I've ever written in this archive. Study how I
   ```

4. 把上一步补全为可执行指令，要求输出一份可复用的风格规则文件，而不是只在对话里点评（补充，非原文）。前提：已进入存档目录。预期结果：目录下生成 style.md，每条规则配 2–3 个原文例子。
   ```
   Read every post I've ever written in this archive. Study how I write:
   sentence length, punctuation habits, capitalization, emoji use,
   how I open and close a post, recurring phrases, topics, and tone.
   Then write the findings to style.md as explicit rules with 2-3
   verbatim examples per rule. Do not invent examples that are not in
   the archive.
   ```

5. 人工审阅 style.md（补充，非原文）。前提：已生成 style.md。删掉把“偶发错别字”也当成风格规则之类的噪声条目，只保留可复现的特征。预期结果：得到一份你认可的、规则数量可控的 style.md；建议先挑出 5–8 条你认为“确实是我”的规则。

### 做法 B：把 style.md 用于起草并自检（补充，非原文）

6. 把 style.md 作为固定上下文，在每次让模型起草时引用，并要求“对照 style.md 逐条自检后再输出”。前提：已有一份审阅过的 style.md。预期结果：模型输出前会先对照规则检查；你需要记录生成后改动了多少处。
   ```
   这是我要写的话题：<topic>
   请先阅读 style.md，再起草。写完后对照 style.md 逐条自检，
   列出不符合的条目并修正，最后只输出修正后的正文。
   ```

怎么选：
- 只想先看看有没有用：走做法 A，产出 style.md 后人工判断规则是否像你。
- 想判断是否真的变好：走做法 B，并按下节做盲测。
- 如果语料本身风格混杂，先不要进入做法 B；换更一致的子集重跑做法 A，否则规则文件不稳定。

## 怎么判断变好了

最小试用（约 1 小时，来自调研报告的建议）：
1. 取一个只含公开帖文的子集（例如最近 200–500 条），不要一上来用完整存档。
2. 在该目录启动 Claude Code，用补充版提示词产出 style.md。
3. 人工从中挑出 5–8 条你认为“确实是我”的规则。
4. 做盲测：选 5 个你以前真实发过的话题，各写两版——A 版由模型在不带 style.md 的情况下写，B 版带 style.md 并按要求自检。打乱顺序，让 2–3 位熟悉你的人判断“哪版更像本人写的 / 哪版更像 AI 写的”，不告诉他们两版的差别。
5. 同时记录 B 版生成后你需要改动多少处（编辑距离或改动条数）。

可观察指标：
- 盲测中 B 版被判为“像本人”的比例，是否显著高于 A 版。
- 从“被判为 AI 写的”到“判不出”的转变，比“更像”更可靠。
- B 版的人工改动条数相比 A 版是否下降。
- 规则文件的稳定性：换一批帖文重跑，产出的规则是否大体一致；若差异很大，说明语料本身风格不统一，方法不适用。

试多久：报告只给出“约 1 小时”的最小试用建议，没有给出长期试用时长。若盲测中两版无法区分，说明这条线索只是“读了自己的旧帖”，没有产生实际增益，应把 verdict 降为 study。

## 常见坑

- 一上来用完整 X 存档：存档包含的不只是公开帖文，隐私风险高，且噪声多。先裁剪出只含公开帖文的子集。
- 把原文第 3 步提示词当成完整指令：原文在“Study how I”处截断，最关键的要求模型输出什么缺失；必须用补充版提示词明确输出格式，否则模型可能只在对话里点评。
- 让模型编造风格例子：补充版提示词里明确“Do not invent examples that are not in the archive”，审阅时仍要核对例子是否真的出自存档。
- 把偶发错别字当风格：人工审阅时删掉不可复现的噪声。
- 只“读旧帖”不验证：原文只有“10 分钟”和“Everyone can tell”的作者主张，没有前后对比、样本、盲测或数据；不验证就无法判断是否真的变好。
- 忽略语料一致性：发帖量少或多语言、多体裁、多账号混杂时，提炼出的规则会失真。
- 把 style.md 当成一次性对话：它应该作为固定上下文在每次起草时引用，并要求模型自检。
