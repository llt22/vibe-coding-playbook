# 让 AI 接手团队文档前：先给上下文和权限，再把重复工作做成 skill

> **未经实测**：本手册由 ai-work-radar 根据自动调研合并生成并持续修订，步骤尚未有人实际跑过。服务修订时基于自己保存的上一版重写，直接改这个文件会被覆盖；实测过的做法请写到 experiences/。
>
> 解决的问题：团队用 AI 写提案、周报、销售跟进、报销初审、入职问答和会议纪要时，因缺少公司上下文、按人文件权限和可复用流程而反复返工、越权或产出不可用；本手册给出一条先小范围验证再扩大的落地路径。
> 先试这一步：先用本地 demo 的双账号确认“看不到的文件夹 AI 也答不出”，再选一个低风险高频文档任务写第一个 SKILL.md，只开给 2–3 人试用。
> 最近修订：2026-11-14

## 解决什么问题

团队让 AI 写提案、周报、销售跟进、报销初审、入职问答、会议纪要时，常见的卡点不是模型不会写，而是它不知道“我们公司是谁、客户是谁、格式是什么、这个人能看哪些文件”。调研里的对比很典型：空白文件夹里的 Claude Code 面对“给 Trina Logistics 写一份提案”会先反问六个关于公司、客户、格式的问题；接上团队文件夹和 CEO 的 proposal skill 后，同一句话直接产出一份 7 页提案 deck。这个对比来自产品 showcase，不是第三方评测，但它指出的问题成立：先把公司上下文和按人权限供给 AI，再谈模型能力。

另一条调研把问题往前推一步：即使给了上下文，如果没有把高价值 workflow 拆成 skill、没有事实与语气文件、没有回归案例和成本记录，AI 仍然只是“会给建议的聊天框”，难以稳定接手重复工作。本手册把两条线合成一条：先用 Trina AX 这类可部署工作台验证权限和文件夹，再用“第二大脑/公司大脑/事实与语气文件/顶层指令/录音转 skill/回归集/成本记录”把重复工作固化。

## 适用与不适用

**适用**

- 团队工作以文档为主：提案撰写、周记转决策/风险/下一步、销售跟进、campaign brief、报销初审、入职问答、会议纪要。
- 素材已经在公司文件夹里，或能整理成 Markdown 文件夹，且需要按人、按组控制可见范围。
- 有一个高价值、重复发生的 workflow，愿意指定负责人，并保留人工批准环节。
- 愿意让 IT 做一次安装、更新和恢复备份，或先用托管/本地 demo 小范围试。
- 接受产出必须由人复核后再用；人类负责批准、拥有结果和客户沟通。

**不适用**

- 要求完全离线：自托管不等于离线，请求所需上下文会发给你所连的 AI 提供商。
- 需要安全认证或第三方评测背书：原文明确没有安全认证。
- 需要 AI 自动做法律、财务、HR 决定：原文明确不做。
- 主要素材是扫描件和照片且部署在 Linux：Linux 服务器不跑 OCR，扫描件和照片不可文本搜索。
- 必须在 Debian 12 上预览 HWP：HWP 可视预览需 macOS 或 glibc 2.39+，Debian 12 不支持。
- 没有 IT 且不愿用托管：Linux 自托管由 IT 负责安装、更新和恢复备份。
- 期待立刻省钱：原文明确不保证省钱。
- 没有历史内容、会议记录或多个数据源，却想一次把 40 条动作全部上线。
- 不愿做权限隔离、日志预算和人工审批，却想让 agent 自动执行工具动作。
- 依赖推文清单第 40 条“周五重写”做完整闭环：原文写到该条即截断，无法提炼完整步骤。

**尚未验证、不要写成生产步骤的**

- 主动推进：Trina 功能列表提到 `schedules` 和网页搜索，但原文没有给触发条件、状态机或持续运行的做法细节；推文清单也提到触发器、常开 orchestrator、夜间流入，但没有配置和阈值。本手册只把它们写成“最小权限试点”，不写成生产步骤。
- MCP：初筛理由提到“接入 MCP”，推文清单也列了 gmail、slack、stripe、linear、notion、posthog、supabase，但都没有给配置；本手册只写“选一个工具、最小权限、保留人工批准、记录日志和预算”。
- 具体模型路由和本地模型：推文清单只给工具名和模型名，没有给配置、成本和版本核实；不要把示例名称当成已验证方案。

## 前置条件

- 一个高价值、重复发生的 workflow，以及一个对该 workflow 负责的人。先能写清：何时用、谁用、输入是什么、输出是什么、什么算成功、谁批准。
- 可写的 Markdown 文件夹或公司文件夹。事实文件里的每条事实可追溯；语气文件有足够历史内容；敏感内容脱敏或做权限隔离。
- 明确的权限边界：哪些文件给哪些人、哪些组、哪些项目；至少准备两个账号用于复核。
- 录音、转写和数据留存合规。若要录会议或口述 workflow，先确认允许录、允许存、允许给哪个 AI 提供商。
- 本地 demo：本机有 Git、Bun 1.3.12、Go 1.27+；demo 里 AI 是关闭的，不需要任何 AI 账号。
- Linux 自托管：Debian 12/13 或 Ubuntu 24.04、systemd 带 cgroup v2、amd64 或 arm64、建议 4 GB 内存、最少 20 GB 磁盘；由 IT 负责安装、更新和恢复备份。
- 托管形态：Trina 托管在 AWS Seoul（原文给的部署形态选项）。
- 客户端：浏览器（桌面/手机）或 Windows 客户端，没有终端入口。
- AI 连接：可以接公司的 Claude 或 OpenAI 账号一次，也可以让每人自连；按人计量并有额度上限。先确认账号条款允许这样共享。
- 如果要自托管接 DeepSeek、Kimi、GLM：原文只给文档锚点 `docs/CONFIGURATION.md#anthropic-compatible-gateway`，没有给具体配置，需要按该文档另做。
- 运行时默认值：每次回答最多 150 轮工具调用、最多 4 个子智能体并发，带网页搜索和调度。
- 扩大时再加：Git/GitHub 版本历史、顶层指令文件能被 agent 启动时读到、安装的现成 skill 已审查代码和权限、MCP 最小权限、每个 job 有日志和预算、回归案例和正确答案。

## 操作步骤

### 1. 选一个高价值、重复发生的 workflow

前提：团队能列出正在重复做的工作，并粗略估算“赚到的钱或省下的钱”。

做法：把公司所有 workflow 画出来，按收益排序，选第一名；指定一个负责人；写下输入、输出、人工审批点和失败回退方式。不要一次选五个。

预期：一句话能说清这个 workflow 何时使用、谁使用、什么算成功；后面所有 skill、触发器、回归集都围绕它做。

### 2. 先跑本地 demo，确认能起来

前提：本机有 Git、Bun 1.3.12、Go 1.27+；不需要 AI 账号。

```sh
git clone https://github.com/trina-app/trina-ax.git && cd trina-ax
bun install --frozen-lockfile
bun run demo        # → http://127.0.0.1:19760 · sign in as alice / teamax-demo-1
```

预期：浏览器打开 `http://127.0.0.1:19760`，用 `alice` / `teamax-demo-1` 登录。README 明确说这**不是生产安装**。

### 3. 用双账号验证“按提问人逐次校验文件权限”

前提：上一步 demo 已启动。

- 开一个隐私窗口登 `bob`，对比 alice 和 bob 看到的组文件夹不同。
- demo 里 AI 是关闭的，所以 demo 只能先验证账号可见的文件夹不同；要验证 AI 回答不越权，需要在已接 AI 连接的试用环境按同一问题复核。
- 在已接 AI 的环境，按 README 的做法用两个账号问同一个问题（示例是销售同事问“上季度营收多少”），确认答案落在受限目录（示例是 `shared/Finance`）时，AI 回答“在我能访问的团队文件里没找到营收数字”，而不是给出数字。

预期：无权限账号看不到受限文件夹；AI 回答不越权；活动记录里能看到 AI 读了哪些文件，而不是看聊天内容。如果这一步不成立，不要进入下一步。

### 4. 选部署形态：做法 A / B / C / D

前提：已经知道团队有没有 IT、是否要求把服务放在公司服务器、是否只用 Claude。

- **做法 A：Trina 托管（AWS Seoul）。** 适合不想自己运维、能接受托管方运维可读存储文件和聊天的情况。原文说运维方（托管时即 Trina）能读存储的文件和聊天，应用管理员看不到别人的私人会话。
- **做法 B：Linux 自托管。** 适合有 IT、需要把服务放在公司服务器上的情况。前提见上。在非生产机按 `docs/INSTALL-LINUX.en.md` 装一遍。预期：能完成安装、更新和恢复备份；专门确认 HWP 预览在 Debian 12 不可用这类坑。
- **做法 C：办公室 Mac。** 适合只用 Claude、不用 Codex 的小团队。原文说 Office Mac 以登录用户身份运行，没有 OS 隔离。
- **做法 D：本地 demo。** 只用于看权限模型和试 skill 结构，不是生产安装。

怎么选：没有 IT 或只想先验证，选 D 再考虑 A；有 IT 且数据要放在公司服务器，选 B；只用 Claude 且接受 Mac 常开，选 C。不要用 demo 直接承载真实敏感文件。

### 5. 按首周顺序配置

前提：已选定形态并能登录 owner 账号。

顺序：创建 owner 账号 → 配置权限 → 接 AI 连接 → 邀请团队 → 建第一个 skill → 首次备份。

预期：六项全部完成再开始真实任务；任何一项没完成，先不要扩大使用范围。首次备份按产品界面或文档完成，不要跳过。

### 6. 建公司大脑、个人第二大脑、事实文件和语气文件

前提：已确定哪些文件可以给团队看，哪些只能个人看；敏感内容已脱敏或做权限隔离。

- 公司公共文件放 `shared/`，组内共享放 `groups/`，项目放 `projects/`，个人目录另设；都带版本历史。PDF、Office、HWP/HWPX 可抽文本。
- 公司大脑放客户、通话、数字、定价、playbook、过去决策及原因；统一目录和字段，否则后续难以检索。
- 个人第二大脑用 Markdown 文件夹记录你如何思考、写作和决策。原文以 Obsidian 的 Markdown 文件夹为例；在 Trina 形态下对应个人目录，不要另造一套无法权限隔离的库。
- 事实文件只放关于你和公司、允许 agent 对外说的真实内容，用来减少编造；每条事实可追溯。
- 语气文件收集你最好的 50 条帖子、你讨厌的 20 条，以及你永不使用的词；这是原文给的数量，目的是让输出像团队而不是像通用 AI。
- 全部放进 Git/GitHub，让每次变更都有历史；敏感内容脱敏或做权限隔离。

预期：AI 能在权限范围内检索到这些文件；事实可追溯；共享目录里没有不该给的内容。但 Linux 服务器不跑 OCR，扫描件和照片不可文本搜索；HWP 可视预览需 macOS 或 glibc 2.39+，Debian 12 不支持。

### 7. 写顶层指令文件

前提：agent 启动时能读到该文件；文件所在目录的权限与公司文件夹一致。

在仓库根目录写 `CLAUDE.md` 或 `AGENTS.md`，放入原文规则：

```
read these files before any task, never overwrite, always date
```

预期：每次任务先读事实、语气和公司大脑文件；不覆盖原文；输出带日期。这个文件和 Trina 的 `SKILL.md` 不冲突：顶层指令管“每次都要遵守的规则”，skill 管“某一类工作怎么做”。

### 8. 写第一个 skill：做法 A 抄示例 / 做法 B 录音转 skill

前提：已有一个低风险、重复发生的文档任务；第一个 skill 只开给 2–3 人试。

一个 skill 就是一个 `SKILL.md` 文件，例如提案写法放 `skills/proposal/SKILL.md`。一个工作一个 skill；小而无聊胜过一个巨大 prompt。

**做法 A：从示例结构抄。** 适合任务与示例接近、团队还不想录口述的情况。先照 `examples/skills/` 里对应结构抄，不要从零发明。

| 角色 | 任务 | 可抄文件 |
|---|---|---|
| CEO / 团队负责人 | 周记 → 决策、风险、下一步 | `examples/skills/weekly-team-report/SKILL.md` |
| 销售 | 从会议记录起草跟进，不许编造承诺 | `examples/skills/sales-follow-up/SKILL.md` |
| 市场 | 从已批准的 brand notes 出 campaign brief | `examples/skills/brand-brief/SKILL.md` |
| 财务 | 标记缺发票和金额不确定项待复核 | `examples/skills/expense-review/SKILL.md` |
| HR | 只依据有权限的政策回答入职问题 | `examples/skills/new-hire-guide/SKILL.md` |
| 所有人 | 从会议记录抽决策与行动项 | `examples/skills/meeting-summary/SKILL.md` |

**做法 B：把负责人做一遍的过程录下来，再转成 skill。** 适合高价值但“只在他脑子里”的 tacit workflow。负责人完整做一次该 workflow，边做边口述判断并录音；让 agent 把录音转成 skill，写清何时使用、步骤、检查项、要避免的错误。前提是录音可转写、录音和转写合规。

怎么选：任务与示例接近，先用 A；高价值且步骤说不清，用 B。两者都可以先只开给 2–3 人，不要把第一个 skill 全团队放开。

预期：skill 是“一组可复用的指令”，不是模型训练、也不额外赋权；AI 要改一个 skill 之前会先问人。

### 9. 接 AI 连接并设按人额度

前提：确认公司账号条款允许共享，或决定让人自连。

可以接公司的 Claude 或 OpenAI 账号一次，也可以让每人自连；按人计量并有额度上限。自托管时 Claude Code 还能经 Anthropic 兼容网关跑 DeepSeek、Kimi、GLM，原文只给 `docs/CONFIGURATION.md#anthropic-compatible-gateway`，没有给具体配置。

预期：每个人有独立用量上限；先小额度试，不要一上来全团队放开。定价只作参考：2026-11-02 核查，税前美元，Free 最多 3 人（名额有限）、Starter $39/月（5 人）、Team $69（15 人）、Business $129（40 人），40 人以上另报价；AI 用量另计。

### 10. 收窄入口（IT/管理员侧）

前提：有自托管或托管的管理员权限。

引擎自带的 shell 和文件工具被关掉，通往公司文件夹的唯一路径是 Trina 的文件工具，逐次调用逐次检查；每个引擎的这层收窄有回归测试覆盖。token 在浏览器里先封装再上送，引擎拿到的是每轮临时替身 token，由模型代理换成真 token。

预期：AI 不能绕过文件工具直接读公司文件夹；如果关不掉引擎自带工具，不要上线。

### 11. 接工具或触发器：先做最小权限试点

前提：已有一个 skill 和明确的人工审批点；选定一个工具或一个事件；有日志和预算。原文只给工具名和动作，没有给 MCP 配置、触发器定义或权限模型，以下不补造配置。

- **做法 A：接一个 MCP 工具。** 从 gmail、slack、stripe、linear、notion、posthog、supabase 中选一个，只给完成该 skill 所需的最小权限；先保留人工批准，不让 agent 自动发送或自动改动。
- **做法 B：把 skill 放到一个触发器上。** 例如每日、每周、每个新 lead、每次取消事件；先只做通知或草稿，不自动执行最终动作。
- **做法 C：暂不接。** 先手工跑 skill，等回归集和成本记录稳定后再接。

怎么选：没有日志、预算和人工审批就不接；要接就先接一个工具或一个事件。浏览器和独立电脑同理：原文只列为“给 agent 浏览器/自己的电脑”的动作，没有给配置，先小范围试。

预期：agent 能行动而不只是建议；每个 job 有 job、budget、log；失败可回退；人类仍保留批准和客户沟通。

### 12. 建回归集和 reviewer 门槛

前提：已有 skill 和一批真实案例；案例和正确答案已脱敏。

保留 50 个真实案例和正确答案；最小试用可先做 10 个，再逐步补到 50。每次改 skill、换模型或改指令文件都重跑，新模型发布时切换到赢家。给 reviewer agent 一个明确门槛：

```
would the best team in the world ship this?
```

不到 yes 就拒绝。人类负责批准、拥有结果、和客户沟通；这是要保留的 10%。

预期：回归通过率可比较；人工修改时间可比较；reviewer 不是“看着差不多就过”，而是按统一门槛拒绝。

### 13. 记录每个 job 的成本，决定模型路由和本地模型边界

前提：已经有 job 日志和成本记录；知道哪些数据不能出机器。

做法：贵的模型负责计划和检查，便宜的模型跑量；缩短输出、缩小 tool results 来降 token 账单；对不能出机器的数据跑本地模型；追踪每个 job 的成本，如果成本高于收益，就修或杀。原文举了具体模型名（如 fable 5.2、gemini 4 carbon、gemma 4），需自行核实可用性和版本。

预期：单成功任务成本不高于原流程；如果成本高于收益或错误率上升，按停止条件处理。

### 14. 每个完成的 job 写回公司大脑

前提：公司大脑有可写入的目录，且规定不得覆盖原文。

每个完成的 job 写回：什么有效、什么失败、什么要停止。写回内容要带日期，并和对应客户、项目、skill 关联。

预期：下一次同类任务不用从零开始；失败模式能被回归集吸收；公司大脑越来越像团队的工作记忆，而不是文件堆。

### 15. 做权限隔离复核和上线前合规检查

前提：已有两个账号、一个受限目录，准备放真实文件。

用无权限账号问一个答案落在受限目录里的问题，看 AI 是否“找不到”；同时核对活动记录里 AI 读了哪些文件，而不是看聊天内容。撤销文件夹权限不会抹掉此前已产生的回答，所以复核要在放入敏感文件之前做。

上线前确认三件事：请求所需上下文会发给你所连的 AI 提供商；每个 Codex 网页搜索会把此前对话发给 OpenAI 的搜索服务；选了 OpenRouter 做语音时，团队文件的音频会发给 OpenRouter 及其上游。服务器每 30 分钟向 `updates.trina.app` 询问自身公网地址，`MYCEL_EXIT_ADDRESS_CHECK=off` 可关。

预期：回答不出现受限数字；活动记录与预期一致；如果运维方无法满足数据合规要求，退回单人本地使用，不强行上线。

## 怎么判断变好了

**最小试用方式（一周内可完成，不碰生产环境）**

1. 本地 demo 跑通，用 `alice` 与隐私窗口的 `bob` 双账号确认“看到不同组文件夹”。
2. 按第 1 步选一个低风险、高频 workflow，指定负责人，写清成功标准和人工审批点。
3. 建最小公司大脑：事实文件、语气文件、公司文件夹或 Markdown 文件夹；敏感内容脱敏。
4. 写顶层 `CLAUDE.md` 或 `AGENTS.md`，放入原文规则；再按做法 A 或 B 写第一个 `SKILL.md`。
5. 接公司 Claude 或 OpenAI 账号（先确认授权条款允许这样共享），或先让人自连个人账号；设按人用量上限。
6. 建 10 个真实案例和正确答案；每次改 skill、换模型或改指令文件都重跑。
7. 可选：按第 11 步只接一个 MCP 工具或一个触发器，保留人工批准，记录 job、budget、log。
8. 若要自托管，先在非生产机按 `docs/INSTALL-LINUX.en.md` 装一遍，专门确认 HWP 预览在 Debian 12 不可用这类坑。

**观察指标**

- **权限是否真的成立**：用一个无权限账号，问一个答案落在受限目录里的问题，看 AI 是否“找不到”；同时核对活动记录里 AI 读了哪些文件，而不是看聊天内容。
- **回归通过率**：10 个案例起步，逐步补到 50；每次改 skill、换模型或改指令文件都重跑，比较通过率而不是凭感觉。
- **事实错误/编造次数**：事实文件是否减少编造；销售跟进是否出现未经授权的承诺；报销和入职问答是否引用了无权限内容。
- **输出质量**：同一 prompt 在“空工作区”和“有公司大脑/skill 的工作区”各跑一次，人工盲评三项——是否符合公司模板、是否有编造承诺、需要返工几轮。
- **交互成本**：从提问到可用草稿的轮数、人工修改时长、AI 反问次数（对照原文里“空文件夹先反问六个问题”的基线）。
- **reviewer 通过率**：用“would the best team in the world ship this?”这个门槛，统计不到 yes 被拒绝的比例和原因。
- **单成功任务成本**：记录每个 job 的成本；如果成本高于收益，就修或停。
- **采用度**：第一周清单（权限 → AI 连接 → 邀请 → 第一个 skill → 备份）是否全部完成；各 skill 的使用人数与复用次数。

**试多久**

用一周做最小试用，一周结束按上面指标复盘；没有改善就停，不要用“感觉变好了”代替指标。第一周只做 10 个回归案例；确认有改善后，再逐步补到 50 个，并扩大使用范围。

**停止条件**

出现越权读取、产出需要大改、事实错误上升、回归通过率下降、单成功任务成本高于原流程，或运维方无法满足数据合规要求时，退回单人本地使用，不强行上线。

## 常见坑

- **把“自托管”当“离线”。** 请求所需上下文会发给你所连的 AI 提供商；Codex 网页搜索会把此前对话发给 OpenAI 的搜索服务；OpenRouter 语音会把团队文件的音频发给 OpenRouter 及其上游；服务器每 30 分钟向 `updates.trina.app` 询问自身公网地址，`MYCEL_EXIT_ADDRESS_CHECK=off` 可关。
- **以为撤销文件夹权限会抹掉已经产生的回答。** 不会。撤销权限只影响之后的访问，不清理历史回答。
- **以为管理员能看到所有聊天。** 应用管理员看不到别人的私人会话；但运维方（托管时即 Trina）能读存储的文件和聊天。选托管前把这条讲清楚。
- **在 Linux 上找扫描件。** Linux 服务器不跑 OCR，扫描件和照片不可文本搜索；HWP 可视预览需 macOS 或 glibc 2.39+，Debian 12 不支持。
- **把 OS 隔离当成所有形态都有。** OS 隔离（专用引擎账号）只适用于 Linux 和角色账号 Mac 安装；Office Mac 以登录用户身份运行；本地 demo 无 OS 隔离。
- **把 demo 当生产。** README 明确说 demo 不是生产安装，且 demo 里 AI 是关闭的。
- **把 skill 当模型训练或权限。** skill 是一组可复用的指令，不额外赋权；AI 改 skill 前会先问人。
- **只看模型，不看上下文供给。** 空白文件夹里 Claude Code 会先反问六个问题；先把公司文件夹、事实文件、语气文件和 skill 放进去，再评价模型。
- **一次上 40 条。** 推文清单是动作清单，不是上线顺序；先取第 1、5、6、8、14、15、16、30、36、38 条做最小闭环，其他等回归集和成本记录稳定后再加。
- **装现成 skill 不审查。** 原文说“不要从零写技能，先安装现成的好技能”，但也要求安装前审查代码和权限；不要把“安装”当成“可信”。
- **MCP 或触发器给过大权限。** 原文只给工具名和动作，没有给权限模型；没有最小权限、日志、预算和人工批准，不要接。
- **没有回归集就换模型。** 原文建议保留 50 个真实案例和正确答案，每次新模型发布就重跑，切换到赢家；没有回归集就无法判断换模型是变好还是变坏。
- **只记 token 账单，不记单成功任务成本。** 原文要求追踪每个 job 的成本；如果成本高于收益，就修或杀。
- **把第 40 条截断内容补造成完整闭环。** 原文写到“every friday an agent rewrites”即截断，无法评估；不要据此写“周五自动重写”的生产步骤。
- **忽略许可证和条款。** Trina AX 许可证 AGPL-3.0-only，若改版后通过网络提供服务需向用户提供源码；Claude Code / Codex 自身条款仍适用，本项目未获 Anthropic 或 OpenAI 背书。
- **把安装包当最新源码。** 项目 60 星，安装包可能落后于源码。
- **期待自动法律/财务/HR 决定、保证答案完美、保证省钱。** 原文明确不承诺这些，产出需人工复核。
- **把定价当长期固定。** 2026-11-02 核查，税前美元，AI 用量另计，40 人以上另报价。
