# 让编码不因配额耗尽中断：把工具接到本地网关，按任务选模型并自动回退

> **未经实测**：本手册由 ai-work-radar 根据自动调研合并生成并持续修订，步骤尚未有人实际跑过。服务修订时基于自己保存的上一版重写，直接改这个文件会被覆盖；实测过的做法请写到 experiences/。
>
> 解决的问题：编码中途被限流、配额耗尽或某个 key 失效时，能不能由一层本地 OpenAI 兼容网关按任务选模型、自动切到下一个可用目标，而不是你手动换模型换 key。
> 先试这一步：先在本机 `npm i -g omniroute` 把服务起起来，用一条 `model=auto` 的 curl 确认本地端点无需 key 就能返回，再只把一个你在用的编码工具的 base URL 指过去。
> 最近修订：2026-10-02

## 解决什么问题

编码过程中经常遇到三种中断：某个供应商的订阅配额到期没用完、编码到一半被限流、某个 key 死掉导致整条流程卡住。这些事本身没有谁专门负责，于是变成你手动换模型、换 key。这篇手册的做法是：在本机起一层 OpenAI 兼容的网关，把已有的编码工具统一指过去，由它按任务选模型，并在配额耗尽、供应商失败或成本上升时自动回退到下一个健康目标。

调研报告显示，这个项目把四类痛点明确列为可接管项：订阅配额到期未用完、编码中途被限流、工具输出烧 token、死 key 导致阻塞。

## 适用与不适用

适用：

- 你手上有多个供应商或多把订阅/API key，经常因为某一个配额耗尽、限流或失败而中断工作。
- 你愿意在本机长期运行一个本地服务，并且手上的工具支持自定义 OpenAI 兼容 base URL。
- 你只想先在非敏感、非生产任务上小范围试。

不适用或需要谨慎：

- 有合规或数据敏感要求：接入前先看清请求是否会经过第三方免费层。
- 想直接采信 README 的效果数字：原文没有给出测量方法、测试集或对照实验，只能自己 A/B。
- 想用它的“生产级”能力（MCP、A2A、guardrails、evals、TLS stealth、key pools 等）：给定材料里只有名词，没有配置步骤，无法据此落地。

## 前置条件

- 本机可安装 npm 全局包（有 Node.js/npm 环境）。
- 能长期运行一个本地服务。
- 零凭证也能先跑：README 称全新安装无需任何凭证即可先用 `auto`（keyless 供应商 OpenCode Free 已预置进 `auto` combo）。
- 要接自有供应商时，需要有对应的 API key 或订阅凭证。
- 被接入的工具本身支持自定义 OpenAI 兼容 base URL。README 点名的可接工具包括 Claude Code、Codex、Cursor、Cline、Copilot、Antigravity。
- README 还提到 Docker、源码、pnpm、Arch 等安装方式，但给定文本未给出对应命令，需要到仓库文档自查。

## 操作步骤

**做法 A：先跑通最小闭环（建议从这里开始）**

1. 安装并启动网关。前提：有 Node.js/npm 环境。

```bash
npm i -g omniroute
```

预期结果：README 说明安装后服务在本机 `localhost:20128` 启动。

2. 零凭证验证连通。前提：上一步的服务已在跑。

```bash
curl http://localhost:20128/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto","messages":[{"role":"user","content":"Hello!"}]}'
```

预期结果：拿到模型回复，说明本地端点可用、无需 key 就能返回。如果只想指定这个免费后端，可直接调 `oc/…`（OpenCode Free），跑通后再改用 `auto` 让它自己挑。

3. 只把一个工具指向这个端点。前提：该工具支持自定义 OpenAI 兼容 base URL。把 base URL 设为 `http://localhost:20128/v1`，模型名填第 4 步的别名。建议先接一个你已经在用的工具，不要一次全换。

4. 按任务选模型别名。原文给出的映射可直接用，这是最可照做的一步：

| 模型 ID | 用途 |
| --- | --- |
| `auto` | 均衡默认，粘住上次可用的好供应商（LKGP） |
| `auto/coding` | 代码生成，质量权重优先 |
| `auto/fast` | 最低延迟优先 |
| `auto/cheap` | 每 token 最便宜优先 |
| `auto/offline` | 剩余配额/限流余量最多优先 |
| `auto/smart` | 质量优先 + 10% 探索 |
| `auto/lkgp` | 显式“上次已知良好供应商”粘性 |
| `auto/chaos` | 并行发到一个模型面板（默认每供应商一个、共 5 个），返回一个答案 |

5. 连续试用并保留对照路径。同一批任务下，一路走网关、一路直连原供应商，记录中断次数和人工切换次数。

6. 看配额与用量。打开 `/dashboard/free-tiers` 看已用/剩余。README 称该页每两周对照实时目录重审，还称 dashboard 有 usage、quota、savings、p95 延迟的实时分析，但没有给操作步骤，所以只把它当成提示，别当成依据。

**做法 B：需要更细控制时自建 combo**

当 `auto` 别名不够用（例如你必须固定尝试顺序，或必须按实时目录价最小化成本）时，自建 combo 并逐步选择路由策略。原文列出 19 种可混搭策略，给定文本只到第 12 种：

- `priority`：按序先耗尽第一个再下一个
- `fill-first`：先把每个目标的配额填满
- `weighted`：按权重随机
- `round-robin`：轮转
- `p2c`：二选一随机负载均衡
- `least-used`：选当前负载最低
- `random`：均匀随机去重
- `strict-random`：随机且不去重
- `cost-optimized`：按实时目录价最小化成本
- `headroom`：选剩余配额最多
- `reset-window`：优先选配额窗口最快重置的
- `reset-aware`：按配额重置时间排序，短窗口优先

怎么做 A / B 的选择：先用做法 A 的 `auto` 系列别名跑一周；只有在你能明确说出“我需要固定顺序 / 我需要按目录价最小化成本 / 我需要按配额重置时间调度”这类具体目标时，再进做法 B。

**暂时不要碰的部分**：README 提到的 MCP（110 个工具）、A2A、memory、guardrails、evals、TLS stealth、key pools 公平配额、AES-256-GCM 加密存 key，在给定材料里只有名词，没有配置步骤。

## 怎么判断变好了

最小试用（1–2 天，仅限非敏感、非生产任务）：

1. 按做法 A 第 1–2 步装好并跑通 `curl` + `model=auto`，确认本地端点可用、无需 key 就能返回。
2. 只接一个工具（建议先接你已在用的 Cline 或 Claude Code），base URL 指向 `http://localhost:20128/v1`。
3. 连续一周用 `auto/coding` 做日常编码任务，同时保留一条直连原供应商的对照路径。
4. 不启用来源不明的免费供应商；先用自有 key 或已知供应商验证回退逻辑是否按预期工作。

指标（都自己测，不采信 README 的百分比）：

- 中断次数：同一批任务下，因限流/配额耗尽导致的请求失败或人工切换次数，对照直连单供应商。
- 人工干预次数：一周内你手动换模型/换 key 的次数是否下降。
- 成本与 token：相同任务集在直连与经网关两条路径下的实际 token 数与账单金额；要验证压缩效果，必须用同一提示词做 A/B，而不是引用 15–95%。
- 延迟：自己记录 p95，别只信 dashboard 的 savings 卡片。
- 配额真实性：把 `/dashboard/free-tiers` 显示的 used/remaining 与供应商后台账单对照，这直接决定“配额感知回退”是否可信。
- 质量不下降：用你既有的评测方式（或同一组任务的人工打分）确认换模型后结果没有变差；`auto/chaos` 并行面板会成倍消耗上游调用，试用时单独计费观察。

试多久、什么情况下停：试三周。若三周后“中断次数 / 人工切换次数”没有下降，或配额显示与实际账单明显不符，就停用并把结论降为 study。

## 常见坑

- 把 README 的自述数字当结论。省 15–95% token、~1.62B 免费 token/月、“永不停止编码”都没有给出测量方法或对照实验。
- 一次把所有工具都切到网关。先只接一个，保留直连对照，否则无法判断是网关起了作用还是任务本身变简单了。
- 忘记核对免费供应商条款。README 自己披露有 13 家供应商因条款风险被标记为 avoid。
- 把多把第三方 key 交给一个本地服务。README 称 key 本地加密（AES-256-GCM）、本地优先，但没有给出可照做的验证方法。
- `auto/chaos` 的并行扇出：默认每供应商一个、共 5 个模型面板，会成倍消耗上游调用。
- 只信 dashboard。savings 卡片不等于你自己的 p95 和账单。
- 材料本身是截断的。原文正文在 19 种路由策略表格第 12 行处被截断，Docker/pnpm 等安装方式、MCP/A2A/guardrails/evals 的配置步骤都不在材料内。
- 名称相近但关系不明。材料里作为 keyless 免费后端的 “OpenCode Free”（`oc/…`）与别处提到的 OpenCode 名称相近，但原文没有说明两者是否同一项目，不能确认。
