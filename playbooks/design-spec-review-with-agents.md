# 在写代码前，让零上下文评审者挑设计漏洞

> **未经实测**：本手册由 ai-work-radar 根据自动调研合并生成并持续修订，步骤尚未有人实际跑过。服务修订时基于自己保存的上一版重写，直接改这个文件会被覆盖；实测过的做法请写到 experiences/。
>
> 解决的问题：需要先做设计决策的功能，常在实现前漏掉未言明假设、遗漏需求和实现风险，导致编码后返工。
> 先试这一步：选一个确实需要设计取舍的功能，在支持 fresh subagent 的编码代理里安装 EGM，只走一遍 /egm-brainstorm → /egm-draft → /egm-review，并人工决定采纳哪些评审发现。
> 最近修订：2026-10-29

## 解决什么问题
需要先做设计决策的功能，常见问题是：设计里的未言明假设、遗漏需求和实现风险，直到编码后才暴露，造成返工。EGM 把工作拆成“大象”带项目上下文起草规格、“金鱼”用全新子代理零上下文评审、人做架构取舍并批准，再进入实现。

## 适用与不适用
适用：一个功能在实现前确实需要设计取舍，例如新增 webhook 投递，需要讨论投递失败、同一事件到达两次等设计问题。也适用于已有笔记转设计文档、为已有代码库补文档、处理评审发现、检查文档与代码漂移等单点任务。

不适用：小型、明确的 bug 修复仍走普通编码流程，不要强行套完整流程。设计评审不能替代测试或人的判断。若编码代理不能创建全新子代理，金鱼评审无法进行，EGM 会停止评审。EGM 不是 Google 官方支持产品，采用前要按团队要求评估。

## 前置条件
- 编码代理支持插件，并且当前会话能创建新的子代理（fresh subagents）。README 明确说金鱼评审需要全新子代理上下文；代理无法创建时，EGM 会停止评审。
- 准备好项目上下文、需求、先前决策、被评审文档及其引用的源材料。
- 有人参与：每节草稿后给反馈，评审发现逐条取舍，最终批准规格后才实现。
- 安装完整插件，而不是只拿技能提示；材料说完整插件便于技能读取评审提示和文档标准。
- Claude Cowork 和 ChatGPT Work 需按 README 指向的 setup guide 配置；本次材料未提供该 setup guide 正文。

## 操作步骤
1. 确认代理能力。前提：你选定的编码代理支持插件，且会话能创建 fresh subagent。做法：在正式使用前确认能新建子代理。预期结果：能创建；若不能，停止走金鱼评审，不要假装完成零上下文评审。

2. 安装完整 EGM 插件。前提：按所用代理选择命令。Claude Code：
```sh
claude plugin marketplace add google/elephant-goldfish-model
claude plugin install egm@egm
```
Antigravity：
```sh
agy plugin install https://github.com/google/elephant-goldfish-model
```
Codex：
```sh
codex plugin marketplace add google/elephant-goldfish-model
codex plugin add egm@egm
```
预期结果：插件安装完成。安装后开始一个新会话。Claude Cowork 和 ChatGPT Work 按 README 指向的 setup guide 配置；材料未提供该指南内容。

3. 选择一个需要设计决策的功能。前提：功能不是小型明确 bug 修复，而是需要先讨论设计取舍。示例：README 用“给项目增加 webhook 投递”举例，并明确要讨论“投递失败怎么办”“同一事件到达两次怎么办”。预期结果：你能写出几个必须由人拍板的设计问题；若写不出，可能不该套用本流程。

4. 做法 A：走完整流程，从想法到批准规格。前提：你希望把一个功能从模糊想法推进到可实现的批准设计。按下面顺序做：

4.1 探索想法并形成概念简报。Antigravity（agy CLI）和 Claude Code 加 `/egm:` 前缀；Codex 从技能选择器中选择对应 EGM 技能。README 示例：
```text
/egm-brainstorm Add webhook delivery to this project.
```
与代理讨论需求和取舍；新评审者会挑战提案；代理把达成的一致方向保存到 `concepts_brief.md`。预期结果：得到一份概念简报，关键取舍有记录。

4.2 起草规格文档：
```text
/egm-draft
```
代理把简报转成 `design_draft.md`，每写完一节暂停，等待你在对话中反馈。预期结果：逐节形成设计草稿，而不是一次性生成后无人校对。

4.3 用零上下文评审者评审草稿：
```text
/egm-review design_draft.md
```
使用代理返回的草稿路径。新评审者检查设计本身、清晰度、与代码的契合度以及实现计划；你选择要处理哪些发现。预期结果：拿到一份可逐条处理的评审发现清单。

4.4 处理发现并定稿。可使用 `egm-resolve` 技能逐条处理评审发现并商定修改。预期结果：对采纳和不采纳的发现都有明确结论；README 提到完整流程会把批准的规格保存在 `docs/designs/` 下。

4.5 人工批准后再实现。你负责解决取舍、批准设计，然后让编码代理按批准的设计实现。预期结果：实现前已有批准规格，而不是边写边改设计。

5. 做法 B：按需单独使用技能。前提：你不需要完整序列，只想补一个环节。可按任务选择：`egm-brainstorm` 测试想法并写概念简报；`egm-draft` 把简报或已有笔记转成设计文档；`egm-resolve` 处理评审发现并商定修改；`egm-bootstrap` 为已有代码库创建或更新文档；`egm-review` 用新代理分五阶段评审设计；`egm-review-loop` 为特定评审任务运行一组配置好的评审者；`egm-drift-report` 把已检入文档与当前源代码对比。预期结果：只补所需环节，但不要因此跳过人的取舍和批准。怎么选：从模糊想法到批准规格用做法 A；已有简报只差文档用 `egm-draft`；已有评审发现用 `egm-resolve`；已有代码库缺文档用 `egm-bootstrap`；要检查文档与代码是否一致用 `egm-drift-report`。

6. 用 `egm-drift-report` 做一致性检查。前提：已有检入文档和当前源代码。做法：使用 `egm-drift-report` 技能对比文档与当前代码。预期结果：发现文档与代码漂移，作为后续维护输入；材料未给出该技能的具体命令形式，不要臆造命令。

7. 保留试用记录。前提：你准备判断效果。做法：保留 `concepts_brief.md`、`design_draft.md`、评审发现记录、采纳决定、批准后的规格和实现后的返工/缺陷记录。预期结果：能回答“评审是否在编码前发现了会导致返工的问题”，而不是只凭感觉。

## 怎么判断变好了
- 最小试用：选一个中等复杂度、确实需要设计取舍的功能（README 示例是新增 webhook 投递），在 Claude Code 中安装 EGM，按 `/egm-brainstorm` → `/egm-draft` → `/egm-review` 走一遍，保留 `concepts_brief.md`、`design_draft.md` 和评审发现记录；由人决定采纳哪些发现后再实现。
- 试多久：材料没有给出固定试用时长或样本量。可把“完整走完一个中等复杂度功能从设计到实现”作为一个试用单元，再决定是否扩大范围；不要只做一次评审就下结论。
- 看这些指标：对比使用前后，设计评审中发现的“未言明假设 / 遗漏需求 / 实现风险”的数量与质量；记录评审发现中被采纳的比例；记录是否在编码前发现了会导致返工的问题；记录从设计到实现的返工次数、规格变更次数、实现后缺陷数；检查批准后的设计文档是否可用于后续实现和交接；用 `egm-drift-report` 检查文档与代码是否保持一致。
- 降级或停止条件：如果评审只能产生泛泛意见、无法创建 fresh subagent，或发现的问题在编码前没有实际减少返工，应降级为 study 或停止使用。

## 常见坑
- 把小型明确 bug 修复套完整流程。README 明确说小型明确 bug 修复仍走普通编码流程。
- 让金鱼带着先前对话上下文评审。金鱼评审要零上下文、全新子代理；代理不能创建 fresh subagent 时 EGM 会停止评审。
- 只安装技能提示，不安装完整插件。材料说完整插件便于技能读取评审提示和文档标准。
- 安装后不开始新会话。README 要求安装后开始一个新会话。
- 把评审当测试或人的判断替代。README 明确评审不能替代测试或人类判断。
- 不选评审发现、不人工批准就进入实现。流程要求人选择处理哪些发现、解决取舍并批准规格。
- 只看评审意见数量，不看采纳和返工。材料没有量化改善数据；泛泛意见不等于有效发现。
- 把项目自述当效果证据。README 声称“数千名 Google 工程师使用 EGM”，仓库显示 5242 stars，但材料没有使用效果、缺陷率、返工率或评审命中率数据；“金鱼评审能暴露未言明假设和盲点”是项目主张，不是对照实验结论。
- 忽略材料边界。原文是 GitHub README，不是完整文档；`docs/getting_started.md`、`docs/harnesses.md` 等链接内容未提供；Claude Cowork 和 ChatGPT Work 的 setup guide 也未提供。
- 误以为 EGM 是 Google 官方支持产品。材料明确说该项目不是 Google 官方支持产品。
