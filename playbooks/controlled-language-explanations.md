# 让 AI 解释复杂内容时，先选最低够用的理解形式

> **未经实测**：本手册由 ai-work-radar 根据自动调研合并生成并持续修订，步骤尚未有人实际跑过。服务修订时基于自己保存的上一版重写，直接改这个文件会被覆盖；实测过的做法请写到 experiences/。
>
> 解决的问题：解决怎么把模型默认的长文本解释，改成读者更容易准确理解的最低够用形式，并用事实保全和读者反馈判断是否真的改善，而不是被精致产出误导。
> 先试这一步：先不安装任何技能，拿一份事实密集的技术说明或模型输出，套用“80% 到 ASD-STE100”提示词让模型重写，逐条核对数字、条件、限定词是否一个没少。
> 最近修订：2026-10-10

## 解决什么问题
当你要让同事、客户或未来的自己准确读懂一段模型输出、代码说明或流程文档时，模型的默认解释往往读起来顺但歧义不少；直接让它“写清楚”也可能只是更长。这篇手册给出一套从小范围试用开始的做法：先用受控英语或“80% 到 ASD-STE100”把内容压到低歧义，再按内容类型选择能完全回答问题的**最低**理解阶梯（文本→图表→交互页→视频），并用事实保全与读者反馈判断是否真的降低理解成本。注意：现有材料只支持作者个人经验、手工示例和少量前后对照，不宜直接当成团队定稿规范。

## 适用与不适用
适用：
- 需要跨读者一致理解的技术说明类文本（推断：受控语言的主要卖点是低歧义、一致性）。
- 你或他人需要读懂的一段模型输出、代码、协议、流程说明、对外文档。
- 事实密集的技术说明或状态更新，适合做零安装最小试用。
- 有“某个参数会改变结果”“过程/因果/状态/组件”“随时间展开的推导”等内容，可能适合从文本升级为图表、交互页或视频。
- 需要向不理解背景的同事解释一段 AI 产出的内容。

不适用或慎用：
- 需要表达丰富度、自然语气、文学性的写作；受控语言的一般代价是牺牲表达丰富度和自然度（常识性推断，原文未提及）。
- 原文没有说明适用于哪些内容类型、哪些读者、哪些模型，也没有给出任何效果数据，所以不要把它当成已验证有效的通用方法。
- 原文本身被截断，ASD-STE100 的完整规则和来源领域在本次材料中无法确认。
- 不应当一律把简单定义升级成 HTML 或视频；选择最低的、足以完整回答问题的阶梯，不要爬得比问题需要得更高。
- `plain-chinese` 是给 LLM 的轻量规则集，不是完整写作标准；句长之类的数字是经验法则，未经过阅读研究检验。

## 前置条件
- 一个“需要被准确理解”的解释对象，例如一段代码、一个协议、一份流程说明、一个对外文档，最贴合的起点是你自己或他人需要读懂的一段模型输出。
- 原文给出的提示词指令：`Ask your LLM to explain something in ASD-STE100.`
- 如果你要走做法 B，需要自备 ASD-STE100 规范文本；本次材料没有提供规范内容，也不知道模型是否内置该规范。
- 至少 2–3 位不了解背景的读者，用于做前后对照（来自调研报告的最小试用方案）。
- 进阶试用需要支持 Agent Skills 的客户端（原文列出 Claude Code、Codex、Cursor 等）和安装权限。
- 中文输出依赖 `plain-chinese` 规则集；本次抓取到的只有 README，分类逻辑细节和 15 条中文规则原文在未抓取的 SKILL.md 里，无法据此复现全部规则。
- 阶梯 4 只写分镜，渲染依赖外部视频工具（showtime 0.4.0+）。

## 操作步骤
1. 选定一个需要被准确理解的对象。前提：你手里有具体文本，且有真实读者。预期结果：得到一个明确的改写对象，而不是泛泛地“让模型写得更好”。

2. 先用最低成本方式重写：受控英语或“80% 到 ASD-STE100”。
   - 做法 A（原文做法，只给规范名称）：按原文做法，直接在提示词里写 ASD-STE100。原文原样指令：
     ```
     Ask your LLM to explain something in ASD-STE100.
     ```
     落地时可以写成：
     ```
     Explain <要解释的内容> in ASD-STE100.
     ```
   - 做法 B（调研中的推断做法，把规范文本放进上下文）：用于模型本身不熟悉该规范时。前提：你自备规范文本；本次材料没有规范内容。
   - 做法 C（零安装最小试用，调研给出的可复制提示词）：调研称它是 Karpathy 的“80%”加上最关键的一条规则：
     ```
     Write about 80% of the way to ASD-STE100: one idea per sentence, one term per meaning, active voice, no filler. Cut nothing — keep every fact, number, condition, and hedge; just make the sentences clean.
     ```
     前提：把原文一并给模型。预期结果：得到一版更干净的文本，且不删事实、数字、条件、限定词。
   - 怎么选：想最小试，先用做法 C，因为不需要安装、可复制；如果你的目标就是检验模型是否真的按 ASD-STE100 规范写，并且你能提供规范文本，用做法 B；只想复现原文最短指令则用做法 A。做法 A 最简单，但无法确认模型是真的按规范写，还是只把句子改短、改简单。三者共同预期：输出应保留每个事实、数字、条件、限定词，只是句子更干净。

3. 如果问题不只是“文本难读”，而是“该用什么形式解释”，安装 understanding-ladder 技能（可选，进阶）。前提：使用支持 Agent Skills 的客户端（原文列出 Claude Code、Codex、Cursor 等），有安装权限。安装三选一：
   - 通用方式：
     ```bash
     npx skills add ChangWenC/understanding-ladder
     ```
   - Claude Code 插件：
     ```text
     /plugin marketplace add ChangWenC/understanding-ladder
     /plugin install understanding-ladder@understanding-ladder
     ```
   - 手工克隆到 Claude Code 全局 skills 目录：
     ```bash
     git clone --depth 1 https://github.com/ChangWenC/understanding-ladder.git
     cp -r understanding-ladder/skills/* ~/.claude/skills/
     ```
   预期结果：技能靠 description 自动命中。可直接提问触发，原文给的示例：
   ```text
   Help me understand how learning rate affects convergence.
   Explain the TLS 1.3 handshake the clearest way.
   An agent wrote this plan — help me see what it actually does.
   Walk me through the Fourier series from rung 1 to rung 4.
   ```

4. 让它按内容类型自动选最低够用的阶梯。前提：已安装技能，或你愿意手工按映射表要求模型。核心分派表：
   | 内容类型 | 阶梯 | 输出形式 |
   |---|---|---|
   | 定义、事实、流程 | 阶梯 1 | 文本（英文约 80% ASD-STE100，中文用 `plain-chinese`） |
   | 过程、因果、状态、组件 | 阶梯 2 | 图表（Mermaid / SVG + “这张图怎么读”） |
   | 某个参数会改变结果 | 阶梯 3 | 单文件 HTML，带滑块，双击即可打开 |
   | 随时间展开的推导 | 阶梯 4 | 视频：出分镜 + 旁白，交给 showtime ≥ 0.4.0 用 `--from-storyboard` 渲染 |
   预期结果：输出形式刚好够回答问题。注意：选择最低的、足以完整回答问题的阶梯，不要爬得比问题需要得更高；如果一条简单定义被做成动画视频，说明分派逻辑没生效。

5. 遵守三条贯穿所有阶梯的规则。前提：无论用哪个阶梯，都先有可检查的阶梯 1 文本草稿。三条规则是：
   - 不删内容：用简单语言，不是更少内容；每个数字、条件、限定词都要留下。
   - 先出草稿：任何图表、页面、视频都从一份可检查的阶梯 1 文本草稿开始。
   - 结尾附“该检查什么”。
   预期结果：每个图表、页面、视频都能回溯到事实完整的文本草稿，末尾有检查清单。注意：这三条是作者倡导的做法，没有对照实验。

6. 阶梯 4 渲染（如果用到）。前提：已装 showtime 0.4.0+。技能只负责写 storyboard，渲染由外部视频工具完成，例如：
   ```text
   showtime new <template> <dir> --from-storyboard storyboard.md
   ```
   （原文说明支持英文或中文表头。）预期结果：得到可播放的视频，但渲染质量与事实正确性仍要人工检查。

7. 把改写结果和原解释并排给人读。目的不是“读起来更顺”，而是看读者是否更快、更少追问地得到正确理解。前提：有 2–3 位不了解背景的读者。预期结果：得到一组可比较的读者反馈，进入下一节判断。

## 怎么判断变好了
最小试用方式：
1. 零安装先做：挑一份你自己写的、事实密集的技术说明或状态更新，把“80% 到 ASD-STE100”提示词连同原文一起丢给模型，让它重写。
2. 或按原有做法：让同一个模型产出两版：一版不加约束，一版明确要求用 ASD-STE100 写。
3. 找 2–3 位不了解背景的同事各读一版，做两件事：
   - 记录读完所需时间和中途提问次数；
   - 让对方用自己的话复述一遍，标出与原意不符的点。
4. 进阶试用：按操作步骤安装 skill 后，分别拿三类内容各一条去问——一条定义/事实、一条流程或因果关系、一条含“某个参数会改变结论”的说明——观察它是否分别落到文本、图表、交互页，以及有没有把简单问题过度升级成 HTML 或视频。

可观察指标：
- 事实保全：逐条比对原文与产出，数字、条件、限定词是否一个没少。这是原文最强调的一条，也是最容易失败的一条。
- 理解成本：需要追问的次数是否下降；读完需要多久。
- 复述时出现的事实性偏差数量是否减少。
- 同一段内容被不同读者复述出的版本是否更一致（一致性是受控语言的主要卖点）。
- 形式是否够用而非过度：产出形式是不是刚好够回答问题；如果一条简单定义被做成了动画视频，说明分派逻辑没生效。
- 警惕反向效果：特意在内容里留一个错误或遗漏，看自己是否因为产出“看起来精致”而漏检——这正是原文所说的“精致产出降低警惕”。
- 代价项：文本是否变得过于生硬、信息是否有丢失。

失败信号：简化时丢掉了限定词和条件；或者阶梯选择总是往上跳，把任何输入都做成图和视频。

试多久：本次材料没有给出时长。建议至少完成一轮上述对照（同一份内容、2–3 位读者）后，再决定是否扩大到更多文本或团队范围。注意：原文没有提供任何基线数据，所以只能做自建的前后对照，不要引用本条线索去声称“已被验证有效”。

## 常见坑
- 把热度当效果：调研给出的互动数据是 likes 24173、reposts 3078、replies 717，仓库星标 30。这只说明受关注度高，不构成效果证据。
- 把“更简单”当成“符合规范”：如果模型不熟悉 ASD-STE100，这条指令可能只产生更简单、更短的句子，而非真正符合规范（推断，原文未验证）。
- 把“80% 到 ASD-STE100”当成完整标准：它自称是 80%，不是完整 ASD-STE100；`plain-chinese` 也只是轻量规则集，不是完整写作标准。
- 忽略受控语言的代价：它通常牺牲表达丰富度和自然度，换取一致性与低歧义（常识性推断，原文未提及）。因此更可能适用于需要跨读者一致理解的技术说明类文本，而不是所有写作。
- 只给规范名称、不给内容：原文只给了规范名称，没有提供规范内容。需要走做法 B 时，要自备规范文本并放进上下文。
- 忘记事实保全：简化时丢掉了限定词、条件、数字、限定词，是最容易失败的一条；不删内容这条规则要优先检查。
- 被精致产出降低警惕：更容易理解 ≠ 已验证；动画里的错误比文字里的错误更有说服力。每个输出都应附“该检查什么”。
- 阶梯选择总是往上跳：简单定义也做 HTML 或视频，说明没有按内容类型选择最低够用阶梯。
- 以为安装技能就万事俱备：核心分类逻辑和 15 条中文规则在未抓取的 SKILL.md 里，本材料无法据此复现全部规则。
- 阶梯 4 误以为技能负责渲染：技能只写 storyboard，渲染依赖外部视频工具 showtime 0.4.0+。
- 把截断线索当完整方法：原文被截断在第二个句子中途，ASD-STE100 的来源领域、完整技巧列表、后续 tips 全部缺失。
- 直接写成团队规范：调研结论明确说，原文只剩作者个人经验且无任何效果数据，只适合小范围试，不宜直接写成手册定稿。
