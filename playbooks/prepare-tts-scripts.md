>
> 解决的问题：解决文稿直接丢给 TTS 后出现念稿感、标签被大声读出、笑声和语气不按预期执行的问题，用免费 lint、语速校准和固定 seed 的 A/B 在消耗额度前先验证。

## 解决什么问题

把文稿直接丢给 TTS，常见结果是听起来像念稿、标签被大声读出、笑声或语气没有按预期执行。本手册把 tts-director 作为一个可安装到 Claude Code（或其他能读取 `SKILL.md` 的 agent）的技能，要求在送 TTS 前先做节拍图、口语化重写和标签预算，再用免费 lint、语速校准、固定 seed 的 A/B 与转写核验，把能免费发现的问题先修掉，再决定是否消耗额度做完整配音。

## 适用与不适用

适用：
- 你使用 Claude Code，或使用其他能读取 `SKILL.md` 的 agent。
- 你要把口播/视频脚本送进 TTS，尤其是 ElevenLabs v3/v4。
- 你有 Python 3.9+ 环境，愿意先跑 lint、再做小范围 A/B，并接受人耳听感作为最终判断。
- 其他 TTS 服务可以按仓库指南适配，但原文只给指南，没有同等脚本支持。

不适用：
- 你想找的是一个 TTS 引擎替代品；tts-director 不是 TTS 引擎，它做的是送进 TTS 前的重写和标注。
- 你用的模型会把标签大声读出来，却仍想直接套用标签方案；应先去掉标签或换模型。
- 你没有 ElevenLabs API key、voice ID 或额度，却想直接做真实 A/B；可以先做 dry-run 和免费 lint。
- 你需要可直接复制的提示词模板；原文没有给出。
- 原文以波斯语 README 为主、支持英语；其他语言没有给出同等说明，先小范围验证。

## 前置条件

- Python 3.9+。
- Claude Code 或其他能读取 `SKILL.md` 的 agent。
- 仓库无依赖；`ffmpeg` 可选，用于生成后调速度。
- 真实 A/B 需要 `ELEVENLABS_API_KEY`、voice ID 和可用额度。
- 一条准备送 TTS 的脚本；如果要校准语速，再准备一条自己声音的成品录音。

## 操作步骤

1. 安装为 Claude Code 技能（做法 A：个人技能；做法 B：项目技能）。前提：本机有 git 和 Python 3.9+。做法 A 执行：
```bash
git clone https://github.com/aligh98/tts-director ~/.claude/skills/tts-director
```
做法 B 是把同一仓库克隆到项目的 `.claude/skills/` 下；原文只给出个人技能的完整命令，项目路径是同一仓库的另一种放置方式。预期结果：agent 能读取该 skill。README 说当文本要进 TTS，或要求声音更有人味、更有能量时，技能会自动激活；这是作者说明，不是独立验证。

2. 先画节拍图，再改写。前提：已有一条待处理脚本。逐行标出每句话的角色，例如 hook、引入、列表项、金句、笑话、行动号召。预期结果：你知道每一句在听觉上要完成什么任务，而不是直接逐句润色。原文没有给出可直接复制的提示词模板，这一步不要期待复制一段 prompt 就完成。

3. 按“给耳朵写”重写，并设标签预算。前提：节拍图已完成。把文稿改成口语化、短句，把关键词放到句尾，加入真实口语填充词（原文例子是波斯语的「وای」「ببین」「دیگه」），但不改变原文事实。标签预算按作者给的数字：约每 3–4 句一个标签；每条 reel 0–2 次笑，只在真人会笑的地方；每 8–12 秒做一次语气变化，例如耳语、叹气或停顿。标签即使正文是波斯语也用英文写。不要写文本「هاها」，改用 `[laughs]` 或 `[chuckles]`。v3/v4 不识别 `<break>`，改用 `...`。预期结果：得到一版可送 lint 的脚本；这些数字是作者预算，不是独立评测结论。

4. 先跑免费 linter，不消耗 TTS 额度。前提：skill 已安装，脚本文件已准备好。把示例文件换成你的脚本：
```bash
python scripts/tag_lint.py examples/reel-fa.txt --model eleven_v4 --tempo 1.15
```
它检查过度打标签、笑声过多或过近、文本「هاها」、视频开头说「سلام」，以及模型特有问题，例如 v4 上的 SSML，或在不支持标签的模型上使用标签。预期结果：拿到问题清单，先改到 lint 通过或问题可解释，再考虑真实生成。

5. 用一条成品录音校准真实语速（可选）。前提：你有一条自己声音的已完成录音。执行：
```bash
python scripts/tag_lint.py script.txt --calibrate voice.mp3
```
预期结果：按你真实说话速度校准后续判断，而不是凭感觉猜语速。

6. 按模型差异选择做法。前提：你知道自己要用的 ElevenLabs 模型。做法 A：用 `eleven_v4`。它会忽略速度与 style 设置，只对 stability 有反应；速度可在生成后用 ffmpeg 调整：
```bash
ffmpeg -af atempo=1.1
```
README 称该方式不改变音高。做法 B：用 `multilingual_v2`、flash、turbo。这些模型会把标签大声读出来，不应直接套用标签方案；按指南去掉标签或换模型。预期结果：不会在 v4 上调速度和 style 等一个不会发生的变化，也不会在会读标签的模型上把标签写进正文。

7. 对敏感句子先做 A/B dry-run。前提：选一句容易听出差异的句子，准备两个版本；dry-run 不发送请求，不消耗 TTS 额度。执行：
```bash
python scripts/ab.py "[excited] وای! فقط تا جمعه وقت داری!" "وای... فقط تا جمعه وقت داری!" --stability 0.35 --stability 0.5 --out probe --dry-run
```
预期结果：先看到成本，再决定是否真实生成。

8. 真实生成并转写核验。前提：已确认成本可接受，已设置 `ELEVENLABS_API_KEY`、voice ID，并有可用额度。执行：
```bash
export ELEVENLABS_API_KEY=...
python scripts/ab.py "[excited] وای! فقط تا جمعه وقت داری!" --voice YOUR_VOICE_ID --lang fa --en-check --out probe
```
README 说所有版本用同一 seed，便于公平比较；`--prev`、`--next` 把前后文作为上下文；`--lexicon words.tsv` 用「书写<TAB>口语」文件修正专名和外语词发音；`--en-check` 额外用英文转写以发现被读出的英文标签。预期结果：生成版本后，把每个片段转成文本，确认哪个标签被大声读出、哪个笑声真的执行。注意：转写只能证明笑声执行了；声音是否真的兴奋，只能靠人耳判断。原文真实生成示例只给了一个文本参数；如果要比较两个版本，先按仓库 README 确认参数，不要凭空改写命令。

9. 跑离线测试（可选）。前提：已克隆仓库。执行：
```bash
python -m unittest discover tests
```
预期结果：确认仓库自带测试能跑通；这不等于你的配音效果已被验证。

## 怎么判断变好了

最小试用：选一条准备用于 TTS 的短脚本，安装 skill 或直接运行脚本；先跑 `tag_lint.py`，修掉过度标签、过近笑声、文本「هاها」、开头「سلام」和模型特有问题；如有一条成品录音，用 `--calibrate` 校准语速；再选一句敏感句，用两个版本跑 `--dry-run`，成本可接受时用固定 seed 真实生成并转写，最后人耳听是否自然、是否有能量。原文没有给出试用时长和量化改善指标；建议先以“一条短脚本 + 一句敏感句”为单位试，记录前后通过/不通过或简单评分，不要直接上完整配音。

可观察指标：
- lint 报告的问题数和类型是否减少。
- 标签密度是否接近每 3–4 句一个。
- 每条 reel 笑声是否控制在 0–2 次。
- 语气变化是否约每 8–12 秒一次。
- 转写是否不再出现标签被读出；笑声是否按预期执行。
- 人耳盲听或前后对比是否认为更自然、更少“念稿感”。

这些指标来自作者给出的标签预算和脚本检查项；“更自然、更有能量”仍是主观判断，原文没有量化结果改善数据。

## 常见坑

- 把 tts-director 当 TTS 引擎。它不替代 TTS，只在文稿送进 TTS 前做重写和标注。
- 在会把标签读出来的模型上用标签。`multilingual_v2`、flash、turbo 会把标签大声读出来；这类模型不应直接套用标签方案。
- 在 `eleven_v4` 上调速度和 style。v4 会忽略速度与 style，只对 stability 有反应；速度用 `ffmpeg -af atempo=1.1` 后处理，README 称不改变音高。
- 用 `<break>`。v3/v4 不识别，改用 `...`。
- 写文本「هاها」。它会被逐字读出，改用 `[laughs]` 或 `[chuckles]`。
- 标签过密、笑声过多或过近。先跑免费 lint，不要先消耗额度。
- 以为转写能证明情绪。转写只能证明笑声执行了；兴奋度要人耳判断。
- 直接真实 A/B。先 `--dry-run` 看成本；真实 A/B 会消耗 ElevenLabs 额度，并需要 API key 和 voice ID。
- 直接把 dry-run 的双文本命令改成真实生成命令。原文真实生成示例只展示了一个文本参数；要比较两个版本，先按仓库 README 确认参数，不要凭空改写。
- 期待复制一段提示词就完成节拍图和重写。原文没有给出可直接复制的提示词模板。
- 把作者主张当已验证结论。「像真人、更有能量」主要是作者主张，没有独立评测；仓库约 31 stars，README 以波斯语为主，英文版内容未给出；效果强依赖 ElevenLabs 模型、声音、语言和人工听感，模型行为也可能变化。
