# 把智能体的计划摊成逐项批注页，你签字后再让它开工

> **未经实测**：本手册由 ai-work-radar 根据自动调研合并生成并持续修订，步骤尚未有人实际跑过。服务修订时基于自己保存的上一版重写，直接改这个文件会被覆盖；实测过的做法请写到 experiences/。
>
> 解决的问题：解决智能体在聊天里丢一堵计划墙、你逐条回复容易漏，且它可能把空回答当成同意或擅自开工的问题。
> 先试这一步：装好 skill 并重启会话后，拿一个含 3–5 个决策点的真实计划任务，用 `pack it into a page` 触发页面，故意留一个空回答框，确认它不会把空框当成同意。
> 最近修订：2026-11-01

## 解决什么问题

智能体带着计划来时，常把一堵嵌套列表丢在聊天里，末尾问一句“这几项你怎么定”。人要在长文本里逐条找、逐条回，容易漏、容易烦；更危险的是，智能体可能把“没回答”当成“同意”，或者你刚在计划上点了头，它就擅自开工。这篇手册的流程是：让智能体把计划生成为一个本地可视化页面，每个条目下面留回答框，你逐项批注；它按轮次读取回答、回显改了什么或为什么没改；只有你明确下令，它才动手。

## 适用与不适用

适用：

- 任何“智能体带计划来”的中等规模任务。原文点名的例子包括 bot、网站、自动化、视频剪辑；判断标准是计划里有多个需要你逐项确认的决策点。
- 你已经在用 Claude Code 或 Codex，并且愿意多一步“看页面、写批注”的往返。

不适用：

- 普通提问、短计划。原文明确说这些仍走聊天，误用只会增加无谓开销。
- 其他智能体或 IDE：材料只给出 Claude Code / Codex 的适配，别的环境没有依据。
- 你希望页面上的回答直接触发智能体开工：这条流程是反向约束，页面作答只表示同意或修改条目，起工必须由人显式下令。

## 前置条件

- Claude Code 和/或 Codex。
- Python 3.7 或更新；本地服务器只用标准库。
- 一个浏览器；最好是 Claude/Codex 桌面应用的内置浏览器，因为智能体可以在给你看之前自查页面。
- Windows 需在 WSL 里执行下述命令。
- 知道 skill 的安装目录：Claude Code 是 `~/.claude/skills`，Codex 是 `~/.agents/skills`，Codex 也读旧的 `~/.codex/skills/`；项目内则是对应项目下的 `.claude/skills/` 或 `.agents/skills/`。

## 操作步骤

1. 取回仓库。

前提：本机已装 git，且当前目录可写。
预期结果：得到 `visual-review-page/` 目录，里面还有一层同名文件夹，那一层才含 `SKILL.md`。

```bash
git clone https://github.com/pavel-molyanov/visual-review-page.git
```

2. 安装。先选做法：日常多个项目都用，选全局安装；只想在单个项目里试，选项目内安装。选一种即可，装完都要重启智能体会话。

做法 A：Claude Code 全局安装

```bash
mkdir -p ~/.claude/skills && cp -R visual-review-page/visual-review-page ~/.claude/skills/
```

做法 B：Codex 全局安装

```bash
mkdir -p ~/.agents/skills && cp -R visual-review-page/visual-review-page ~/.agents/skills/
```

项目内安装：把内层 `visual-review-page/`（含 `SKILL.md` 的那层）拷进该项目的 `.claude/skills/` 或 `.agents/skills/`。用 ZIP 下载的，解包后同样拷内层文件夹。

预期结果：skills 目录下出现 `visual-review-page/SKILL.md`；skill 与你自己的 skill 并列，只有你要求“可视化展示计划”时才启用。

3. 重启会话并确认加载。

前提：上一步已拷贝完成。
预期结果：重启后能在 `/skills` 或等价入口里看到它。看不到就检查是不是拷了外层文件夹、是不是忘了重启。

4. 触发页面。智能体带着计划来时，对它说原文给的任意一句：

```text
show it visually
```

```text
pack it into a page
```

```text
present the solution
```

前提：任务是中等规模、有多个决策点的计划，不是普通提问或短计划。
预期结果：智能体在项目某个文件夹里生成页面，起一个小本地服务器，并用内置浏览器打开；若智能体没有浏览器，你自己打开它打印的 `http://127.0.0.1:<port>/`。

5. 逐项批注。在各条目下的回答框里写答复，边打字边保存。

关键约束：空框表示“未回答”，绝不等于“同意”。有意见就写，没意见也要明确表态，不要用沉默代替同意。
预期结果：回答写入页面文件夹的 `answers.json`，智能体像读聊天消息一样读取，其余不外传。

6. 回聊天说“答完了”。用任意说法告诉智能体你答完了。

预期结果：它读回答、改页面，并在每条回答上方显示改了什么或为什么没改；已同意的条目折叠，回答框清空进入下一轮；上一轮的回答保留为 `answers-<round>.json`。检查这三件事是否都发生。

7. 只在明确下令后才开工。

前提：你已经看完修订后的页面，确认可以动手。
预期结果：页面上的回答只表示同意或修改条目，永远不触发起工；你显式下开工指令后，它才开始工作。若它在你下令前动手，记为一次起工纪律失败。

8. 更新时先删再拷，避免旧版本残留文件。

```bash
git -C visual-review-page pull
rm -rf ~/.claude/skills/visual-review-page && cp -R visual-review-page/visual-review-page ~/.claude/skills/
```

Codex 用户把第二行的 `~/.claude/skills` 换成 `~/.agents/skills`。
预期结果：skills 目录里只剩新版本文件，不出现旧版残留。

## 怎么判断变好了

最小试用方式，半天内可完成：

1. 按步骤 1–3 装好并重启会话，确认入口里能看到它。
2. 选一个真实的中等规模计划任务，例如一次包含 3–5 个决策点的改动方案，先照常用聊天方式让智能体给计划，记下这次表现作为基线。
3. 换一个同类任务，用 `pack it into a page` 触发页面，逐项批注，其中故意留一个空框，验证空框确实不被当成同意。
4. 回聊天说“答完了”，检查：它是否读到全部回答；每个答复上方是否标了“改了什么/为什么没改”；已同意项是否折叠、框是否清空、`answers-<round>.json` 是否生成。
5. 只在你确认后再显式下开工指令，观察它是否在你下令前不动手。

试多久：建议 3–5 次试用后再判断；只试一次容易被单个任务的复杂度干扰。

可观察指标。这些是按调研报告建议自定的试用指标，原文未提供：

- 往返轮数：从“智能体首次给计划”到“人可以开工”之间的消息轮数，与聊天基线对比。
- 澄清成本：同一任务中聊天里追问、重述的条数。
- 误改率：最终交付中因理解偏差需要返工的决策点数。
- 遗漏率：你实际有意见但未被处理的条目数；页面模式下应接近 0，因为每项都有框。
- 作答完成度：已回答框除以总条目数，以及“空框被误判为同意”的次数，后者应恒为 0。
- 起工纪律：在你未显式下令前智能体擅自开工的次数，应为 0。

判断：若 3–5 次试用后往返轮数与返工率没有下降，或页面生成质量不稳定、经常退回文字墙，把它的采用状态下调为 study，继续观察，不要继续硬推。

## 常见坑

- 对普通提问和短计划也触发页面。原文明确不适用，会增加无谓开销。
- 把空回答框当成同意。空框只表示“未回答”，不是默许；要么写意见，要么明确表态。
- 以为在页面上答完就会自动开工。页面作答只做同意或修改，起工必须由人显式下令。
- 拷错文件夹。要拷的是内层含 `SKILL.md` 的那层，不是仓库最外层。
- 装完不重启会话，导致 skill 没加载。
- Windows 不在 WSL 里执行命令。
- 更新时只拷不删，旧版本残留文件继续生效。
- 页面文件夹散落在项目里，长期使用需要自己做 `.gitignore` 与清理约定；原文只提到智能体默认不把页面文件夹提交进版本库，若你习惯全量提交，要自己加进 `.gitignore`。
- 页面质量取决于智能体是否遵守 `SKILL.md`，原文没有给出失败模式的兜底；遇到经常退回文字墙，按上面的判断标准降级。
- 把隐私承诺当成已经审计过的结论。原文的隐私说明是仅监听 `127.0.0.1`、校验 Host 头、回答只写本地 `answers.json`，属于作者声明加代码实现，材料未提供代码审计结论。
