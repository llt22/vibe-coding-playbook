## 解决什么问题

解决离开工位或切换设备时，不想在云端重开一个没有上下文的白板会话，而是让手机接管本地正在运行的 Claude Code 会话，尽量延续同一段上下文。原文把这种用法描述为「把手机当成终端的遥控器」，底层逻辑是「本地进程不杀」。

## 适用与不适用

适用：

- 需要长上下文连续、且依赖本地开发环境的场景。
- 会从工位切到手机继续同一个开发会话。
- 本地终端里的 Claude Code 会话能持续存活、不被杀掉。

不适用或暂不适用：

- 本地进程无法长期存活，例如终端关闭、笔记本休眠或进程被杀。
- 当前 Claude Code 版本没有 /rc 命令，或终端没有出现可扫码入口。
- 需要把流程直接写进团队标准操作，但扫码之后的步骤和边界条件还没验证。
- 原文在「手机扫码接管 →」处被截断，扫码后的流程缺失，因此不适合把未验证部分当成固定做法。

## 怎么判断变好了

最小试用方式：

1. 在一次本地 Claude Code 会话中先聊几轮。
2. 植入一条只有该会话知道的信息，例如临时约定一个词。
3. 在终端输入 /rc。
4. 用手机扫码接管。
5. 在手机上追问那条信息。

可观察指标：

- 上下文连续性：手机端能否回答出只有本地会话才知道的信息。这是原文价值的核心检验点。
- 进程存活性：接管期间与结束后，本地终端进程是否仍然存活，没有被中断。
- 可逆性：从手机切回本地终端后，能否继续同一会话。
- 可复现性：是否每次都能成功；失败时记录 Claude Code 版本和报错信息。
- 支持性：/rc 是否存在、是否有二维码出现；若不存在，记为不适用。
