> 解决的问题：当你想把分类、门禁、排序这类判断从通用大模型里拆出来，用更便宜的决策模型降本提速时，如何做一次可对照、可回退的小范围实验。

## 解决什么问题
把“是否通过 / 属于哪类 / 打几分 / 怎么排序”这类门禁与排序判断从通用大模型里拆出来，用决策模型跑一次可对照、可回退的小范围实验；本手册只覆盖这个实验怎么做，不覆盖直接上生产。

## 适用与不适用
**适用**：能表达成分类、是/否、评分或排序的工作，例如垃圾邮件判定、建议标签、优先级与排序、退款请求判定、检索重排。同一个 state 可以带多个问题，问题并行求值，发很多问题和只发一个耗时相近。
**不适用**：数字、日期和对抗性内容；需要给出判断依据或解释的任务（输出只有浮点数）；高风险场景，例如给求职者排序——浮点数会掩盖看不见的偏差，而且事后拆解偏差很困难。原文没有涉及时间、事件、状态触发或持续运行，因此也不适合据此设计持续运行的任务。

## 前置条件
- 能跑 LLM CLI 的环境，已安装 LLM CLI 和 llm-typesafe 插件；原文只给了基本用法，其他查询类型的例子在插件 README 里。
- 一个可表达的 state：字符串、字符串数组，或一组 name-value 键值对。
- 准备好的问题：是/否陈述、选项集合，或带描述的数值等级。
- 100–200 条已知正确答案的历史样本，用于和现有方案做对照。
- 若走 API：原文没有给出注册、鉴权、API endpoint 等细节，只有使用形态和一条 CLI 示例；这些需要自行从插件或服务方补齐，本手册无法给出可靠步骤。

## 操作步骤
1. **选任务并确定问题类型。** 前提：任务能表达成分类、是/否、评分或排序。预期：你明确要问的是以下哪一种——是/否问题（Noul，返回 0–1 的浮点数，表示模型认为该陈述为真的置信度）、选择问题（Choice，从给定选项里选一个，实际返回置信度分数加上在所有选项上的概率分布）、评分问题（Score，提供一串带描述的数值等级，返回落在该区间内的浮点分数）。做法选择：单条记录的门禁、打标、优先级用做法 A；检索结果重排用做法 B。

2. **构造 state。** 前提：有原始记录。做法：把记录整理成一个字符串、一个字符串数组，或一组 name-value 键值对。预期：这个 state 作为唯一输入，后面所有问题都基于它提问。例如，退款判断可以用：
```text
state（字符串）: Please refund my last payment.
问题（是/否）: Does this message explicitly request a refund?
```

3. **做法 A：跑单条是/否判断。** 前提：已安装 LLM CLI 和 llm-typesafe 插件。命令：
```bash
llm -m jev 'Please refund my last payment.' \
  -s 'Does this message explicitly request a refund?' 
```
预期：返回 0–1 浮点数，表示模型认为该陈述为真的置信度。注意：原文没有给出注册、鉴权、API endpoint 等 API 侧细节，只有使用形态和这条 CLI 示例；如果不用 CLI，需要自行从插件或服务方补齐。

4. **一次提交多个问题。** 前提：问题能塞进上下文窗口。做法：同一个 state 配多个问题；原文说问题并行求值，发很多问题和只发一个耗时相近。预期：一次拿到多个判断。限制：原文没有给出多问题的具体 CLI 语法，其他查询类型的例子在插件 README 里。

5. **做法 B：检索重排。** 前提：已有检索结果和原始 query。做法：先用便宜的算法（如 BM25）取出约 100 个可能匹配项，再让 Jev 针对原始 query 给这 100 个候选逐个打相关性分数并重排。预期：得到按相关性分数重排的列表。说明：原文说这是作者“I've been experimenting with it”，没有给任何指标，所以只适合小范围试，不要直接当生产排序。

6. **规避已知弱项。** 前提：判断涉及数字、日期或对抗性内容。做法：不要把这类判断交给它。预期：避免把已知不擅长的任务纳入实验。依据：Jev 1.13 的 jaggedness 文档。

7. **做对照实验。** 前提：有 100–200 条已知正确答案的历史样本。做法：按字符串/字符串数组/键值对构造 state，配上对应问题；跑 Jev 拿到 0–1 浮点数或概率分布，按阈值转成判断；同一批样本用你现有的方案再跑一遍。预期：得到两套结果，可以算一致率/准确率和相对变化。若做检索重排，对比前 k 条的命中情况。

8. **做偏差对照。** 前提：样本里包含姓名、性别、地区等标记。做法：把这些标记替换成对照版本，看分数是否出现系统性偏移。预期：发现潜在偏差提示。注意：原文里作者拿湾区各城市问“Good city?”得到 Cupertino 最高、East Palo Alto 最低，是单次非正式实验，他自己也说“Huh”，只能作为存在潜在偏差的提示，不能当作偏差结论。

9. **固定成回归集。** 前提：上面的样本集已经跑通。做法：因为价格低，把样本集固定成回归集，改问题措辞时重跑。预期：每次改问题都能看到结果是否漂移。

10. **评估方式优先于常规 LLM 项目。** 前提：你准备认真用这个判断。做法：因为输出只有浮点数、无法要求解释，作者建议评估和结构化实验比常规 LLM 项目更重要；好在成本极低，跑几百甚至几千次实验提示只要几美分。预期：用结构化实验替代“看输出感觉对不对”。

## 怎么判断变好了
可观察指标：
- 与人工标签的一致率/准确率。
- 相对当前方案的变化幅度。
- 每千次调用成本。
- p95 延迟（注意多问题并行、耗时接近单问题）。
- 偏差对照样本上的分数差。
- 做检索重排时，和原排序对比前 k 条的命中情况。

最小试用方式：挑一个你现在用通用 LLM 做的、能表达成是/否或分类的门禁任务（例如“这条消息是否明确要求退款”），取 100–200 条你已知正确答案的历史样本，按字符串/字符串数组/键值对构造 state，配上对应问题，跑 Jev 拿到 0–1 浮点数或概率分布，按阈值转成判断；同一批样本用现有方案再跑一遍作对照。若做检索重排，BM25 取约 100 个候选，让 Jev 对原始 query 打分重排，和原排序对比前 k 条命中。

试多久：原文没有给出时间长度；跑完一轮固定样本对照即可初步判断。因为便宜，可以把样本集固定成回归集，改问题措辞时重跑。
