# 把简单判断交给快脑前，先做一次可回退的小范围验证

> **未经实测**：本手册由 ai-work-radar 根据自动调研合并生成并持续修订，步骤尚未有人实际跑过。服务修订时基于自己保存的上一版重写，直接改这个文件会被覆盖；实测过的做法请写到 experiences/。
>
> 解决的问题：如何用可对照、可回退的小范围实验，验证把简单判断交给 Jev 决策模型或 Claude Code 的 jev-mcp 快脑分流是否真的改善工作流。
> 先试这一步：挑一个你现在用通用 LLM 做的是/否门禁任务，取 100–200 条已知答案的历史样本，按字符串 state 跑一次 Jev 与现有方案的对照。
> 最近修订：2026-10-14

## 解决什么问题
把“是否通过 / 属于哪类 / 打几分 / 怎么排序”这类门禁与排序判断从通用大模型里拆出来，用决策模型跑一次可对照、可回退的小范围实验；也可以把简单判断作为初筛交给快脑，让大模型只处理难题。本手册覆盖这两条路线的实验怎么做，不覆盖直接上生产。

## 适用与不适用
**适用**：能表达成分类、是/否、评分或排序的工作，例如垃圾邮件判定、建议标签、优先级与排序、退款请求判定、检索重排。同一个 state 可以带多个问题，问题并行求值，发很多问题和只发一个耗时相近。也适用于 Claude Code 工作流里“简单请求先由快脑挡掉、难题再叫大模型”的分流实验。
**不适用**：数字、日期和对抗性内容；需要给出判断依据或解释的任务（输出只有浮点数）；高风险场景，例如给求职者排序——浮点数会掩盖看不见的偏差，而且事后拆解偏差很困难。原文没有涉及时间、事件、状态触发或持续运行，因此也不适合据此设计持续运行的任务。Claude Code 插件路线原文截断，安装配置不完整，不适合要求可控、可审计链路的团队直接上生产。

## 操作步骤

1. **选任务并确定问题类型。** 前提：任务能表达成分类、是/否、评分或排序。预期：你明确要问的是以下哪一种——是/否问题（Noul，返回 0–1 的浮点数，表示模型认为该陈述为真的置信度）、选择问题（Choice，从给定选项里选一个，实际返回置信度分数加上在所有选项上的概率分布）、评分问题（Score，提供一串带描述的数值等级，返回落在该区间内的浮点分数）。做法选择：单条记录的门禁、打标、优先级用做法 A；检索结果重排用做法 B；在 Claude Code 里想让简单请求先被快脑挡掉用做法 C。

2. **构造 state。** 前提：有原始记录。做法：把记录整理成一个字符串、一个字符串数组，或一组 name-value 键值对。预期：这个 state 作为唯一输入，后面所有问题都基于它提问。例如，退款判断可以用：
```text
state（字符串）: Please refund my last payment.
问题（是/否）: Does this message explicitly request a refund?
```

3. **做法 A：跑单条是/否判断。** 前提：已安装 LLM CLI 和 llm-typesafe 插件。命令：
```bash
llm -m jev 'Please refund my last payment.' \
  -s 'Does this message explicitly request a refund?' 
```
预期：返回 0–1 浮点数，表示模型认为该陈述为真的置信度。注意：原文没有给出注册、鉴权、API endpoint 等 API 侧细节，只有使用形态和这条 CLI 示例；如果不用 CLI，需要自行从插件或服务方补齐。

4. **一次提交多个问题。** 前提：问题能塞进上下文窗口。做法：同一个 state 配多个问题；原文说问题并行求值，发很多问题和只发一个耗时相近。预期：一次拿到多个判断。限制：原文没有给出多问题的具体 CLI 语法，其他查询类型的例子在插件 README 里。

5. **做法 B：检索重排。** 前提：已有检索结果和原始 query。做法：先用便宜的算法（如 BM25）取出约 100 个可能匹配项，再让 Jev 针对原始 query 给这 100 个候选逐个打相关性分数并重排。预期：得到按相关性分数重排的列表。说明：原文说这是作者“I've been experimenting with it”，没有给任何指标，所以只适合小范围试，不要直接当生产排序。

6. **做法 C：在 Claude Code 里试 jev-mcp 快脑分流。** 前提：本机已安装并能正常使用 Claude Code；网络可访问 GitHub。原文把 JEV 描述为“快速直觉脑”，Claude 描述为“缓慢思考脑”，两者通过 `jev-mcp` 插件连接；本质是让便宜快速的模型做前置初筛，贵的大模型只处理通过筛选的难题。
   - **6.1 添加插件市场。** 原文给出的唯一一条完整、可直接复制的命令：
```text
/plugin marketplace add rashedInt32/jev-mcp
```
   在 Claude Code 会话中执行，预期会把 `rashedInt32/jev-mcp` 注册为一个插件来源。
   - **6.2 安装并启用该插件。** 原文截断，只留下 `/plugin` 开头：
```text
/plugin
```
   原文到此处中断。后续是 `/plugin install ...` 还是走交互菜单、插件名是什么、是否需要 API key，原文没有给出。这一步必须先到 `rashedInt32/jev-mcp` 仓库 README 里确认，不要凭猜测补命令。
   - **6.3 确认 MCP 已被 Claude Code 识别。** 按 Claude Code 常规方式查看已加载的 MCP 服务/插件列表，确认 `jev-mcp` 处于已启用状态。
   - **6.4 准备快脑所需的外部条件。** 原文只说 JEV 是“快速直觉大脑”，未说明它是本地小模型还是远程服务、是否要单独配 key、是否要指定模型名。装之前先在仓库文档里确认依赖，否则可能装上了也跑不起来。
   - **6.5 用一个已知的简单任务和一个已知的难题各跑一次。** 观察调用路径是否真的分叉：简单任务有没有被快脑接住而没有惊动大模型；复杂任务有没有被正确放行。

7. **规避已知弱项。** 前提：判断涉及数字、日期或对抗性内容。做法：不要把这类判断交给它。预期：避免把已知不擅长的任务纳入实验。依据：Jev 1.13 的 jaggedness 文档。

8. **做对照实验。** 前提：有 100–200 条已知正确答案的历史样本。做法：按字符串/字符串数组/键值对构造 state，配上对应问题；跑 Jev 拿到 0–1 浮点数或概率分布，按阈值转成判断；同一批样本用你现有的方案再跑一遍。预期：得到两套结果，可以算一致率/准确率和相对变化。若做检索重排，对比前 k 条的命中情况。若试 Claude Code 插件，准备一个明确简单任务和一个明确复杂任务，分别在开启插件和关闭插件两种状态下各跑一遍。

9. **做偏差对照。** 前提：样本里包含姓名、性别、地区等标记。做法：把这些标记替换成对照版本，看分数是否出现系统性偏移。预期：发现潜在偏差提示。注意：原文里作者拿湾区各城市问“Good city?”得到 Cupertino 最高、East Palo Alto 最低，是单次非正式实验，他自己也说“Huh”，只能作为存在潜在偏差的提示，不能当作偏差结论。

10. **固定成回归集。** 前提：上面的样本集已经跑通。做法：因为价格低，把样本集固定成回归集，改问题措辞时重跑。预期：每次改问题都能看到结果是否漂移。

11. **评估方式优先于常规 LLM 项目。** 前提：你准备认真用这个判断。做法：因为输出只有浮点数、无法要求解释，作者建议评估和结构化实验比常规 LLM 项目更重要；好在成本极低，跑几百甚至几千次实验提示只要几美分。预期：用结构化实验替代“看输出感觉对不对”。

## 怎么判断变好了
可观察指标：
- 与人工标签的一致率/准确率。
- 相对当前方案的变化幅度。
- 每千次调用成本。
- p95 延迟（注意多问题并行、耗时接近单问题）。
- 偏差对照样本上的分数差。
- 做检索重排时，和原排序对比前 k 条的命中情况。
- Claude Code 插件路线：分流是否命中——简单任务有没有被快脑接住而没有惊动大模型；复杂任务有没有被正确放行。分流错误率是最核心的指标。
- Claude Code 插件路线：同一简单任务的延迟、同一批简单任务的 token 消耗或调用次数，开启前后对比。
- Claude Code 插件路线：复杂任务的产出质量、返工次数，与关闭插件时相比不下降。
- Claude Code 插件路线：人工干预次数——插件是否频繁报错、是否需要你手动绕过。

最小试用方式：挑一个你现在用通用 LLM 做的、能表达成是/否或分类的门禁任务（例如“这条消息是否明确要求退款”），取 100–200 条你已知正确答案的历史样本，按字符串/字符串数组/键值对构造 state，配上对应问题，跑 Jev 拿到 0–1 浮点数或概率分布，按阈值转成判断；同一批样本用现有方案再跑一遍作对照。若做检索重排，BM25 取约 100 个候选，让 Jev 对原始 query 打分重排，和原排序对比前 k 条命中。若试 Claude Code 插件，单独执行 `/plugin marketplace add rashedInt32/jev-mcp`，先确认仓库存在、可访问、最近仍有提交；若仓库不可达或已废弃，直接停在这里。按仓库 README 补全安装步骤，单独记录你实际执行的命令，和原文做对照。准备一个明确简单的任务（例如给一批文件按扩展名分类、判断一段文本是不是中文）和一个明确复杂的任务（例如跨多个文件的逻辑重构），分别在开启插件和关闭插件两种状态下各跑一遍这两个任务。回退方式：在插件列表里禁用/移除 `jev-mcp`，回到原生 Claude Code 行为。

试多久：原文没有给出时间长度；跑完一轮固定样本对照即可初步判断。因为便宜，可以把样本集固定成回归集，改问题措辞时重跑。Claude Code 插件建议半天内做完最小试用，随时可回退。判定标准：简单任务被正确拦截 + 延迟或成本下降 + 复杂任务质量不变 → 值得继续用并写进自己的工作流；如果分流经常误判、或需要频繁手动纠正，直接弃用，回到原生 Claude Code。
