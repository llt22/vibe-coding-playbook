# 让 AI 智能体说清依据、动手前等人批准

> **未经实测**：本手册由 ai-work-radar 根据自动调研合并生成并持续修订，步骤尚未有人实际跑过。服务修订时基于自己保存的上一版重写，直接改这个文件会被覆盖；实测过的做法请写到 experiences/。
>
> 解决的问题：AI 智能体给出结论或准备自动执行时，你无法追溯它看了什么、引用了什么、凭什么这么判断，因此不敢真正放手让它做事。
> 先试这一步：先跑 `pip install aisoc-sandbox && aisoc-sandbox demo`，看一条告警走完智能体处理流程，把它的 Investigation Ledger 当成你要抄的字段清单。
> 最近修订：2026-11-02

## 解决什么问题

AI 智能体给出结论时，你说不清它看了什么、引用了什么、为什么这么判断；想让它自动执行，又不敢放手。这篇手册给出一套可运行的参照实现和一份可以直接搬走的验收清单，让你的智能体工作流做到：提示词与工具调用全程留痕、结论必须有据可查否则降级人工、动作默认只预览、人批准后才执行。

## 适用与不适用

**适用**

- 需要“说清 AI 为什么这么判断”的工作：告警分级（给结论、置信度、理由原文）、事件调查、写处置建议、跨数据源取证。
- 想逐步给智能体放开自治权，但需要一条“它凭什么可以自己动手”的判据。
- 有可重放样例、并且愿意把“未测量”如实写出来的团队。

**不适用或要打折扣**

- 一次性的、无后果的问答，不值得为它建这套账本。
- 参照实现 AiSOC 是安全运营专用产品。把它提炼成通用清单是**类比**，调研报告原文写明“迁移到其他工作是类比而非原文验证过的结论”。迁移到写作、客服、数据分析等场景，须自行在小样本上验证。
- 它不依赖前沿模型：报告明确写其默认模型“不是前沿模型”，靠受限工具调用 + 封闭 schema 弥补。你若指望换个更强模型就自动可信，这套做法帮不上。

## 前置条件

- 只想先看一眼：能 `pip install` 即可，无需 Docker。
- 想完整部署参照实现：Docker Compose v2；Docker VM 内 8 GB 内存（full 档 12 GB）、20 GB 空闲磁盘；`python3` 3.9+；`bash`。
- 想直接迁移清单：你已有自己的智能体工作流，并有一批**可重放的样例输入**（对应原文的“厂商形状事件”）。没有可重放样例，“执行权只能靠挣”这一条无法落地。
- 权限：动作的审批人必须持有要求的权限层级，且不能是发起该动作的人。

## 操作步骤

### 做法 A：先把参照实现跑一遍，把它的账本当模板（建议先做）

**步骤 1｜零依赖最小试跑**（前提：只要能 `pip install`，无需 Docker）

```bash
pip install aisoc-sandbox && aisoc-sandbox demo
```

README 称 30 秒内离线把一条告警走完智能体处理流程。预期结果：看到一条告警从输入到“智能体调查 + 记录”的完整路径。这是成本最低的观察入口，**不是**能力证明。

**步骤 2｜完整本地部署**（前提：Docker Compose v2，8 GB 内存、20 GB 空闲磁盘，`python3` 3.9+，`bash`）

```bash
git clone https://github.com/beenuar/AiSOC && cd AiSOC
make up
```

先跑 `make doctor` 检查主机工具、内存、磁盘、端口和各数据存储（方式是查询数据存储，而不是看容器是否在跑）。预期结果：控制台可访问。

Windows 或空白机器可以一行装完依赖：

```powershell
iwr -useb https://raw.githubusercontent.com/beenuar/AiSOC/main/install.ps1 | iex
```

```bash
curl -fsSL https://raw.githubusercontent.com/beenuar/AiSOC/main/install.sh | bash
```

也可以用 GitHub Codespaces 打开仓库，在终端里 `make up`。首次运行会下载约 2 GB 模型到一个 volume，只有 `make clean` 能清除。

**步骤 3｜拿到登录凭据**（前提：已执行 `make up`）

`make up` 会创建 `.env` 并生成其中 15 个密钥（凭据保险库、会话签名密钥、五个服务间凭据、四个数据存储密码），并创建管理员、打印一次密码（生成在本地、只显示一次、不存储）。丢失后：

```bash
make bootstrap ARGS=--reset-password
```

端口被占用不会中断安装：它会发布到空闲端口、打印占用的进程，并随之改变控制台地址。

**步骤 4｜证明它真的能跑**（前提：栈已启动）

```bash
make smoke
```

它会发一条真实事件到 ingest API，让它穿过 Kafka、检测、关联、Postgres，再从公开 API 读回这条告警，每个阶段报 PASS/FAIL。预期结果形如：

```
[PASS] raw telemetry accepted by ingest
[PASS] event traversed the spine and became an alert
PASS: 10/10 stages
```

**步骤 5｜用样例数据观察分流**（前提：已登录控制台）

在向导里按 **Load sample data**：五个场景走真实连接器用的同一条 ingest 路径（不是插入行），故意覆盖从低到严重；标注来源为 `AiSOC`；如果租户已有真实告警就拒绝加载，且不会把 setup 标记为完成。要更大的固定语料：

```bash
make demo
```

它加载**合成**数据集（每行 `is_synthetic = true` 且在控制台标注）。README 明确说这是流水线形状，不是基准、不是客户、不是真实事件——别拿它当效果数字。

**步骤 6｜接入自己的真实数据（推送路线）**（前提：`make ingest-token` 取到凭证；租户由凭证决定，不由 header 决定）

```bash
make ingest-token
```

```bash
curl -X POST http://localhost:8081/v1/ingest/batch \
  -H 'Content-Type: application/json' -H "Authorization: Bearer $AISOC_INGEST_TOKEN" \
  -d '{"connector_id":"edr-1","connector_type":"crowdstrike","events":[{"severity":"high",
       "title":"Encoded PowerShell from Office","host":"WIN-FIN-01"}]}'
```

**步骤 7｜接入真实数据（拉取路线）**（前提：有对应系统凭证）

在 **Settings → Connectors** 配置 90 个点击式连接器之一（Splunk、Sentinel、Elastic、CrowdStrike、Okta、AWS、Kubernetes audit 等有厂商专用归一化与安装文档）；没有厂商配置文件的连接器走通用映射，解析 host、user、source IP。云上另有四个采集器读真实出口：CloudTrail 组织跟踪经 **S3 + SQS 通知**、**GCP Pub/Sub**（Cloud Logging sink）、**Azure Event Hubs** capture、**syslog/CEF** 监听；每个都保留可恢复游标和每轮预算，积压时形成背压而不是淹没 ingest。

**步骤 8｜迁移已有规则**（前提：已有 Splunk 等规则集）

`packages/aisoc-migrate` 负责翻译 Splunk SPL、Sentinel KQL、Elastic EQL，翻不动时**拒绝而不是近似**。README 给出：随附 2005 条 Splunk 规则中 1734 条可译，其中 1711 条是部分翻译。对你的启发：宁可缺一条规则，也不要一条“差不多对”的——后者比缺失更难发现。

**步骤 9｜让规则“挣得”可执行资格**（前提：有可重放的厂商形状事件）

只有当一条规则被厂商形状事件穿过真实连接器与引擎重放、并**被看到触发**，才进入编译规则集。绝不从目录或 `enabled:` 标志推断。反向自检：

```bash
--prove-gate
```

它会回退 Windows 连接器并要求 1687 条 Windows 规则全部静默。注意其含义是“可达”，不是“能检测出攻击”；仍有 2 条规则无法触发（从 119 条降下来，因为无法触发的规则不再计入可执行），两条都在等行为基线，这个棘轮只减不增。

**步骤 10｜让动作默认只预览、人批准后才执行**（前提：想开自动响应时）

由告警触发的 playbook 必须先预览再动作。三重开关必须同时同意——部署、租户、playbook——且每个默认关闭；缺一个就以预览运行，并把计划附在告警上。审批步骤是**可持久暂停**：运行挂起到 Postgres，重启后存活，在批准后恢复，过期则记录结果而不是挂死。审批人必须持有要求的权限层级，且不能是发起该动作的人。

**步骤 11｜换模型或加速**（前提：有 GPU 或自有 provider）

```bash
make up-gpu
make up-host-llm
```

还可以在控制台配自己的 provider（任何本地 OpenAI 兼容端点）。默认随网关发的是 Ollama 上钉死版本的约 2 GB `llama3.2:3b-instruct-q4_K_M`（CPU 推理）；默认安装不会把提示词发往任何地方，模型跑在旁边。

**步骤 12｜让“测量”本身可复算**（前提：想引用它的任何数字）

```bash
make test    # 每个服务的单测
make smoke   # 对运行中的栈跑黄金流水线
make stats   # 重算 README 发布的每个数字
```

README 声称每个计数都从代码树重算，README 与事实不符时 CI 失败。

### 做法 B：把这些构件搬进自己的智能体工作流，当验收清单

前提：你有一个自己的智能体流程和一批可重放样例。以下每条都是类比迁移，报告未在非安全场景验证过。

1. **结论必须带账本**。每次运行记录：提示词、工具调用、引用、结论、token 成本；能导出为字节级一致的签名证据包（提示词以摘要形式）。
2. **依据核验不过就降级**。结论引用了证据里从未出现过的指标时，降级为人工复核，而不是自动关闭。
3. **提示词发送前校验**。原始日志、整包载荷、形似密钥的值在发送前被拒绝，而不是事后脱敏。
4. **受约束的工具调用**。模型只负责选工具、传参数，从不写查询语句；狩猎时模型只填封闭 schema，每个值绑定为参数，因此“根本无法表达一条查询”。
5. **执行权是挣来的**。任何规则或动作要有可重放样例穿过真实链路并被“看着触发”，才进入可执行集合；不能从配置里的开关推断。
6. **按任务评估模型，并设确定性基线**。在同一锁定证据上给每个已配置模型打分，对照一条确定性基线；未出资的行写 *not measured*，永不写 `0`。
7. **输出结构化是被测量过的变量**。约 2 GB 的 `llama3.2:3b` 在 50 条告警上，把回复约束为 JSON 之前可用输出 44 次，约束之后 50 次（方法脚本 `scripts/measure_triage_reliability.py`）。界面上标注是哪条路径答的。
8. **归属清楚**。每份评分卡写明实际服务的模型（网关证明或自报，带显式来源状态）；缺归属、零真实调用或确定性回退的运行，不能当作某个具名模型的成绩。
9. **分母公开，不舒服的方向胜出**。召回把弃权和失败留在分母里；关闭声明带其污染率；压缩率必须给全三个标注过的数字（75.3% 旧分组、33.3% 生产键、24.5% 检测形状 cohort），补标识符时是**收窄**分组而不是放宽。
10. **冻结回放时间**。历史回放时在检索查询里强制证据截止（不是靠提示词），披露模型知识截止，且不能执行真实动作；用新情报重扫旧数据是另一种可排练模式，其发现绝不计为原事件时刻的预测。
11. **“稳定”要有定义和门禁**。一行测试只有满足“每次 PR 都跑、无路径过滤、驱动真实生产路径打真实基础设施、且有一个靠把东西弄坏看它变红证明过”才算 stable。

### 怎么选

- 想建立标准、给团队一个可以指着看的东西 → 走 A。成本：sandbox 约 30 秒；完整部署首次会下载约 2 GB 模型到一个 volume。
- 要在自己领域真正落地 → 走 B，并自行在小样本上验证。A 只提供模板，不提供背书。
- 两者不冲突：常见顺序是先 A 后 B，用 A 的输出当 B 第 1 条的字段清单。

## 怎么判断变好了

可观察的指标（均来自参照实现，迁移后需自行重测）：

- **分阶段 PASS/FAIL**：`make smoke` 打出 `PASS: 10/10 stages`，而不只是“容器起来了”。
- **结构化约束带来的可用率**：50 条告警上从 44 次可用输出到 50 次（`llama3.2:3b`，约 2 GB）。
- **规则棘轮只减不增**：无法触发的规则数从 119 降到 2，且不再计入可执行集合。
- **每个对外数字都可重算**：`make stats` 重算 README 发布的每个数字；未测量写 *not measured*。
- **结论可追溯到具体模型**：每份评分卡写明实际服务的模型与来源状态。

最小试用方式：拿你手上一个真实任务，准备一批可重放样例，只走做法 B 的第 1、2、5、6 条——能不能写出账本、能不能在依据缺失时降级、能不能证明某条规则真的被触发过、能不能给出一条确定性基线。四项做不到，先别扩大自治范围。

试多久：调研材料没有给出时长建议。可用的判据是“跑完一个完整任务批次，并能算出哪些项尚未测量”，而不是按天数计。

## 常见坑

- 把 `pip install aisoc-sandbox && aisoc-sandbox demo` 的 30 秒跑通当成能力证明——它只是最低成本的观察入口。
- 把 `make demo` 的合成数据当基准——每行 `is_synthetic = true`，README 明说不是基准、不是客户、不是真实事件。
- 从目录或 `enabled:` 标志推断规则可执行——必须被厂商形状事件重放并“看着触发”。
- 把 `--prove-gate` 的“可达”当成“能检测出攻击”。
- 把“迁移到非安全领域”的说法当成已验证结论——它是类比。
- 未测量写成 `0`——应写 *not measured*。
- 混用压缩率的三个数字（75.3% / 33.3% / 24.5% 分母不同），或只引用最好看的那个。
- 历史回放后把新发现当成原事件时刻的预测——回放时间被冻结，发现不计为预测。
- 让发起动作的人自己批——审批人必须是另一个持有相应权限层级的人。
- 只用一个总开关控制自动响应——三重开关（部署、租户、playbook）缺一个就应退回预览。
