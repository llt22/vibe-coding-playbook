# 让 agent 做重复填报，但把提交权留在人手里

> **未经实测**：本手册由 ai-work-radar 根据自动调研合并生成并持续修订，步骤尚未有人实际跑过。服务修订时基于自己保存的上一版重写，直接改这个文件会被覆盖；实测过的做法请写到 experiences/。
>
> 解决的问题：这篇手册解决如何把求职投递这类重复、跨站点的流程交给 AI 推进，同时用事实校验和人工确认点防止它乱改事实、乱提交。
> 先试这一步：先按默认复核模式跑通一个岗位：扫描、筛选、改写简历、填到复核页，不开启自动提交，也不授权密码和验证码。
> 最近修订：2026-11-02

## 解决什么问题

把求职投递这类重复、跨站点、需要按对象微调的流程交给 AI 推进时，最大的风险不是它不会填，而是它悄悄改事实、重复投递、或在没有人工确认时提交。这篇手册给出一套可照做的分工：AI 在长期上下文库上逐任务改写，事实校验打回新增断言，流程停在复核页由人按提交，并用去重记忆避免重复劳动。

## 适用与不适用

**适用**：流程化、有明确事实源、可设人工确认点的重复工作，例如求职投递、按岗位定制材料、跨站点表单填写、按模板改写文档、从多个来源收集并筛选信息。ApplyTwin 是这类工作的一个可试跑样例，但方法本身可迁移。

**不适用**：需要自动提交、自动接受法律协议、绕过 CAPTCHA、或必须把密码/邮箱验证码交给模型的场景；高风险决策不能全自动；非英语或本地化招聘渠道的覆盖，材料未提及；目标站点改版后，按系统写的 playbook 可能失效；商业使用或改造 ApplyTwin 代码受许可证限制。

## 前置条件

- 已付费的 Claude Code 或 Codex 订阅（ApplyTwin 不调用 API key，复用订阅额度）。
- Python 3.9 或更新；Node.js（agent 需要它驱动浏览器）。
- 能驱动浏览器的 agent：Claude in Chrome、Claude Code 的 computer use，或 Codex 的浏览器工具。
- 一份现有简历（PDF、Word、LaTeX 或纯文本）；一次性填好的常规申请问题答案；可选的历史投递 CSV（Simplify / Huntr / Teal / Notion / Google Sheet）。
- 可选：求职网站专用邮箱和密码、邮箱验证码读取权限。两者默认关闭，需要逐项显式开启；密码由应用自己输入页面，填表的 AI 看不到，且只留在本机。
- 安装目录为 `~/.applytwin-app`（Windows 为 `%USERPROFILE%\.applytwin-app`），数据在 `~/.applytwin`。许可证为 PolyForm Strict 1.0.0：可非商业安装运行，不可复制、修改、再分发或据以构建衍生作品。

## 操作步骤

### 做法 A：用 ApplyTwin 在求职投递上小范围试跑

适合：你已经在用 Claude Code 或 Codex，想先跑通一个真实流程，接受安装风险，并严格保持默认复核模式。

1. **备齐前置条件**。前提：上面列出的 Python、Node.js、订阅和浏览器 agent 至少满足；缺任一项安装器会报出并提示。预期：你知道自己缺什么，先补齐再装。
2. **安装，优先走可先看代码的路径**。前提：你接受把应用装在本地；更稳妥的做法是先 clone 再跑安装，不要直接执行远程脚本。预期：本地应用可启动，浏览器能访问 `http://localhost:4747`。
```bash
git clone https://github.com/OjasMishra32/applytwin.git
cd applytwin
./install.sh               # 连接 Claude Code 和 Codex，然后打开 http://localhost:4747
python3 tests/smoke.py     # 冒烟测试
```
如果坚持用 README 的一行安装，材料原文是下面两条；调研同时指出安装脚本与凭据处理存在明显风险，执行前应明白这是 `curl … | bash` 模式：
```bash
curl -fsSL apply.twinly.tech/install | bash
```
```powershell
irm apply.twinly.tech/install.ps1 | iex
```
3. **打开本地应用并登录**。前提：安装完成。预期：用 Google 登录后，配置、答案、投递记录同步到账号，换电脑可续。不想上报安装统计时，在设置里关掉 Count my install，或设 `APPLYTWIN_NO_TELEMETRY=1`。注意 `apply.twinly.tech` 只是取安装命令的站点，应用本体是 `http://localhost:4747`。
4. **供给上下文**。前提：你已有简历和常规申请答案。预期：上传简历、一次性回答常规申请表问题；新问题后续只问一次并记住；如果先导入历史投递 CSV，去重才能更早生效。这一步决定后面改写质量，不要跳过。
5. **跑环境自检**。前提：能看到 `applytwin` 命令。预期：`applytwin doctor` 通过。若提示 command not found，开一个新终端，因为安装器把命令写进 PATH，已开的窗口看不到。
```bash
applytwin doctor
```
6. **接上 agent**。前提：尚未登录 Claude Code 或 Codex。预期：agent 可用，并能被 ApplyTwin 调用。
```bash
npm install -g @anthropic-ai/claude-code   # 然后运行：claude   并输入 /login
npm install -g @openai/codex               # 然后运行：codex login
```
登录后：
```bash
applytwin install-agents
```
也可在应用 Autopilot 页按 Install and sign in，它会自动装 agent 并打开官方登录页。
7. **启动自动流程，但保持默认复核模式**。前提：agent 已接上。预期：在 Autopilot 页按 Start，它在自己的浏览器窗口里操作，需要你时通知你；投递网站账号创建默认关闭；第一轮不要打开 Submit applications on its own。若确需开启账号创建，单独填一个只用于求职网站的邮箱和密码；邮箱验证码读取也要单独开启。
8. **先用命令行跑单个环节，不需要 agent 也能用**。前提：`applytwin` 命令可用。预期：先跑通扫描、看岗位、改写、ATS 检查、模板列表和定时刷新，再决定是否让 agent 接管浏览器。
```bash
applytwin scan
applytwin jobs
applytwin tailor JOB_ID
applytwin ats JOB_ID
applytwin templates
applytwin watch --every 120
applytwin update
applytwin help       # 完整命令列表
```
9. **用 agent 对话驱动，但只让它做到复核页**。前提：agent 能驱动浏览器。预期：你能用自然语言让它扫描、排序、改写并解释选择；不要用 `twin: apply to my top 10` 这类批量投递提示语去开启自动提交，除非你已明确改变策略。可用的提示语原文包括：
```text
set me up with applytwin
twin: scan and show my top 20
twin: tailor my resume for <job id or URL> and explain the choices
twin: apply to my top 10
twin: review my resume like a recruiter
```
10. **排障**。前提：出现首页打不开、命令找不到、端口冲突或 Windows 脚本报错。预期：按下面处理，不靠猜。
- 首页打不开：首次启动可能要一分钟，等一等再刷新；不行就 `applytwin app` 手动起（Mac/Linux 先开新终端）。
- 端口 4747 被占用：会自动换端口并打印地址，也可指定 `applytwin app --port 5050`。
- 日志：Mac/Windows 在用户主目录 `.applytwin` 文件夹下的 `server.log`。
- Windows 报 running scripts is disabled：改用 `claude.cmd`、`codex.cmd`、`npm.cmd`，或从命令提示符运行；或执行 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`。
- Python 缺失或过旧：`winget install Python.Python.3.12`。
- Node.js 缺失：从 https://nodejs.org 装 LTS（Windows 可 `winget install OpenJS.NodeJS.LTS`）。
11. **把不可越过的边界当配置写死**。前提：你准备让 agent 操作真实表单。预期：遇到边界就停下并通知人工，而不是让 agent 自行绕过。照抄它的约束清单：
- 不把密码给 AI。
- 不解 CAPTCHA。
- 不接受法律协议。
- 不改简历上的数字、职位、雇主、学历、奖项。
- 碰到以上任一项即停下并通知人工。
12. **用去重和记忆减少重复劳动**。前提：已有投递记录或历史 CSV。预期：同公司同岗位不重复投；新问题只问一次并记住答案；可在 `apply.twinly.tech/app` 查看已同步的投递记录。

### 做法 B：不安装，把结构迁移到其他工作

适合：你不想承担安装/许可证风险，或要处理求职以外的流程。材料明确说 ApplyTwin 代码受 PolyForm Strict 限制，不能复制、修改、再分发或据以构建衍生作品；可复用的是结构与做法。

1. **建一个上下文资料库**。前提：这项工作的原始事实分散在简历、表格、文档、历史记录里。预期：把所有经历/素材集中到一处长期维护，类似 Career Vault；后续每次改写真基于沉淀，而不是每次重来。
2. **为每个任务单独改写，而不是一份通稿到处发**。前提：每个目标有不同要求。预期：从上下文库里挑最相关条目、按目标重排、压到约束长度；简历场景是压到一页，其他场景换成你的输出长度约束。
3. **设事实校验**。前提：你允许 AI 改写表述。预期：凡是新增了原始条目里没有的数字、工具或断言的一律打回；数字、职位、雇主、学历、奖项等事实字段不允许变动。迁移到其他工作时，先写一张锁定字段清单。
4. **设人工确认检查点**。前提：流程有提交、发送、发布等不可逆动作。预期：AI 做到复核页/待确认状态就停，人确认后再执行；默认不自动提交。
5. **设去重记忆**。前提：同一对象可能被重复处理。预期：同公司同岗位或同对象同任务不重复；新问题只问一次并记住答案。
6. **按系统分 playbook**。前提：不同网站/渠道的表单和规则不同。预期：每个目标系统一份操作手册，记录字段、坑和停止条件；站点改版后更新对应 playbook，而不是让 agent 临场猜。
7. **把可脚本化的部分和需要 GUI 的部分分开**。前提：流程里既有批量扫描、筛选，也有打开浏览器填表。预期：能 CLI 的先跑，需要浏览器的交给带浏览器 agent；这样出错时容易定位。

**怎么选**：要马上验证真实流程、且接受安装与许可证边界，选做法 A；不想装、要用于其他工作、或只想复用方法，选做法 B。两者都保留同一条底线：默认人工确认、事实校验、去重记忆。

## 怎么判断变好了

材料没有给出任何结果侧指标（面试率、通过率、节省时间），所以不要把“面试率提升”当成已证结论。先看可观察的正确性护栏：
- 事实校验打回次数：改写后新增数字、工具或断言是否被拦住。
- 人工修改处数：从 agent 填到复核页，你改了多少处；改得越少，说明上下文和规则越可用。
- 重复投递拦截：同公司同岗位是否被去重记忆挡住。
- 提交前发现的错误数：人工复核时发现的错误是否下降。
- 单岗位从扫描到复核页的耗时：自行记录，材料没有基准，不要伪造对比。
最小试用方式：只跑一个完整流程——扫描岗位、看前 20 个、挑 1 个岗位改写、填到复核页、由人决定提交或放弃。试多久：材料没有时间数据，建议以完成一轮完整流程为限；这一轮做到事实零违规、人工修改可接受，再考虑扩到更多岗位。结果指标要自己另设基线，且只能作为你的观察，不是材料结论。

## 常见坑

- 直接执行 `curl … | bash` 安装脚本。调研指出安装脚本与凭据处理存在明显风险；更稳妥是先 `git clone` 看代码再跑 `./install.sh`。
- 把默认复核模式改成自动提交。第一轮不要打开 Submit applications on its own；批量投递提示语会扩大风险。
- 为了省事把求职网站密码或邮箱验证码权限交给模型。材料的设计是密码由应用自己输入、填表 AI 看不到；验证码读取默认关闭，需要单独开启。
- 以为事实校验能保证简历质量。它只拦新增事实和锁定字段，不证明匹配分能挑出好岗位，也不证明面试率会上升。
- 忽略许可证。PolyForm Strict 1.0.0 只允许非商业安装运行，不允许复制、修改、再分发或据以构建衍生作品；不要拿它的代码改造成自己的产品。
- command not found 就重装。先开新终端，PATH 可能还没刷新。
- 首页打不开就以为坏了。首次启动可能要一分钟；端口被占用会自动换端口并打印地址。
- Windows 直接跑脚本报 running scripts is disabled。改用 `.cmd` 或调整执行策略。
- 目标站点改版后继续用旧 playbook。按系统写的 playbook 依赖表单结构，站点改版即可能失效，需要更新。
- 岗位源以英文环境为主。材料列的是 Greenhouse、Lever、Ashby、Workday、SmartRecruiters、The Muse、HN Who is hiring、社区实习追踪表；非英语或本地化渠道未提及。
- 把作者主张当效果证据。匹配分、懂领域强简历、事实校验实际拦截效果、去重准确度都只是作者主张，README 未给用户量、成功率、误报率、节省时间数据。
